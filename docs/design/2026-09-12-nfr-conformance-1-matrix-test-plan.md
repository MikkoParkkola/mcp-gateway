## 4. Model: totality by construction, applicability by filtered rule

`docs/design/2026-09-02-conformance-matrix.md` Q2 decided the product is **total**: every row
emits every cell, per-row axis opt-out was rejected, and impossible combinations are `EXEMPT`
carrying a named rule plus a witness. Q3 fixed three cell states, with `EXEMPT` emitted by the
renderer and never typed by a human. The exemption vocabulary is closed:

| Code | Witness required |
|---|---|
| `NO-SURFACE-IN-ROLE` | the statement text |
| `TRANSPORT-LACKS-MECHANISM` | the transport capability declaration |
| `REVISION-PREDATES-STATEMENT` | the `SUPPORTED_VERSIONS`/`MODERN_VERSIONS` entry plus the introducing change |

A code outside that list is refused; adding a code is a design event, not a test edit.

Concretely, in Rust:

- `Row.role` and `Row.transport` stop being single values. The row keeps `statement`,
  `requirement` and gains `evidence: &[Evidence]`, where each `Evidence` carries the test path
  **plus the coordinates it covers** — role, transport, revision scope, outcome.
- Exemptions live in a separate `EXEMPTIONS` table: `(code, witness, scope)` where `scope` is a
  predicate over the four axes plus the statement.
- The matrix is generated by iterating the full product and asking, for each cell: does an
  evidence entry cover it, or does an exemption rule match it? Neither means the cell is empty,
  and an empty cell is the finding.

**Revision scoping is coarse on purpose.** The retained legacy tests
(`ac_stateless_3_a_legacy_response_still_carries_the_session_header`,
`ac_stateless_6_ping_still_works_on_the_legacy_path`, `ac_result_1_a_legacy_result_carries_none`,
`ac_header_2_a_legacy_request_needs_no_headers`) do not distinguish `2025-11-25` from
`2024-11-05`. Evidence therefore gets a revision scope of `Modern`, `AnyLegacy`, or one named
version. `AnyLegacy` is recorded as coarse here rather than discovered in review; it is what
those tests actually prove.

## 5. Tests

### 5.1 New

1. **`every_cell_is_covered_or_exempt`** — the completeness assertion. Walks all 880 cells;
   fails listing any cell that is neither evidenced nor exempt. This is the criterion's
   obligation 1 and 2 in one test.
2. **`every_exemption_names_a_known_code_and_a_witness`** — the code is in the closed vocabulary
   and the witness string is non-empty. Obligation 2's "reason" must be a witness.
3. **`an_exemption_rule_is_scoped_on_at_least_one_axis`** — refuses a rule unscoped on all of
   {statement, role, transport, revision, outcome}. Without this, three broad rules turn 880
   cells green.
4. **`a_cell_carrying_evidence_matches_no_exemption_rule`** — **the load-bearing test.** Every
   one of the 20 existing statements comes from the 2026-07-28 changelog, so a blanket
   `REVISION-PREDATES-STATEMENT` over the four legacy revisions would cover ~640 cells on one
   rule *and swallow the retained-legacy evidence the criterion explicitly demands*. This test
   makes that collision a failure instead of a silent pass, and forces rules to be scoped per
   statement rather than per axis.

### 5.2 Re-expressed, not deleted

`the_client_role_is_covered_and_not_only_the_server_one` and
`both_transports_carry_the_statements_that_apply_to_them` read the row-level `role`/`transport`
fields this plan removes. Dropping them would read as a coverage regression. Each is re-expressed
as a floor over cells: *N statements have at least one client-role cell carrying evidence*,
*N statements have at least one stdio cell carrying evidence*. Same guard, new shape.

### 5.3 Unchanged

`matrix_has_no_empty_cells`, `a_tracked_gap_is_still_a_gap`,
`every_statement_names_the_requirement_that_owns_it`, `the_matrix_covers_every_major_change`,
`every_cited_test_exists`.

`every_cited_test_exists` is the reason this cannot be padded: every evidence string must name a
real `ac_*` function in the tree or the suite goes red.

## 6. The two named content areas — measured findings

The criterion names two behaviours by hand. Neither has evidence today. Of the 124 distinct
`ac_*` functions in `src/` and `tests/`, **zero** name elicitation, completion, structured
results, `outputSchema`, scalar, array or arbitrary JSON. Both are new statements plus new
acceptance tests, not re-citations.

### 6.1 Modern URL-elicitation completion removal

Measured:

- `notifications/elicitation/complete` appears **nowhere** in `src/` or `tests/`. Its only
  occurrence in the repository is `docs/issue-73-impl-plan.md:462`.
- `ElicitationCreateParams` (`src/protocol/messages.rs:513-529`) carries
  `mode`, `message`, `requested_schema`, `url` — and **no `elicitationId`**, though
  `docs/issue-73-impl-plan.md:77` lists one.
- The mode set is closed: `ElicitationMode { Form, Url }` (`src/protocol/meta.rs:306-330`),
  absent mode reads as `Form`; declaration check `has_elicitation_mode` (`:398-403`) over
  `elicitation_form`/`elicitation_url`; capability type `ElicitationCapability { form, url }`
  (`src/protocol/types.rs:368-376`).
- Undeclared-mode refusal is real: `src/protocol/mrtr.rs:297-333,368-371`, gated on
  `method != "elicitation/create"`, refusing through a `Mode(ElicitationMode)` variant.
- Bridge rule, `docs/design/2026-09-01-mrtr7-legacy-client-bridge.md:140-160` (MRTR.9): URL mode
  is sent only where the session store holds `elicitation.url`, else refused by name.

**The hazard.** "Removal" here is absent-by-omission. A test asserting *the gateway emits no
completion notification* passes trivially and would pass forever even if the whole elicitation
path were deleted — exactly the vacuous evidence this file exists to prevent. The discriminating
pair is instead:

- **positive/modern**: a URL-mode elicitation completes through the MRTR continuation, with no
  server-initiated completion notification in the exchange;
- **positive/legacy**: the same elicitation completes through server-initiated
  `elicitation/create` on the bridge — the "retained legacy behavior" the test row demands;
- **negative/modern**: URL mode with `elicitation.url` absent from the session store is refused
  by name (MRTR.9), not silently downgraded to `Form`.

**Open question O1.** That positive/modern cell is only writable if the modern completion path is
wired in this tree. If it is not, the honest artifact is a `TRACKED_GAPS` entry naming the owning
work — the same shape as the existing Cluster B gap — rather than a test I author. Confirming the
wiring state is the first implementation step, before any test is written, and the answer changes
whether this area yields evidence or a tracked gap. Flagging it now because the ledger records
MRTR as unwired and CONFORM.2 as blocked on it.

### 6.2 Arbitrary-JSON structured results

Measured, and this one clears:

- Every `output_schema: None` site in `src/provider/transforms/{filter,namespace,rename,chain,response}.rs`
  and `src/provider/composite_provider.rs` sits **below that file's `#[cfg(test)]` line**. They
  are test fixtures constructing bare tools, not production transform constructors dropping an
  upstream schema. **No product fix is in scope here** — `outputSchema` preservation is
  assertable as-is.
- `src/gateway/router/tests/task_execution_adapter/result_shapes.rs` covers result shapes but its
  functions are not `ac_*`-named, so they cannot be cited under `every_cited_test_exists`.

Three positive cells (scalar, array, object structured result, each with `outputSchema` surviving
the transform chain) plus a negative cell (a structured result whose shape contradicts its
declared `outputSchema`). New `ac_*` tests, named for the statement they prove.

## 7. Decisions for the lead

**D1 — WebSocket: axis value or not?**
`src/transport/mod.rs:22` has three client-side `Transport` implementations (http, stdio,
websocket) and the serving side spawns a WS listener at `src/gateway/server/mod.rs:1921`. I found
the listener spawn but no MCP dispatch behind it. In: **1320 cells**, and every statement owes a
WebSocket answer or a `TRANSPORT-LACKS-MECHANISM` exemption. Out: **880 cells**, and the matrix
is silent about a transport that ships.
*Recommendation: out, with a single tracked gap naming WebSocket conformance as unowned* — it
keeps this criterion honest without absorbing another cluster's scope. Lead's call.

**D2 — "complete applicable" versus totality-with-exemptions.**
The criterion (2026-09-06, authority) says the *complete applicable* matrix. The
totality-with-exemptions mechanism comes from the 2026-09-02 design, which predates it. The two
converge only if N/A-with-reason *is* how applicability gets expressed — which is the reading
this plan adopts, and the reading that makes the criterion's second clause ("every N/A cell has a
reason") load-bearing. That is a ratification the lead should make explicitly rather than one I
adopt silently.

**D3 — Rust-only; no TOML source and no renderer.**
The 2026-09-02 design sketches a rendered matrix from a declarative source. It was never built:
`scripts/release/` holds no `render_conformance_matrix.py`, there is no
`docs/requirements/conformance-matrix.toml`, and no rendered matrix document exists.
`tests/mik_7272_conformance.rs` is the live artifact. Building a Python renderer is a project,
not a widening, and the design predates the authority document. *Proposed: widen the Rust file;
leave the renderer unbuilt.* Stated as a deliberate deviation so it is not rediscovered in review.

**D4 — minor-change numbering.**
`MINOR` covers changelog items 1-10 and 12; **11 and 13 are absent**. The two new statements may
be exactly those items, but the changelog is not in the repository, so I will not invent the
numbers — the statements go in with the criterion's own wording and the numbering gap is recorded
here. Note also there is no `covers_every_minor_change` counting test to match
`the_matrix_covers_every_major_change`; adding one would need the authoritative minor count.

**O1 (from 6.1)** — is the modern URL-elicitation completion path wired in this tree? Evidence if
yes, tracked gap if no.

## 11. Rulings (reviewed 2026-09-12)

All four decisions and the open question are answered. Implementation proceeds on this basis.

**D1 — WebSocket is OUT**, with a tracked gap naming WebSocket conformance as **unowned** in as
many words. A conformance cell asserts MCP behaviour over a transport; the listener has no MCP
dispatch behind it, so 440 extra cells could only be evidenced vacuously. One honest gap beats
440 vacuous cells. Target stays **880**.

**D2 — ratified.** The 2026-09-06 criterion supersedes the 2026-09-02 design; that supersession is
the standing rule for this scope update. "Complete applicable" wins, and N/A-with-reason is how
applicability is expressed. The criterion's second clause is therefore load-bearing.

**D3 — approved as a deliberate deviation**, recorded here with its reason rather than left as an
oversight. The criterion asks for evidence references per cell, not for a rendered document. The
Rust file is the live artifact; building the designed-but-never-built TOML source and renderer
would put the criterion behind a deliverable nobody asked for.

**D4 — no invented numbers.** Statements go in with the criterion's own wording. No
`covers_every_minor_change` test: a totality test needs an authoritative denominator, the
changelog is not in the repository, and a totality test on a guessed count asserts something
false while looking like coverage. Filed as a tracked gap naming what it needs — the
authoritative minor count.

**O1 — tracked gap, not a test.** The modern completion path is not wired in this tree. The
ledger records MRTR as unwired, and the neighbouring path shows the same shape: `InputBridge` is
defined in `src/gateway/input_bridge.rs` on the integration branch and constructed nowhere, while
`main` constructs it in production inside `invoke_tool_traced`. The discriminating pair of §6.1
therefore has only one live arm, and "no completion notification is emitted" would pass trivially
and forever. Entered as a tracked gap naming the owning work: `MIK-7387.STDIO.1`-`.3` and
`CONFORM.2`. The test is not authored.

**Statement count**: 20 supersedes the earlier 19.

Both findings in §6 are ruled as plan content, not thread content: the zero-of-124 measurement
means anyone sizing this row from the existing test count sizes it wrong, and the `#[cfg(test)]`
finding is a negative result that stops a bug being opened against a non-defect.

Guard ordering is mandatory: the two exemption guards (§5.1 items 3 and 4) land **before** the
matrix widens, so the widening cannot outrun its own guard.
