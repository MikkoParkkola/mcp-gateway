# 4.0.0 upgrade notice — what the changeset owes an operator

`Cargo.toml` says `version = "4.0.0"`. `MIGRATIONS`
(`src/commands/upgrade.rs:97`) holds exactly one entry, `applies_below: "3.0.0"`.
So a 3.x deployment upgrading to 4.0.0 is told nothing, and this release changes
behaviour under deployments that edit no configuration at all.

The 3.0.0 entry is the pattern: informational, never edits the file, idempotent
via the version stamp (`:107`).

## Audit — every 4.0.0 entry, and whether it owes a notice

| change | owes a notice | why |
|---|---|---|
| OAuth credentials keyed by issuer; **every OAuth backend re-authenticates once** | **yes** | the operator sees an auth prompt or a refusal on a backend that worked yesterday, with no config change to explain it. Highest-surprise item in the release. |
| a **malformed env-file line now fails startup** (was: skipped) | **yes** | a gateway that started yesterday refuses to start today. The line is never echoed, so the notice is where the operator learns what to look for. |
| **`2024-10-07` no longer advertised** as a supported protocol version | **yes** | a client pinned to it stops negotiating. Not fixable by the gateway operator without knowing it happened. |
| env files no longer applied to the process environment | no | a fix whose whole point is that the environment is left as it was. Nothing an operator must do. |
| `{env.VAR}` secrets, the provenance key and `env:` credentials read the overlay | no | these previously expanded to nothing; the change is that they now work. |
| a webhook secret resolving to empty is refused | borderline — **fold into the env-file notice** | a deployment relying on an empty HMAC key was already forging-open; refusing it is the fix, and the startup error names it. |
| config rewrite no longer persists a resolved secret | no | no operator-visible behaviour change beyond the file no longer leaking. |
| reload no longer refused over a reference the parser would ignore | no | strictly fewer refusals. |
| MCP `2026-07-28` behind `server.modern_protocol` | no | opt-in flag, default off. |
| destructive call refused when unconfirmable, continuations sealed, per-caller state deadline, `gateway_search` signals, anomaly-detection reporting | no | modern-path or internal; none changes a legacy deployment that edits nothing. |
| GH #475: rate limiting stops counting against backend health | **yes** | covered by that change's own design (D5); it is one line of the same notice. |

Four items earn a line. One notice, four lines, one entry.

## Shape

```
applies_below: "4.0.0"
description: v4.0.0: informational upgrade notice (config unchanged)
```

Body, as bullets the operator can act on: OAuth backends re-authenticate once —
expect one prompt per backend, no config change; env files are now strictly
parsed — a malformed line fails startup, naming file and line, never the
content; `2024-10-07` is no longer advertised — clients pinned to it must
negotiate a supported revision; rate limiting no longer counts against backend
health.

Two properties inherited from the 3.0.0 entry and kept: it never writes to the
operator's config, and the version stamp makes a second `upgrade` run silent.

## Fail-fast

The check that this is right is cheap and mechanical: set the stamp to `3.9.0`,
run `mcp-gateway upgrade`, assert the notice is emitted and `gateway.yaml` is
byte-identical; run it again at `4.0.0` and assert silence.
