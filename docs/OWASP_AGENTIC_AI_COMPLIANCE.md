# OWASP Agentic AI self-assessment matrix

**Date**: 2026-09-26 (4.0 release line; re-audited against source)
**Standard**: OWASP Top 10 for Agentic Applications 2026 (ASI01-ASI10, published 2025-12-09); risk names follow that list
**Sources**: [OWASP Top 10 for Agentic Applications 2026](https://genai.owasp.org/resource/owasp-top-10-for-agentic-applications-for-2026/), [OWASP Agentic Security Initiative](https://genai.owasp.org/initiatives/agentic-security-initiative/), [OWASP Agentic AI Threats and Mitigations](https://genai.owasp.org/resource/agentic-ai-threats-and-mitigations/)
**Scope**: mcp-gateway repo-local controls at the gateway boundary.

This matrix is a **self-assessment**, not a certification. It tracks mcp-gateway only. It cites controls that run on the request path or when config loads, plus, for ASI04 alone, the release-time supply-chain controls (signing, SBOM, npm provenance); a control that exists only in the CLI or in tests is not counted. Each row says which controls are on by default and which an operator must enable. Current mapping: **3/10 COVERED, 7/10 PARTIAL** for the gateway boundary. CI checks that every path and validation test cited here exists (`scripts/dev/check-owasp-citations.py`).

## Compliance Matrix

| # | OWASP ASI Risk | Status | mcp-gateway controls | Boundary / hardening |
|---|---|---|---|---|
| ASI01 | Agent Goal Hijack | COVERED | On by default: the request firewall scans call arguments and refuses shell-injection and path-traversal payloads (`src/security/firewall/input_scanner.rs`, called from `src/gateway/router/backend_handlers.rs` and `src/gateway/router/handlers.rs`). The response firewall scans backend `tools/list` and results: it redacts credential patterns and warns on prompt-injection text, which stays in place (`src/security/firewall/mod.rs`). Response inspection observes by default and blocks only with `action_mode` (`src/security/response_inspect.rs`). A tool whose description fails the tool-poisoning validator (`src/validator/rules/tool_poisoning.rs`) at blocking severity is withheld from every served tool list and refused by name for every caller once any listing has shown it (`src/backend/descriptor_gate.rs`, applied in `src/backend/annotations.rs`); `allow_flagged_tools` serves one explicitly, pinned to its descriptor digest. | A tool name that no listing has returned is forwarded, since its description was never served (GitHub #1441). |
| ASI02 | Tool Misuse and Exploitation | COVERED | On by default: default-deny patterns refuse destructive and dynamic-execution tool names (`src/security/policy.rs`, checked in `src/gateway/router/authorization.rs`). Admin-only meta-tools, log-level changes and callback-registering capabilities are refused to non-admin callers with 403 (`src/gateway/router/authorization.rs`, `src/gateway/meta_mcp/visibility.rs`). API keys reach only their listed backends (`src/gateway/auth.rs`). Arguments carrying keys a closed tool schema does not declare are refused once the schema is cached; `input_schema_enforcement` sets the mode (`src/gateway/meta_mcp/invoke.rs`, `src/backend/input_keys.rs`). Opt-in tool-sequence anomaly scoring (`src/security/firewall/anomaly.rs`) scores each call against its caller's previous call, using transitions learned from all admitted calls, after a warm-up. With `anomaly_detection` on, a call with no caller identity is refused. | Structural graph-level misuse analysis remains hardening beyond the runtime policy. |
| ASI03 | Identity and Privilege Abuse | PARTIAL | Each caller sees and can invoke only the tools it is entitled to, on every discovery surface (`src/gateway/meta_mcp/visibility.rs`, `src/gateway/meta_mcp/search.rs`); cached results are bound to the caller (`src/identity_propagation/mod.rs`). Over HTTP, admin standing comes only from the operator bearer token, an admin API key, the dashboard bootstrap session, or an explicit issuer-scoped `role_mapping` rule (`src/gateway/auth.rs`, `src/control_plane/role_mapping.rs`). A stdio caller is always admin, because it spawned the gateway process and already holds the operator's access (`src/gateway/server/mod.rs`). Identity headers are honoured only from configured trusted proxies (`src/security/caller_identity.rs`; off by default). mTLS verifies client certificates and access rules fail closed when rules exist but no identity is present (`src/mtls/`). Identity grants gate personal capabilities (`src/identity_grants.rs`). Boundary-call attestation refuses a missing or invalid token when `GATEWAY_ATTESTATION_MODE=enforce` (`src/attestation/wiring.rs`); it is off by default. | Token-only deployments are outside the hardened profile unless paired with mTLS, trusted-proxy identity, or explicit grants. Failed authentication is not throttled or locked out: the per-client rate limit and circuit breaker apply only after a token authenticates (`src/gateway/auth.rs`). A change to any caller's own tool catalogue sends a content-free `tools/list_changed` to every listener already admitted to that backend. The hint carries no tool data and no caller identity, and a relist returns only the listener's own view. Its timing still shows that some view of the backend changed, and where a backend has very few callers it can hint whose (`src/gateway/server/tools_changed/views.rs`). |
| ASI04 | Agentic Supply Chain Vulnerabilities | PARTIAL | A capability file with a `sha256:` pin is refused on load, and on hot reload, when its content no longer matches the pin (`src/capability/hash.rs`, `src/capability/watcher.rs`); unpinned files load. Remote backend provenance binds name, transport, URL, subject, issuer and issue time to an Ed25519 signature at config validation when required (`src/security/remote_provenance.rs`, `src/config/mod.rs`; opt-in). Container images are signed with cosign and carry an SPDX SBOM attestation, verified in CI on release tags (`.github/workflows/ci.yml`); npm publishes with OIDC provenance (`.github/workflows/release.yml`). Each release binary is built with `cargo auditable`, ships an SPDX SBOM and a keyless cosign bundle, and the release stays a draft until every signature verifies against the release workflow's identity; the published release is verified again after publication (`scripts/release/sign-release-assets.sh`, `scripts/release/verify-release-assets.sh`, `scripts/release/check_release_assets.py`). | Remote backend provenance is opt-in; a remote backend running without it is named in a startup warning and in `doctor` (`src/config/remote_provenance_posture.rs`). Live remote attestation discovery is not implemented. |
| ASI05 | Unexpected Code Execution (RCE) | PARTIAL | On by default: the input firewall refuses shell injection and path traversal (`src/security/firewall/input_scanner.rs`), and default-deny refuses dynamic-execution tool names (`src/security/policy.rs`). The SSRF guard refuses private, loopback, link-local, multicast, reserved and CGNAT destinations including IPv4 embedded in IPv6, and pins DNS results against rebinding in the HTTP clients (`src/security/ssrf/`); capability executors, discovery, OpenAPI import and HTTP redirects call it. Opt-in: firewall rules that block SQL-injection patterns (`tests/firewall_integration.rs`). | Backend URLs from the operator's own config are trusted and not re-checked by default. The runtime-substrate preflight (`src/runtime/provision.rs`) is a CLI check and launches no sandbox. Downstream tools still need least privilege. |
| ASI06 | Memory & Context Poisoning | PARTIAL | On by default: the memory scanner refuses LLM control tokens and role-confusion payloads in memory-write tools (`src/security/firewall/memory_scanner.rs`, `src/security/firewall/mod.rs`). The ContextIntegrityKernel classifies tool output on `gateway_invoke` and the per-backend route and attaches provenance metadata (`src/context_integrity/`, `src/gateway/meta_mcp/invoke/dispatch_guards.rs`); by default it monitors and delivers content unchanged. Opt-in: `security.context_integrity.preset: team_shared` withholds output that fails the baseline (`src/config/features/security.rs`). | A withheld result's audit metadata still echoes a short fragment of the matched text (#2204). mcp-gateway owns no vector store; memory backends must enforce their own integrity. |
| ASI07 | Insecure Inter-Agent Communication | PARTIAL | Opt-in: HMAC-SHA256 response signing adds `_signature` to `gateway_invoke` responses, and a nonce a client sends is refused on replay within the window; `require_nonce` makes the nonce mandatory (`src/security/message_signing.rs`, `src/gateway/meta_mcp/signing.rs`). mTLS protects transport when configured (`src/mtls/`). On by default: the gateway mints every HTTP session id and never adopts one a client chooses (`src/gateway/router/handlers.rs`). Opt-in multi-gateway signature chaining: a gateway emits an Ed25519 origin link, strips any chain a backend sends, and for a backend set to `signature_chain: verify` or `require` verifies the upstream chain at raw receipt against its own per-dispatch challenge, preserves it and appends its own link, so a client verifies the whole chain; a tampered, swapped, stale, wrong-origin or dropped hop is refused or marked unverified (`src/security/signature_chain.rs`, `src/gateway/meta_mcp/chain_receipt.rs`; `tests/signature_chain_hops.rs`). Outbound A2A (`transport: a2a`): an agent's answer is untrusted tool output on the same terms as an MCP result, screened and annotated by default and refused under a Block rule (`tests/a2a_outbound/untrusted.rs`), and the backend's credentials go only to the origin of `a2a_url` (`src/a2a/client.rs`). | Signing, replay protection and chaining are off by default. A2A agent answers are neither signed nor chained, and an agent's JSON-RPC error text is not yet screened (MIK-8139). Chaining covers `gateway_invoke` and direct-route `tools/call` for opted-in MCP backends when the client sends a chain nonce; caches, idempotent replays, tasks, Code Mode, playbooks and capability backends are not chained. |
| ASI08 | Cascading Failures | COVERED | Shared circuit breaker, retry and rate-limit modules isolate failing backends, and an open breaker degrades `/health` (`src/failsafe/`); a backend's own rate-limit refusal does not trip its breaker. Webhook `rate_limit` is enforced (`src/gateway/webhooks/`). Opt-in: per-key throttling and per-client dispatch circuit breakers (`src/gateway/auth.rs`), and daily cost budgets checked on every dispatch, meta and per-backend routes alike, and kept across restarts (`src/cost_accounting/enforcer.rs`). | Distributed circuit state across several gateway processes remains deployment architecture. |
| ASI09 | Human-Agent Trust Exploitation | PARTIAL | Destructive meta-tools need an explicit confirmation exchange (`src/gateway/destructive_confirmation.rs`). A destructive meta-tool call from a modern HTTP client that cannot confirm is refused, and so is every destructive meta-tool call over stdio, since stdio has no confirmation channel (`src/gateway/meta_mcp/confirmation.rs`); only a legacy HTTP client that cannot elicit proceeds, with a warning. The kill switch, set through admin-only meta-tools, halts a backend on every route (`src/kill_switch/`, `src/gateway/meta_mcp/invoke/dispatch_guards.rs`). With auth on, the transparency log is required: every invocation that reaches dispatch gets a hash-chained record on the meta and direct routes, including authorization refusals decided there, HMAC-signed when `shared_secret` is set. Direct-route identity refusals happen before that point and leave no invocation record, the log rotates and verifies across segments, and a failed write withholds the result with 503 (`src/security/transparency_log.rs`, `src/security/transparency_log_rotation.rs`, `src/gateway/meta_mcp/invoke/audit.rs`, `src/gateway/router/backend_handlers/direct_audit.rs`). Opt-in: budget alerts (`src/cost_accounting/enforcer.rs`). | Legacy HTTP clients bypass destructive confirmation; operators need runbooks for high-risk tool approval. |
| ASI10 | Rogue Agents | PARTIAL | The kill switch and error budgets halt a misbehaving backend on every route; per-backend failures count toward the error budget too (`src/kill_switch/`, `src/gateway/meta_mcp/invoke/dispatch_guards.rs`). Opt-in anomaly blocking (`anomaly_detection` plus `anomaly_block_threshold`, `src/security/firewall/anomaly.rs`, `src/security/firewall/anomaly_gate.rs`) scores each call against its caller's previous call, using transitions learned from all admitted calls on the meta and per-backend routes, and refuses a transition scoring at or above the block threshold; no rule can downgrade that refusal. A caller's first calls are warming up and are not scored (`anomaly_min_observations`, default 20). Known limit: the model is shared across callers, so during a tool's warm-up any admitted caller shapes what counts as usual. With `anomaly_detection` on, a call with no caller identity is refused. Opt-in: cost budgets bound spend on every route (`src/cost_accounting/enforcer.rs`); attestation `enforce` constrains each call to its signed task scope on every route (`src/attestation/wiring.rs`). | Multi-agent collusion detection is partial: opt-in verbatim relay detection (`security.firewall.collusion`, `src/security/firewall/collusion_gate.rs`) covers the per-backend and the meta-MCP routes (HTTP, stdio, tasks, bridged prompts, replays, and `prompts/get` and `resources/read`); an `allowed_flows` allowlist exempts known collaboration and `mcp_gateway_collusion_relay_total` counts reported relays. It compares only the first and last 3 KiB of each delivered result (it keeps about one 48-character window in four as a fingerprint, at most 4,096 per result), so content from the rest of a larger result is not detected, shared text under 48 characters never matches, and a shorter shared run can hold too few fingerprints and pass (with the default `min_matches` of 2, a run of n characters has k = n - 47 windows and is missed with odds (3/4)^k (1 + k/3), about 1 in 850 at 79 characters). Paraphrased or re-encoded relays are out of scope. |

## Validation Commands

These focused tests map directly to the controls most likely to regress:

```bash
cargo test validate_accepts_signed_remote_backend_provenance
cargo test validate_rejects_required_remote_backend_without_provenance
cargo test validate_rejects_tampered_remote_backend_provenance_signature
cargo test sign_response_injects_signature_block
cargo test nonce_store_rejects_replayed_nonce
cargo test memory_write_with_control_token_is_blocked
cargo test memory_write_with_role_confusion_is_blocked
cargo test --lib context_integrity_team_shared
cargo test exec_rule_elevates_sql_injection_to_block
cargo test anomaly_above_block_threshold_is_rejected
```
