## Goal

Route the integration-test files that name the YAML parser directly
through `tests/common/yaml.rs`, which compiles `src/yaml.rs` itself. There
is no behaviour change, and the backend is still serde_yaml 0.9.34. After
F3, and once MIG.1e's last PR (#3977) has merged, the only rows left on the
bypass allowlist are `src/yaml.rs` and `tests/mik_8425_yaml_adapter.rs`.
Only then can MIG.2 swap the backend without any test naming serde_yaml.

## Wiring

**The rule: every test crate loads `tests/common/yaml.rs` exactly once.**
Clippy's `duplicate_mod` refuses a crate that loads it twice (F2's first
gate). So when two modules of one crate both use the adapter, or when a
module's includer also declares it, they share one root declaration and use
`crate::yaml`. The forms below follow from that rule.

Integration-test crates cannot see the crate-private adapter, so they
compile it through `tests/common/yaml.rs` (`#[path = "../../src/yaml.rs"]`).
- **A crate root** (a top-level `tests/*.rs`) declares
  `#[path = "common/yaml.rs"] mod yaml;` and calls `yaml::...`.
- **A non-root module whose crate root is in the same batch** uses
  `crate::yaml`, and the root declares the module. This applies to
  `tests/openwebui_adapter_config/acceptance.rs` and `auth_separation.rs`:
  they take `Value`s from their parent's `accounts_roundtrip` and
  `adapters_sequence`, so they must share its type.
- **A non-root module whose roots are outside the set** declares its own
  module-local `#[path = "<relative>/common/yaml.rs"] mod yaml;`. Two
  conditions apply:
  - no YAML type may cross the module's boundary;
  - no crate that includes it may also declare the root module. Clippy's
    `duplicate_mod` refuses a crate that loads `tests/common/yaml.rs`
    twice: F2's first gate failed exactly so, on the 6 F2 roots that
    include `signing_gateway.rs`.

  A `#[path]` inside a file resolves relative to that file's directory.
  This avoids editing crate roots outside the set (the `tests/mik_7630_events/`
  helper alone is declared as a module by 14). Each of these modules was
  checked, and each only turns a crate config into a `String` or reads one
  back:
  - `tests/common/mrtr7_fixture.rs`;
  - `tests/mik_7272_owner2_stdio_tasks/helper.rs`;
  - `tests/mik_7630_events/gateway.rs`;
  - `tests/task_expiry_http_lifecycle/helper.rs`.
- **A shared module whose includers mix roots in and out of the set** uses
  `crate::yaml`, and every crate that includes it declares the root
  module, including crates outside the set (two lines and a comment, no
  routing). This applies to:
  - `tests/common/signing_gateway.rs` (changed in F2): its 11 includers
    declare the module. That adds the declaration to
    `signature_chain_sites.rs` (an F3 file) and to 4 crates outside the
    set: `anomaly_learning_e2e`, `message_signing_cache_replay`,
    `message_signing_delivery` and `signature_chain_hops`;
  - `tests/task_upstream_recovery/helper.rs` (F3): it is included by
    `task_crash_boundaries.rs` (an F3 root) and by `task_upstream_recovery.rs`,
    which is outside the set, so that crate gets the declaration.
- **Sibling modules of one crate whose root is outside the set** use
  `crate::yaml`, and the root declares the module once (two lines and a
  comment, no routing). Two module-local copies would load the file twice
  in one crate. This applies to:
  - `tests/webui_management_tests/backend_mutation.rs` and
    `internal_routes_served.rs` (root `webui_management_tests.rs`);
  - `tests/task_upstream_recovery_sdk/authority.rs` and `helper.rs`
    (root `task_upstream_recovery_sdk.rs`).
- **The exception is `tests/common/mik_8425_golden.rs`.** It takes a
  `Value` from its includer (`yaml_structure(&Value)`). A module-local copy
  would be a different type once MIG.2 makes `Value` an owned tree, so it
  uses `crate::yaml::Value`. All five of its includers are F1 baselines, and
  each declares the root module.
- A local variable named `yaml` lives in the value namespace, not the
  module namespace, so `yaml::from_str(&yaml)` compiles and the variable
  needs no rename.

## The adapter's dead-code allow

`src/yaml.rs` carries `#![allow(dead_code, unused_imports)]`, and its
reason says to delete the allow in MIG.1f. That no longer holds: every test
crate compiles its own copy of the adapter, and none calls the whole
surface, so without the allow clippy `-D warnings --all-targets` fails. F1
changes only the reason text, to "Delete this allow in MIG.2", where the
swap re-examines the surface. That adds one path to F1.
