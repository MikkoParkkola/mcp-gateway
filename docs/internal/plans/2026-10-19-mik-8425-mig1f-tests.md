## Goal

Route the integration-test files that name the YAML parser directly
through `tests/common/yaml.rs`, which compiles `src/yaml.rs` itself. There
is no behaviour change, and the backend is still serde_yaml 0.9.34. After
F3, the only rows left on the bypass allowlist are `src/yaml.rs` and
`tests/mik_8425_yaml_adapter.rs`, and MIG.2 can swap the backend without
any test naming serde_yaml.

## Wiring

Integration-test crates cannot see the crate-private adapter, so they
compile it through `tests/common/yaml.rs` (`#[path = "../../src/yaml.rs"]`).
- **A crate root** (a top-level `tests/*.rs`) declares
  `#[path = "common/yaml.rs"] mod yaml;` and calls `yaml::...`.
- **A non-root module** (a `tests/common/*` helper, or a file under
  `tests/<crate>/`) declares its own module-local
  `#[path = "<relative>/common/yaml.rs"] mod yaml;`. A `#[path]` inside a
  file resolves relative to that file's directory. This avoids editing
  crate roots outside the set. `tests/common/signing_gateway.rs` alone is
  included by 13 crates, and the `tests/mik_7630_events/` helper by 14.
  Among those roots is `task_upstream_recovery.rs`, which another lane
  holds.
- **The exception is `tests/common/mik_8425_golden.rs`.** It takes a
  `Value` from its includer (`yaml_structure(&Value)`). A module-local copy
  would be a different type once MIG.2 makes `Value` an owned tree, so it
  uses `crate::yaml::Value`. All five of its includers are F1 baselines, and
  each declares the root module.
- No test file declares `mod yaml` today, apart from the out-of-scope
  adapter test. A local variable named `yaml` is in another namespace and
  does not clash.

## Per batch (red first)

- **R1, red:** remove the batch's files from the allowlist. T5
  (`cargo test --test mik_8425_yaml_adapter no_new_file_names_a_yaml_parser_directly`)
  must fail and list exactly those files. After routing it passes.
- **R2, unchanged behaviour:** every touched integration crate runs by
  `--test <crate>`, with a positive passed count. For a non-root module,
  that means every crate that includes it, so `signing_gateway.rs` runs its
  13 includers. The MIG.0 suites run in every batch, and in F1 their
  goldens must still match byte for byte.
- **R3:** clippy `-D warnings` on `--all-targets` with all features and with
  no default features, `check-file-size.py` and `check-timing-asserts.py`.
- **Gate:** CI's exact command,
  `cargo test --all-features --no-fail-fast -- --skip a_real_sdk_job_outlives_the_gateway_and_its_owner_reads_the_result --skip mik_7479_full_burst`,
  plus `scripts/dev/pre-push.sh`, under the Spark full-run cap. After the
  gate, merge the line tip. A disjoint merge gets targeted checks, and the
  regenerated allowlist must equal the tip minus the batch's files.
- **Holders:** before each push, re-scan open PRs, remote branches and the
  lead's on-disk worktree list. A new holder moves its file to a later
  batch.
