## Goal

Route MIG.1e's 4 product files, plus the two test files that belong to
them, through `crate::yaml`. This includes the three figment YAML call sites
the design names for MIG.1e ("the figment provider becomes
`yaml::from_str_loose` ... inside `ConfigFile::data` and the other two
figment call sites"). There is no behaviour change, and the files leave the
bypass allowlist. The backend is still serde_yaml 0.9.34.

MIG.1e's remaining files are 95 test-only `src/` files. On 702227fae the
allowlist has 107 `src/` rows. Leaving out `src/yaml.rs` (the adapter
itself, which stays), the 5 MIG.1d-ii files (#3942) and the 6 here leaves
95. They follow as MIG.1e-2 onward, at 15 paths or fewer each. The 52
`tests/` rows are MIG.1f.

## Tests (red first)

- **R1, red:** remove the 6 files from
  `tests/fixtures/mik_8425_yaml/direct_users.txt`. T5
  (`cargo test --test mik_8425_yaml_adapter no_new_file_names_a_yaml_parser_directly`)
  must fail and list exactly those 6. After routing it passes.
- **R2, unchanged behaviour:** each new call's body is the old expression,
  so the oracle is the existing tests:
  - lib `config::` (the loader and `config/tests/load_error.rs`);
  - the binary's own tests, which are not in the library:
    `cargo test --bin mcp-gateway commands::doctor::hidden_keys` and
    `cargo test --bin mcp-gateway commands::backend_url_keys`;

    `ConfigFile::data`: `c1_unrecognised_config_keys`, plus the adapter and
    MIG.0 golden suites (the redaction golden pins the load-error text);
  - every test is run by filter with a positive count, so a filter that
    matches nothing cannot pass.
- **R3:** clippy `-D warnings` of `--lib --tests --bins` on all-features
  and no-default, `check-file-size.py` and `check-timing-asserts.py`.

No reach check is planned. Unlike part 2's fallback, no site here changes
which function runs: each is the adapter body that wraps the very
expression it replaces.
