## 0. Criteria (verbatim, MIK-8408)

- REPLAY.5: a task re-read of a completed multi-target (plan) task renews the reader's receipts for what that read delivers, each step under its own source, as a live plan stages them. Exception: a step label that carries more than one distinct call (a nested plan) renews nothing (known limit, MIK-8409).
- REPLAY.6: a sync retained replay of `gateway_execute` and of `gateway_run_playbook`, on HTTP and stdio, renews the same receipts, with the same nested-plan exception.
- REPLAY.3: a replay renews only what it delivers: the gateway's own text (gateway_writes record), a redacted or withheld step and an unauthorized replay (MIK-8406, MIK-8392) stage nothing. The direction is guarded by rows, each with a KILLED mutant.
- REPLAY.4: red tests seen failing on CI before the fix; two review seats; mutants; feature combos; changelog line; NFR.WORKLOAD.1 measured if a replay hashes more text.

REPLAY.4 is process, not a row: see §6.

## 1. Harnesses

**HTTP route** (`src/gateway/router/tests/task_execution_adapter/relay_plan_replay.rs`, new):
- Built on `relay_plan_route.rs::plan_state_with` (relay_plan_route.rs:42-99): a router firewall with credential redaction, and a relay firewall with `keeping_every_kgram()` and `min_matches: 1`. With those settings, any receipted 48-char run is always refusable, so a missing receipt cannot pass by sampling luck (MIK-8083).
- Two changes to that harness. First, it keeps the relay `Arc<Firewall>` handle, for `advance_collusion_clock_for_test` (collusion_gate_seams.rs:163) with a 1 s window. Second, it registers **two mock backends**: `A` answers `PROSE` (≥300 chars), `B` answers `OTHER_PROSE`. `sources: ["A:*"]`, so A's text is sensitive by rule and B's is plain. Two backends replace a two-tool mock, because `MockBackend` answers by call order (support/backend.rs:190) and lists one tool (:227). Each backend's `Answer::Sequence` repeats its own text, so a later call (carol's) gets the same text.
- Principals: `three_principal_auth` (support.rs:116; used in relay_plan_route.rs:448). key-a is alice, key-b is bob, key-c is carol.
- Pattern for every red row: settle (tasks: `task_executor.drain` joined), then advance the clock by window+1. **Premise P1:** bob relaying A's text succeeds (the receipt lapsed). Then the re-read. **Premise P2:** the re-read did not re-execute (each mock's `calls()` unchanged), so a fresh live receipt cannot explain the result. Then the row's assertion: bob → -32002.
- A setup assert that the settled row's `targets` holds two distinct pairs.

**stdio** (`src/gateway/server/tests/collusion_stdio_plan_replay.rs`, new): built on `collusion_stdio_plan.rs`.
- Its per-tool transport (`Alpha`, :30) answers `alpha:a` and `alpha:b` with distinct texts. `Gateway::dispatch_single` (:79-118) is alice's stdio read and keyed re-read.
- The oracle is `relayed_by_bob(&firewall, text)` (:62-76), a direct `check_relay` for a second principal on the same firewall. No second transport is needed.
- The relay firewall is built with a 1 s window, and its handle advances the clock.
- P2 for stdio: the transport's call count is unchanged across the keyed re-read. The plan arguments carry an idempotency key, and the row first asserts that the stdio meta has the execution admission store (premise).

**Unit**:
- `src/gateway/meta_mcp/plan_provenance_tests.rs`: `executed_steps`, `PlanProvenance` bounds, serde, decode tolerance and drop tiers.
- `src/security/firewall/replay_receipts_tests.rs`: snapshot export, the fresh-digest constructor, store budget, eviction, entry cap, keys and expiry.

**Test seams (`cfg(test)`, new):**
- `Firewall::take_committed_for_test()` and `take_replayed_for_test()`: snapshot and replay comparison.
- `ReplayReceipts::with_budget_for_test(bytes, entry_cap)`.
- A telemetry capture for the drop and absent counters, as existing rows capture metrics.
- A staging probe: `relay::take_staged_for_test()` (relay.rs:648) today records only the direct route's `stage_with`. It is extended to the meta route's `stage_relay_receipt`, so a row can see what was staged before commit or discard.

**Restart (G32):** the test owns a `TempDir` and a new `state_over(dir, firewall)` helper. The first state is dropped in a scope, which releases the lease (pattern: tests/mik_7272_task_1_acs/lifecycle.rs:334). The store is reopened with a fresh `Firewall`, and the mocks are re-registered.

**Feature combos:** relay rows are `cfg(feature = "firewall")`. The `steps` recording rows (G20, G5, G14) also run under `--no-default-features`.

## 9. r3 changes (round-2 seats: gpt SHIP-WITH-FIXES, muse REVISE); these supersede the rows above where they conflict

Bob's relay probes go through `P`, and each probe asserts its own response contains none of the tested text, so a probe never gives bob a same-source excuse (gpt).
