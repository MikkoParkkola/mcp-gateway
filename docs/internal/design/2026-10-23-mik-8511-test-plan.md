## Spark behaviour proof (through the gateway)

The script and its log are kept with the ratification evidence, not in the
repo. Every step has a 60 s deadline and records an rc line. A timeout is a
failure, recorded as one. A step passes only on its stated content, never on
an exit code alone; any JSON-RPC `error` or tool `isError` fails it.

Each step runs on both Node 24 and Node 22. Node 22 must match Node 24 on every
row (REPLACE.5).

| step | asserts |
|---|---|
| S1 initialize | each of the three backends is listed as connected by `gateway_list_servers` |
| S2 tools | `gateway_list_tools(server)` returns the expected names: filesystem includes `read_file` and `list_allowed_directories`; memory includes `create_entities` and `read_graph`; sequential-thinking includes `sequentialthinking` |
| S3 filesystem (REPLACE.4) | `list_allowed_directories` returns both folder arguments; `read_file` inside one returns the seeded file's exact text; `read_file` outside them returns the server's access-denied answer (its "Access denied" text), not a not-found or a success |
| S4 memory | `create_entities` with one named entity, then `read_graph` returns that entity by name |
| S5 sequential-thinking | one `sequentialthinking` step returns a result naming the thought number |
| S6 memory migration | (1) a 1.0.0 graph with entity A is copied to an absolute `MEMORY_FILE_PATH`; (2) 2.0.0 `read_graph` returns A; (3) `create_entities` B; (4) restart; (5) `read_graph` returns both A and B |
| S7 no warning visible (REPLACE.5) | on Node 22, nothing the client receives in S1–S6 (results, errors, notifications) contains `EBADENGINE` or "engine" |

Any Node 22 failure, timeout or hang stops the work: the original clause
stands and I return to the lead (REPLACE.5).
