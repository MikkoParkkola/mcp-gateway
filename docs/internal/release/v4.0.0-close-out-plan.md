## Ordering, and why it no longer binds

The original ordering existed because work completed before the discovery
change landed might have to be regraded against the merged tree:

- **Streams 2 and 3 were merge-independent.** They add tests and production
  code that survive the merge unchanged.
- **Stream 4 was not.** A latency or workload number measured against the
  pre-merge tree has to be retaken against the post-merge one.
- **Stream 5 was not.** A recorded live run is evidence about a specific build.
- **Stream 1 gated streams 4 and 5** and nothing else.

Stream 1 closed on 2026-09-16, so that constraint is discharged. Measure and
record against `origin/main` at `6d033b42` or later; any number taken against
an earlier tree has to be retaken.
