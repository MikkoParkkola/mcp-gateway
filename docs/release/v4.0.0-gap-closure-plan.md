on 2026-09-08: **23 rows are not MET** — 7 `UNWIRED`, 8 `ABSENT`, 8 `PARTIAL`. 146 rows
are MET and 2 are N/A with a reason.

vocabulary change undercounts silently rather than failing. Reconciliation of the two

Three of the four previously unassigned rows are now claimed. They were the largest single
risk in this plan for a reason worth keeping in view: they were not blocked and not in
progress, which is a quieter failure than being stuck and does not announce itself in any
status. Each is now in read-and-report before any code, because all three are recorded as
mechanisms that exist and are unreachable, and the way to fail here is to ship a fourth one.

`CONTROL.4` remains unowned. It is session-lifecycle TTL-reaping, which sits next to the
backend-startup path another lane holds, so it is the one of the four that should not be
claimed without coordinating first — not the one nobody noticed.

## Order, and why

G first, and within G the bridge rows first: they are the only rows where a mechanism
is finished and one wiring change converts it from invisible to done. The era-field
checkpoint is the current critical path and lands as one complete compiling change —
field, all 23 construction sites, and the `WIRE.*` acceptance test together.

A is next and internally sequenced: `PERF.3` soaks the reclamation `MRTR.8b` introduces.

B, D and E touch disjoint code and run concurrently with A. C and H are Codex lanes and
run on their own clock. F is measured against the finished tree so it lands last, but its
bench harness and the 3.5.0 baseline are built early — a harness written after the change
is a harness written to agree with it.

## Per-package process — full scope, not abbreviated

Each package runs `rules-source/workflows/development-process.md` end to end: design
reviewed before any code, test plan reviewed, failing tests reviewed as tests,
implementation, self-QA, final review (two code legs plus the functional leg),
documentation, housekeeping. The reviewer pair for this session's authorship is
gpt-review + kimi-review.

Each package closes by rewriting its rows in the criteria file with evidence: what was
done, what pins it, and what is still not pinned.

## Honest limits, stated now

- Some of the 23 may prove N/A or already MET once read at source — three rows did exactly
  that this week, in both directions. Each package re-verifies its rows against source
  before designing anything. A status is a claim made when it was written.
- `NFR.PERF.1` needs a 3.5.0 baseline that does not exist in this tree, and the benchmark
  must run off this machine. Until both exist the row moves only on assertion.
- Release readiness is the union of both sides. This plan now names the Codex-owned rows
  rather than excluding them, but it does not track them to closure.
- Nothing here is mechanically enforced. The counts came from reading the ledger, and the
  ledger is maintained by hand.
