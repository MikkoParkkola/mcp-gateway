# Design: stdio dispatcher regression rows for keyed execution

Status: revised after independent review, 2026-09-13. No code written yet.

## Why this exists

An independent non-Claude review of commit `2807d72b` asked for dispatcher-level
coverage that the test landed there does not provide. That test,
`stdio_principal_admits_a_keyed_mutation_and_anonymous_http_still_cannot`, pins the
**admission gate** in isolation: it calls `admit` directly and asserts the stdio
principal is accepted while an anonymous HTTP caller is refused with `-32003`. Its
own doc comment states that limit. The reviewer's point stands: nothing exercises
the **dispatcher** that consumes the gate's verdict, so the wiring between them is
unpinned.

The gate side is better covered than that framing suggests.
`src/gateway/meta_mcp/admission_tests.rs` holds twelve tests with `assert_replay`,
`admit` and `refusal` helpers, and every one of the four outcomes already has a
gate-level assertion. So these rows must earn their place purely on the
dispatcher's *consumption* of a verdict, never on the verdict itself.

## The construct under test

`src/gateway/server/mod.rs:2981-2994` turns four admission outcomes into four
dispatch behaviours:

| Admission outcome | Dispatcher behaviour |
|---|---|
| `Unprotected` | `execution = None`, call proceeds |
| `Owned(lease)` | `execution = Some(lease)`, call proceeds holding the lease |
| `Replay(response)` | `break 'tool_call response` — the backend is never reached |
| `Err(error)` | `break 'tool_call` with `error.to_rpc_code()` |

`Replay` and `Err` matter most, because both are early breaks: a regression that
turned either into a fallthrough would still return a well-formed answer to the
caller while silently re-running a mutation.

## Instrument

`tools_call_count()`, already present at
`src/gateway/server/tests/signing_nonce_allocations_support.rs:152`. It derives the
count from the requests the backend recorder actually received rather than
maintaining a separate tally, so there is no second number that can drift from the
first, and its own doc comment already states the invariant these rows need: *a
refusal must not move this*. A new counter was considered and rejected for exactly
that reason.

Two configuration points these rows must set rather than inherit: response caching
must be off, and the keyed target must be declared mutating. The existing stdio
fixture enables caching and declares its target read-only, which would let a
backend-count assertion pass on downstream suppression instead of on admission
replay — the row would be measuring the cache, not the dispatcher.

The lease needs no instrument at all: `dispatch_tools_call` returns
`(JsonRpcResponse, Option<SyncLease>)` (`src/gateway/server/mod.rs:2872-2875`), so
`None` versus `Some(_)` on the second element is what separates the `Unprotected`
arm from the `Owned` arm. Without asserting it, a regression that dropped lease
acquisition for keyed calls would leave every row green.

Each row uses its own idempotency key, so the state row 3 stores cannot reach row
4's conflict setup and every failure stays attributable to one row.

## Rows proposed

1. **Unprotected: an unkeyed call dispatches with no lease.** Assert the call
   succeeds, `execution` is `None`, and `tools_call_count()` is 1. Without this the
   `Unprotected` arm has no dispatcher row at all.
2. **Owned: a keyed call dispatches once and holds a lease.** Assert a successful
   result, a returned lease, and a count of 1. The lease assertion is the point —
   leaving it to row 3 to imply would test the arm's obligation only indirectly.
3. **Replay: a repeated key returns the stored result without re-running it.**
   Dispatch the same key twice under *different request ids*; assert the second
   answer's `result` equals the first and that it carries the **second** id, and
   that the count is still 1. Not byte-identical envelopes:
   `src/gateway/meta_mcp/admission.rs:190` rewrites `response.id` to the current
   request, so an envelope-equality assertion would fail against correct code.
4. **Err: a conflicting key is refused before dispatch.** Same key, different
   arguments; assert the JSON-RPC error code on the wire and that
   `tools_call_count()` did not advance, which is what distinguishes a refusal
   before dispatch from one after.

An anonymous-HTTP row is deliberately **not** here. `build_stdio_caller_context`
hardcodes `credential_principal: Some(STDIO_CREDENTIAL_PRINCIPAL)`
(`src/gateway/server/mod.rs:2820`), so the stdio dispatcher cannot receive an
anonymous caller; a row asserting it would be asserting against a state this path
cannot produce. That coverage stays where it already is, in `admission_tests.rs`.

## Qualification

Two different things are being checked, and conflating them was the first draft's
error.

**Negative controls** (cheap, run in this worktree, test file only): invert each
row's expectation and confirm it fails. This proves the assertion is load-bearing —
that the row is not passing on an unwired fixture. It does *not* prove the row
detects a dispatcher regression.

**Mutation qualification** (the real check): mutate the dispatcher arm itself and
confirm the row goes red. Discard `Owned`'s lease; make `Unprotected` refuse; make
`Replay` fall through to the backend; make `Err` fall through. Each mutation must
kill its row and only its row.

That second set touches production source, which the standing rule forbids in this
shared worktree because peers run `cargo test` against it. So it runs in a separate
disposable checkout and the results are recorded here; the shared tree never holds
a mutated dispatcher. A row that has only passed its negative control is recorded
as *asserting*, not as *qualified*.

One reviewer proposed the cheaper version — transient uncommitted edits, reverted
before committing — on the reading that the rule protects committed state. It does
not: the reason peers are named in it is that their `cargo test` runs against the
working tree, so an edit that exists only between two reverts is exactly the window
that breaks them. The disposable checkout is the one that holds.

## Review

Reviewed 2026-09-13 by two independent non-Claude reviewers; both returned
SHIP-WITH-FIXES and both named the same two defects, which are fixed above: the
`Unprotected` arm had no row, and the replay falsifier as first written required a
production mutation the plan forbade. Three further corrections came from source
checks prompted by the reviews — the replay row would have asserted byte-identical
envelopes against code that deliberately rewrites the id, the anonymous-HTTP row
asserted a state the stdio path cannot construct, and the instrument already
existed. Each was verified in the tree before being adopted.

## Explicitly out of scope

Transport wiring, session establishment, and the HTTP principal path at
`src/gateway/router/handlers.rs:1572`. End-to-end stdio proof already exists at
`tests/mik_7272_sub2b_acs.rs`; this work pins the dispatcher's four-outcome fan-out
and nothing wider.
