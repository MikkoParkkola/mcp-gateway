# Design: stdio dispatcher regression rows for keyed execution

Status: revised after independent review, 2026-09-13. No code written yet.

## Why this exists

An independent non-Claude review of commit `2807d72b` asked for dispatcher-level
coverage that the test landed there does not provide. That test,
`stdio_principal_admits_a_keyed_mutation_and_anonymous_http_still_cannot`, pins the
**admission gate** in isolation: it calls `admit` directly and asserts the stdio
principal is accepted while an anonymous HTTP caller is refused with `-32003`. Its
own doc comment states that limit. The reviewer's point stands: nothing exercises
the **dispatcher** that consumes the gate's verdict, so the wiring between them is
unpinned.

The gate side is better covered than that framing suggests.
`src/gateway/meta_mcp/admission_tests.rs` holds twelve tests with `assert_replay`,
`admit` and `refusal` helpers, and every one of the four outcomes already has a
gate-level assertion. So these rows must earn their place purely on the
dispatcher's *consumption* of a verdict, never on the verdict itself.

## The construct under test

`src/gateway/server/mod.rs:2981-2994` turns four admission outcomes into four
dispatch behaviours:

| Admission outcome | Dispatcher behaviour |
|---|---|
| `Unprotected` | `execution = None`, call proceeds |
| `Owned(lease)` | `execution = Some(lease)`, call proceeds holding the lease |
| `Replay(response)` | `break 'tool_call response` — the backend is never reached |
| `Err(error)` | `break 'tool_call` with `error.to_rpc_code()` |

`Replay` and `Err` matter most, because both are early breaks: a regression that
turned either into a fallthrough would still return a well-formed answer to the
caller while silently re-running a mutation.

## Instrument

`tools_call_count()`, already present at
`src/gateway/server/tests/signing_nonce_allocations_support.rs:152`. It derives the
count from the requests the backend recorder actually received rather than
maintaining a separate tally, so there is no second number that can drift from the
first, and its own doc comment already states the invariant these rows need: *a
refusal must not move this*. A new counter was considered and rejected for exactly
that reason.

Two configuration points these rows must set rather than inherit: response caching
must be off, and the keyed target must be declared mutating. The existing stdio
fixture enables caching and declares its target read-only, which would let a
backend-count assertion pass on downstream suppression instead of on admission
replay — the row would be measuring the cache, not the dispatcher.

The lease needs no instrument at all: `dispatch_tools_call` returns
`(JsonRpcResponse, Option<SyncLease>)` (`src/gateway/server/mod.rs:2872-2875`), so
`None` versus `Some(_)` on the second element is what separates the `Unprotected`
arm from the `Owned` arm. Without asserting it, a regression that dropped lease
acquisition for keyed calls would leave every row green.

Each row uses its own idempotency key, so the state row 3 stores cannot reach row
4's conflict setup and every failure stays attributable to one row.

## Rows proposed

1. **Unprotected: an unkeyed call dispatches with no lease.** Assert the call
   succeeds, `execution` is `None`, and `tools_call_count()` is 1. Without this the
   `Unprotected` arm has no dispatcher row at all.
2. **Owned: a keyed call dispatches once.** Assert a successful result and a
   count of 1. The lease itself is NOT asserted here: the row calls
   `dispatch_single_with_sink`, the entry point `run_stdio` uses, and that
   function does not return the `Option<SyncLease>` its callee
   `dispatch_tools_call` produces. Reaching the lease would mean calling
   `dispatch_tools_call` directly and giving up the production entry point — a
   worse row, not a better one.

   **D24 closes on the mutation result, and not the way this design predicted.**
   The prediction was that `owned-drops-its-lease` would survive, leaving the
   lease uncovered. It does not survive: it comes back OVERBROAD, killing rows 3
   and 4. The lease is unobservable at this entry point but not unobserved, and
   the consequence is attribution, not coverage — see §Qualification round 3 for
   the mechanism and for why fixing the attribution would cost the production
   entry point.
3. **Replay: a repeated key returns the stored result without re-running it.**
   Dispatch the same key twice under *different request ids*; assert the second
   answer's `result` equals the first and that it carries the **second** id, and
   that the count is still 1. Not byte-identical envelopes:
   `src/gateway/meta_mcp/admission.rs:190` rewrites `response.id` to the current
   request, so an envelope-equality assertion would fail against correct code.
4. **Err: a conflicting key is refused before dispatch.** Same key, different
   arguments; assert the JSON-RPC error code on the wire and that
   `tools_call_count()` did not advance, which is what distinguishes a refusal
   before dispatch from one after.

An anonymous-HTTP row is deliberately **not** here. `build_stdio_caller_context`
hardcodes `credential_principal: Some(STDIO_CREDENTIAL_PRINCIPAL)`
(`src/gateway/server/mod.rs:2820`), so the stdio dispatcher cannot receive an
anonymous caller; a row asserting it would be asserting against a state this path
cannot produce. That coverage stays where it already is, in `admission_tests.rs`.

## Qualification

Two different things are being checked, and conflating them was the first draft's
error.

**Negative controls** (cheap, run in this worktree, test file only): invert each
row's expectation and confirm it fails. This proves the assertion is load-bearing —
that the row is not passing on an unwired fixture. It does *not* prove the row
detects a dispatcher regression.

**Mutation qualification** (the real check): mutate the dispatcher arm itself and
confirm the row goes red. Discard `Owned`'s lease; make `Unprotected` refuse; make
`Replay` fall through to the backend; make `Err` fall through. Each mutation must
kill its row and only its row.

That second set touches production source, which the standing rule forbids in this
shared worktree because peers run `cargo test` against it. So it runs in a separate
disposable checkout and the results are recorded here; the shared tree never holds
a mutated dispatcher. A row that has only passed its negative control is recorded
as *asserting*, not as *qualified*.

### Results — round 1, the committed rows, 2026-09-13

Baseline in the disposable checkout: `5 passed; 0 failed`. Each mutant was
applied to `src/gateway/server/mod.rs` alone, and every row was then run by
itself so a kill is attributable to one row.

| Mutation of the dispatcher arm | Verdict | Killed |
|---|---|---|
| `Unprotected` refuses instead of dispatching | QUALIFIED | its own row |
| `Replay` falls through to the backend | QUALIFIED | its own row |
| `Owned` drops its lease (`Owned(lease) => None`) | **OVERBROAD** | the *replay* row |
| `Err` falls through instead of refusing | **SURVIVED** | nothing |

Two of the four mutants are caught by exactly one row, the row named for them.
The other two results are the finding.

**`Owned` drops its lease → OVERBROAD.** The design predicted this would survive.
It killed row 3 instead: the lease is what stores the record replay reads back,
so destroying it breaks replay. The obligation is covered; the attribution is
not. An `Owned`-arm regression reports itself as a replay failure, which is a
maintenance cost, not a coverage gap. Recorded, not fixed — see row 2 above for
why fixing it would cost the production entry point.

**`Err` falls through → SURVIVED.** This is the defect one reviewer predicted
statically and the run confirmed. The row asserted `code == 409` and a count of
1; neither distinguishes the dispatcher's refusal from the independent
downstream guard at `router/backend_handlers.rs:824-841`, which answers a
mismatched key with its own 409 before reaching the backend
(`idempotency.rs:836-846`). The dispatcher could stop refusing entirely and the
row would stay green. Fixed by asserting the message text, which is different
for each of the two producers, and re-qualified in round 2 below.

### Round 2 — retracted

Round 2 was run against the corrected rows and its verdicts are void. They were
read before the corrected rows had been run against *unmutated* source, and when
that baseline was finally taken the conflict row was **red on clean code**:
3 passed, 1 failed. A row that fails on correct source kills every mutant, so
round 2's `Err falls through → QUALIFIED` was an artifact of a broken row, not
evidence that the fix worked.

The cause was narrow. The dispatcher **is** the refuser on the clean path — the
observed message is
`JSON-RPC error 409: Idempotency key belongs to another execution or representation`.
`Error::json_rpc` renders with a `JSON-RPC error <code>: ` prefix, and the
assertion compared for equality against the unwrapped text. Pinning the whole
string would have pinned the wrapper's formatting alongside the identity of the
refuser, so the assertion is a substring check.

Recorded because it cost a round: **mutation qualification is only meaningful
relative to a green baseline of the same code.** The baseline here was taken
against the committed rows, the rows were then edited, and a mutation verdict was
read as evidence without re-establishing that the edited rows were green
unmutated. The harness now asserts the baseline itself and refuses to mutate
anything if a row is already red.

### Results — round 3, the shipped rows, 2026-09-13

Baseline, corrected rows on unmutated source: **4 passed; 0 failed.** Each mutant
then applied to `src/gateway/server/mod.rs` alone, with every row run by itself so
a kill is attributable to one row.

| Mutation of the dispatcher arm | Verdict | Killed |
|---|---|---|
| `Unprotected` refuses instead of dispatching | QUALIFIED | its own row |
| `Replay` falls through to the backend | QUALIFIED | its own row |
| `Err` falls through instead of refusing | QUALIFIED | its own row |
| `Owned` drops its lease (`Owned(lease) => None`) | OVERBROAD | replay + conflict |

Three of the four mutants are caught by exactly one row, the row named for them.
That is the mutant-to-row direction; the row-to-mutant direction is not one-to-one,
because the replay row and the conflict row each also die under
`owned-drops-its-lease` below. A red row names a suspect arm, not a unique one.
The `Err` row detects its own arm only after the message assertion: in round 1
it survived an arm that stopped refusing altogether, because the independent
downstream guard at `router/backend_handlers.rs:824-841` answers a mismatched key
with its own 409 before the backend (`idempotency.rs:836-846`). Code and count
alone cannot tell the two refusers apart.

**`Owned` remains OVERBROAD, and that is the recorded limitation.** The design
predicted this mutant would survive, leaving the lease uncovered. It does not
survive — it kills two other rows. Dropping the lease destroys the record replay
reads back, and it also leaves no admission record for a second conflicting call
to collide with, so that call falls through to the downstream guard whose message
the conflict row now rejects. The arm's obligation is pinned twice over; what is
missing is attribution, not coverage. An `Owned`-arm regression announces itself
as a replay failure and a conflict failure, and a maintainer has to read two red
rows to find a third arm. Fixing that means calling `dispatch_tools_call`
directly and giving up `dispatch_single_with_sink`, the entry point `run_stdio`
uses — a worse row for a better label. Recorded, not fixed.

One reviewer proposed the cheaper versionOne reviewer proposed the cheaper version — transient uncommitted edits, reverted
before committing — on the reading that the rule protects committed state. It does
not: the reason peers are named in it is that their `cargo test` runs against the
working tree, so an edit that exists only between two reverts is exactly the window
that breaks them. The disposable checkout is the one that holds.

## Review

### Round 2 — the committed rows, 2026-09-13

Two independent non-Claude reviewers read the shipped rows; both returned
SHIP-WITH-FIXES and both independently named the `Owned` row's missing lease
assertion, which D24 had already opened and which row 2 above now records as
*asserting, not qualified*.

One finding was new and was verified at source before being adopted: the `Err`
row asserted `code == 409` and a count of 1, and **neither distinguishes the
dispatcher's refusal from a second one downstream**.
`src/gateway/router/backend_handlers.rs:824-841` runs an independent idempotency
guard after this arm, and `src/idempotency.rs:836-846` answers a mismatched key
with its own 409 *before reaching the backend*. A dispatcher that fell through
the `Err` arm entirely would therefore still produce 409 with a count of 1 and
the row would stay green. The fix is to assert the message: the dispatcher's arm
says `Idempotency key belongs to another execution or representation`
(`src/gateway/meta_mcp/admission.rs:200`), the downstream guard says
`Idempotency key is already in use for a different request: {key}`.

Both reviewers, and the design advisor, separately flagged
`the_fixture_target_is_the_one_these_rows_configure` as a tautology padding the
row count; it is deleted. Its stated reason — keeping `BACKEND`/`TOOL` from
reading as unused — was false when written: the support module consumes both
nine times (`signing_nonce_allocations_support.rs:107, 111, 203, 204, 224, 359,
360`), so nothing was ever at risk of going dead. The `Unprotected` row was renamed to
`an_unkeyed_read_only_call_dispatches_exactly_once`, because the old name
promised a lease assertion the row does not make and cannot make from this entry
point.

### Round 1 — the design

Reviewed 2026-09-13 by two independent non-Claude reviewers; both returned
SHIP-WITH-FIXES and both named the same two defects, which are fixed above: the
`Unprotected` arm had no row, and the replay falsifier as first written required a
production mutation the plan forbade. Three further corrections came from source
checks prompted by the reviews — the replay row would have asserted byte-identical
envelopes against code that deliberately rewrites the id, the anonymous-HTTP row
asserted a state the stdio path cannot construct, and the instrument already
existed. Each was verified in the tree before being adopted.

## Explicitly out of scope

Transport wiring, session establishment, and the HTTP principal path at
`src/gateway/router/handlers.rs:1572`. End-to-end stdio proof already exists at
`tests/mik_7272_sub2b_acs.rs`; this work pins the dispatcher's four-outcome fan-out
and nothing wider.
