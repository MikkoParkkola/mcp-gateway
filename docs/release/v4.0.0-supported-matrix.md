# v4.0.0 supported matrix

Covers the first half of NFR.BUILD.1 (`docs/requirements/RELEASE-4.0.0-scope-update.md:59`):
the concrete clients, backends, feature/build combinations and license availability
that 4.0.0 claims to support. The second half — critical-path coverage and mutation
evidence on the final integration revision — is graded separately in
`docs/release/v4.0.0-burndown-tracker.md`.

A row here is a support claim. Removing a row is a scope reduction; adding one
requires the corresponding build or test to exist.

## Protocol revisions

The gateway serves `2025-11-25` by default (`src/lib.rs:106`) and negotiates
downward. A client that sends no `protocolVersion` is treated as `2024-11-05`.

| Revision | Status |
|---|---|
| 2025-11-25 | Served by default; tasks, elicitation, audio, tool annotations |
| 2025-06-18 | Negotiated |
| 2025-03-26 | Negotiated |
| 2024-11-05 | Negotiated; the default for an unversioned initialize |

`src/protocol_revision_telemetry.rs:41` additionally admits `2026-07-28` and
`2024-10-07` as bounded metric labels. A label is an observation, not a support
claim: anything outside the negotiated set above is counted, not served.

## Feature and build combinations

`default` = `a2a`, `webui`, `config-export`, `cost-governance`, `firewall`,
`discovery`, `semantic-search`, `tool-profiles`, `metrics`.
Non-default: `spec-preview`, `task-sdk-recovery`, `runtime-substrate`.

Every combination below is built in CI with `-D warnings`.

| Combination | CI job |
|---|---|
| `--all-features --all-targets` | `check` |
| `--features default` | `feature-combos` |
| `--no-default-features` | `feature-combos` |
| `--no-default-features --features a2a` | `feature-combos` |
| `--no-default-features --features firewall` | `feature-combos` |
| `--no-default-features --features webui` | `feature-combos` |
| `--features spec-preview` | `feature-combos` |
| `--features task-sdk-recovery` | `feature-combos` |
| `--features runtime-substrate` | `feature-combos` |

`feature-combos` builds the library and binaries only. The integration test
targets are written against the default feature set and do not compile without
it; running them under `--no-default-features` would fail on missing imports
rather than on a real build break.

## License availability

Package metadata is `license-file = "LICENSES.md"` — an affirmative per-file
split, not a single SPDX expression and not a per-feature one. Every source file
carries a copyright line plus an explicit `MIT` or
`PolyForm-Noncommercial-1.0.0` identifier; absence is a CI failure, not a
default (`scripts/ci/check-license-headers.sh`, run by the `public-repo-hygiene`
job).

| Tier | Extent | Boundary |
|---|---|---|
| MIT core | 51 of 569 `src/**/*.rs` | `.mit-core-allowlist` |
| PolyForm Noncommercial | the remaining 518 | everything outside the allowlist |

The MIT core is `src/protocol`, `src/transform`, `src/projection`,
`src/validator`, `src/skills`, `src/semantic_search`, `src/error.rs`,
`src/capability/schema_validator`, `src/capability/hash.rs`,
`src/tracing_context` and `crates/gateway-core/src`. A file inside the allowlist
must carry MIT; a file outside it must not.

**No feature combination produces a PolyForm-free build.** Of the EE paths in
`LICENSE-EE.md:27`, only `src/security/firewall/` is behind a Cargo feature
(`firewall`). `agent_identity`, `data_flow`, `message_signing`, `policy`,
`response_inspect`, `response_scanner`, `scope_collision`, `tool_integrity`,
`transparency_log`, `src/cost_accounting/` and `src/key_server/` compile
unconditionally, including under `--no-default-features`
(`src/security/mod.rs:17`, `src/lib.rs:45`). Commercial use of any build of this
binary therefore requires a commercial license; the MIT core is a source-reuse
grant, not a build target.

`LICENSE-EE.md:38` lists `src/transparency_log/`; the module lives at
`src/security/transparency_log.rs`. The path is stale, the coverage is not.
