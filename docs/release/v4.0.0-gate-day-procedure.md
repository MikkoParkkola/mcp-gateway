# v4.0.0 gate-day procedure: NFR.BUILD.1 C6 mutation evidence

The C6 ranking header (`docs/release/v4.0.0-c6-mutation-ranking.tsv:4`) and
the #2689 description both point to "the gate-day procedure" for the C6 pass
rules. That document was never committed. This file records those rules, and
each rule cites the line it comes from. A rule that no source states is listed
under **Open** and is not applied until it is ruled.

Sources:

- **[NFR]** `docs/requirements/RELEASE-4.0.0-scope-update.md:63`, the NFR.BUILD.1 criterion
- **[COV3]** `docs/requirements/RELEASE-4.0.0-scope-update.md:147`, the MIK-7324.COV.3 criterion
- **[TSV]** `docs/release/v4.0.0-c6-mutation-ranking.tsv:1-4`, the ranking header
- **[PR]** #2689 description (merged as `fef196e05`), the pass-rule sentence
- **[TEST]** `scripts/release/test_c6_mutation_sample.py`

## Rules

| # | Rule | Source |
|---|---|---|
| G1 | Mutation evidence grades the final integration revision. Evidence from any earlier revision does not count. | [NFR] "mutation evidence grades the final integration revision"; [COV3] "on the final revision" |
| G2 | There is one FROZEN revision. Every C6 run is on it. | [PR] "one FROZEN" |
| G3 | The obligations are the 68 `SAMPLE` rows of the ranking: account paths 16, HTTP dispatch 16, startup, OAuth, stdio dispatch and tasks 8 each, bridge 4. | [TSV:4] "SAMPLE rows are the gate's obligations"; [TEST] `test_sample_quotas`; [SAMPLER] `QUOTA` |

| G5 | An understudy replaces a SAMPLE row only in rank order, within the same path. | [TSV:4] "understudies replace a row only in rank order"; [SAMPLER] ranks are per path |
| G6 | Each mutant is fail-open: it makes the function's security decision let through what it should refuse. Mutants are approved and hashed before the run. | [PR] "fail-open mutants approved and hashed before the run" |
| G7 | A mutant counts as killed (RED) only when the declared killing assertion fails. A failure anywhere else is not a kill. | [PR] "RED only by the declared killing assertion" |
| G8 | A VOID result never counts toward the pass. | [PR] "no VOID allowance" |
| G9 | A surviving mutant is fixed with a test. The test is re-run and must turn the mutant RED on FROZEN. | [PR] "survivors fixed and re-run RED on FROZEN" |
| G10 | No mutant run happens before FROZEN exists. | G1, G2 |

Together, G7 to G9 mean the gate passes only when every approved mutant ends
RED by its declared assertion on FROZEN. No source allows a pass rate below
that.

## Open

Each item below needs a ruling before the gate runs. None is applied until it
has one.

**O1. How a survivor fix meets "on FROZEN".** G9 needs a new test, and a new
test is a new commit. The release plan says any commit after the freeze
invalidates the tip evidence.
- (a) The fix lands and becomes a new FROZEN. C5 coverage, and every C6 row
  already graded, are re-run on it. This keeps the sources consistent, and
  every survivor costs a full re-run.
- (b) Graded rows carry over, and only C5 and the fixed rows are re-run on
  the new SHA. This is cheaper, but no current source permits it.
- (c) Mutants run on a pre-freeze candidate. Survivors are fixed before the
  freeze, and FROZEN gets one confirming run. This is cheapest, but it uses
  pre-freeze runs, which G1 and G10 rule out unless the confirming run counts.

**O2. Mutants per SAMPLE row.** No source states a count.
- (a) One fail-open mutant per refusal branch. This covers the most, and the
  run is longer.
- (b) One mutant per function. This is the cheapest, and a function with
  several refusals is only partly graded.

**O3. Who approves the mutant set (G6), and where the hash is recorded.**
- (a) Two review seats on a committed manifest, with its sha256 in the
  ledger row. This is consistent with how #2689 was reviewed.
- (b) Operator approval of the manifest. This takes the most operator time.

**O4. Equivalent mutants.** No source covers a mutant that cannot change
behaviour. G6 makes every approved mutant fail-open by construction, so an
equivalent one is an approval error.
- (a) It is withdrawn before the run and replaced, still under G6. After the
  run it cannot be withdrawn.
- (b) A written waiver naming the function and the reason, under [COV3]'s
  waiver clause. The 2026-10-01 COV.3 ledger note says "no waivers" for
  coverage, so this would need its own ruling.

**O5. When an understudy may replace a SAMPLE row (G5).** No source states
the trigger.
- (a) Only when the function no longer exists at FROZEN, or a fail-open
  mutant of it cannot be written. This is the narrowest, and resists cherry
  picking.
- (b) Also when a row is VOID twice. This is looser, and lets a flaky row
  drop out.

**O6. A VOID result (G8).** No source says whether a VOID row may be re-run.
- (a) A VOID row is re-run on FROZEN until it is RED or SURVIVED. VOID never
  passes.
- (b) Any VOID fails the gate outright.

## Mechanics

Rows run through the existing batch harness: `.github/workflows/mutants.yml`,
`scripts/ci/mutants/run_mutants.py`. It classifies RED, SURVIVED, VOID and
ERROR from cargo's output. G7's declared-assertion check reads the RED row's
evidence lines against the declared assertion. The harness checks that a test
failed; it does not check which one.
