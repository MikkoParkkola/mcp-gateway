## Why the headline number is slow

It is a lagging measure by construction. A criterion closes when its ledger row carries
evidence, not when the code lands, so delivery work that is real moves it late or not at
all. The decomposition below is what actually converges day to day.

| Bucket | Count | What closes it |
|---|---|---|
| Met on the integration branch, unlanded | 9 | the integration merge |
| Validation against the final revision | 5 | measurement after the merge |
| Deploy probe (`NFR.SEC.7`) | 1 | a probe against the running build |
| Genuine implementation | 13 | code |

Two of the five validation rows carry pre-merge build work rather than measurement:
`NFR.CONFORMANCE.1` needs its matrix widened, `NFR.WORKLOAD.1` needs a harness and a
frozen 3.5.0 baseline that no branch currently measures.
