# v4.0.0 decision docket

The release gate is red on 17 criteria. This document splits them by **what
terminates them**: work this line can do, or a ruling only the release owner can
give. It is the actionable half of "What actually blocks the tag" in the burndown
tracker. Nothing here records an approval; the recommendations are input to one.

Counts: **7 terminate on an owner ruling**, **8 are engineering-closable**,
**2 are order-blocked behind another row**.

## B. Engineering-closable on this line (6)

Ordered by cost per row closed.

1. **CLOSED 2026-09-16 at `f93a805b` + `756bd6cd`. `MIK-7387.STDIO.1` / `.2` / `.3` — three rows, one file.** The stdio reply
   channel is built and unwired on the release line; the serve loop at
   `src/gateway/server/mod.rs:2328` awaits each dispatch inline and is strictly
   sequential, so a reply arriving on stdin during a dispatch can never be read.
   The design records the blast radius as LOW — 17 impacted symbols, one file —
   which contradicts the prior grading document's unexplained "large". All three
   acceptance rows already exist and are `#[ignore]`d
   (`tests/mik_7212_mrtr7_stdio_acs.rs:356`, `:421`, `:471`); nothing anywhere
   un-ignores them. **Cheapest cluster on the board, and it also unblocks the
   mixed-era scenario in `NFR.DEMO.1`.**
2. **`MIK-7332.DISCOVERY.1` — product work done, gate red.** All three product
   gaps are implemented and covered. The row stays pending only because the
   release test gate is red on a pre-existing wall-clock-threshold test
   (`registry.rs:288`) that was never re-run against the base commit. Closing the
   row means settling that test, not writing product code.
3. **`NFR.CONFORMANCE.1` — one missing mechanism.** The matrix cell is empty
   because no path recovers the extensions a client declares in `_meta`, so E4/E5
   have nothing to assert against. Closes when client-extension recovery is
   implemented, not when more tests are written.
4. **`MIK-6745.JOURNEY.1` — a recording plus one real path.** Needs a recorded run
   and a real browser-consent-cancel path. No journey or recording branch exists.
5. **`NFR.DEMO.1` — five live scenarios.** The mechanism is not the gap: `demo.tape`
   plus VHS is a re-runnable pipeline. Five live-environment scenarios with version
   and expected/actual write-ups are. **Sequence after the stdio cluster** — the
   mixed-era scenario depends on the legacy stdio bridge, and recording a scenario
   whose mechanism is still moving would have to be redone.
6. **`MIK-6746.CONTRACT.1` — real build work.** Forwarding is already primary while
   C1, C3, C4 and C5 are short, so the gate fires on the conjunction. The only
   passthrough ingress is the gateway-specific header
   `x-mcp-passthrough-authorization`, and `scope-tests.md:46` states a custom header
   alone cannot pass the standard-interoperability cell. Largest of the six.

## C. Order-blocked behind another row (2)

- **`MIK-3274.RANKING.3`** freezes selection quality only
  (`benchmarks/ranking-baseline/FREEZE.md`, 114 held-out queries). Three metric
  families named in its section 3 — discovery turns, invalid invocations, total
  completed-task tokens — have **no thresholds**, and setting them needs a
  live-agent trial harness over the 119-tool capability set.
- **`MIK-3274.RANKING.1`** cannot land first. The row reads: status stays pending
  *until a live-agent baseline run sets the other three thresholds before
  RANKING.1 lands*. Implementing fuzzy matching now would permanently foreclose
  RANKING.3's baseline. The harness is the single most expensive item on the 17,
  and its output is still only an input.

## What this means for the tag

Engineering alone cannot reach it. Seven rows terminate on a decision, and four of
those seven are already diagnosed to the end of cheap evidence — more measurement
will not move them. The engineering half has a clear cheapest-first order, and the
stdio cluster leads it on every axis: three rows, one file, LOW blast radius, tests
already written.
