# v4.0.0 critical-path coverage contract

Covers conjunct **C5** of `NFR.BUILD.1`
(`docs/requirements/RELEASE-4.0.0-scope-update.md:59`):

> Pin supported reference client/backend versions and feature/build
> combinations under the existing license split; current critical-path coverage
> and mutation evidence grades the final integration revision.

## What this document is, and what it is not

**It does not close C5.** Read the criterion's verb: *"current critical-path
coverage and mutation evidence **grades the final integration revision**"* —
one verb, one object, two subjects. C5 carries exactly the same final-revision
dependency as C6, and the final integration revision does not exist yet. Any
number taken today grades a revision that is not the one the criterion names.

What was missing before this document is the other half of the obligation, and
that half does not depend on the final revision at all.
`docs/requirements/RELEASE-4.0.0-scope-tests.md:73` requires coverage on
"final integrated **startup, OAuth, HTTP/stdio dispatch, bridge, tasks and
account paths**" — six named paths with no mapping anywhere to concrete
modules, and no agreed command. "Agreed critical coverage" cannot be run
against a list of six English nouns. This document fixes the mapping, the
command and the baseline now, so that when the final revision lands the
measurement is a re-run rather than a fresh argument about scope.

The prior artifact, `docs/design/2026-09-03-cluster-a-coverage-audit.md`, is
self-scoped "Audit only" and reports Cluster A component rows at `9b0643d4`.
It is not superseded — it answers a different question — but it is not
critical-path coverage and was never claimed to be.

## The mapping

Each row fixes one named path to the modules that implement it. A path whose
module set changes is a change to this contract, made in the same commit.

| Named path | Modules |
|---|---|
| startup | `src/gateway/server/` |
| OAuth | `src/oauth/` |
| HTTP dispatch | `src/transport/http/`, `src/gateway/router/` |
| stdio dispatch | `src/transport/stdio.rs`, `src/gateway/server/stdio_channel.rs`, `src/transport/command_split.rs` |
| bridge | `src/gateway/input_bridge.rs` |
| tasks | `src/gateway/task_service/`, `src/gateway/router/handlers/tasks.rs`, `src/gateway/meta_mcp/task_confirmation` |

## The command

```sh
cargo llvm-cov --lib --summary-only --json --output-path cov.json
```

Line coverage per path is then the covered/total line ratio summed over the
files whose path starts with one of that row's prefixes. Test modules are
excluded: re-running the report with
`--ignore-filename-regex '(_tests|/tests)\.rs$'` returns byte-identical totals
and zero excluded files, so the 382 files in the report are production sources
already.

**`--lib` is a deliberate, stated limit.** It measures what the library's own
unit tests reach. The integration suite under `tests/` exercises dispatch,
tasks and accounts end to end and is *not* counted here, so every figure below
is a floor, not an estimate. The final-revision run must use
`--all-features --all-targets`; this contract records the narrower command
because it is the one that was actually executed, and a command nobody ran is
not evidence.

## The baseline

**Recorded floor, measured and not enforced: each path's `--lib` line coverage
in the table above.** The weakest path is startup at 68.78%; the strongest is
tasks at 93.84%.

This is a **baseline, not a threshold.** Nothing recomputes it. Calling an
unenforced number a rule would be the exact failure this release has already
been bitten by — `docs/release/v4.0.0-supported-matrix.md` spent this same
session replacing a capability count that read as evidence while being a memory
of what was once true, and a floor with no job behind it is that again in a
different file. The numbers above are a measurement with a date and a command,
and they are worth exactly that until something re-runs them.

Turning the baseline into a ratchet — in the shape of
`scripts/ci/check-loc-ceiling.sh`, which the repository already uses for the
file-size deviation — means making an instrumented coverage build a required
job. That is a release-owner decision about CI cost and about which revision it
gates, and this document does not make it.

## What closing C5 requires

1. The final integration revision exists and is named.
2. `cargo llvm-cov --all-features --all-targets` runs clean on it — clean,
   not `--ignore-run-fail`, and on a tree with no uncommitted edits.
3. The per-path table above is re-taken against that revision and no row is
   below its recorded baseline.

Steps 2 and 3 are a re-run of a fixed contract. Step 1 is the blocker, and it
is the same blocker C6 has.
