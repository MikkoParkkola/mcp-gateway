## MRTR residual — verified at source, and the justification does not hold

The MRTR author reported that `apply_context_integrity` replaces the whole
envelope when `enforcement_applied` is true, dropping `requestState`, and judged
MRTR.2 still satisfied **because the affected path is a withhold path**, where
dropping the field is not observable to the caller.

Two corrections, both verified by reading the function.

**The anchor was wrong.** The function is at
`src/gateway/meta_mcp/invoke.rs:1686`, not `src/gateway/invoke.rs:1434`. The
reported path does not exist. Line anchors reported from an agent worktree are
unreliable; re-locate by symbol before citing one.

**The withhold justification covers only one of two branches.**
`context_integrity_delivered_result` (line 1741) has two exits:

| branch | condition | what the caller receives |
|---|---|---|
| withhold | `evaluation.transformed.delivered` is `None` | an `isError` envelope — the author's justification applies here |
| **transform** | `delivered` is `Some(obj)`, `obj.is_object()` (lines 1757-1758) | **`delivered` returned wholesale as a normal, non-error result** |

On the transform branch the original `result` is discarded and the call still
succeeds. `requestState` is dropped on a path where the caller sees success and
has every reason to expect the envelope intact. That is not a withhold, and the
recorded justification does not reach it.

**Consequence: MRTR.2 cannot be stamped MET on the reasoning as recorded.**
Either show the kernel never returns `Some` under `enforcement_applied` — which
would make the transform branch dead and the justification sound — or treat
MRTR.2 as open. The burden sits with the MET claim, not with the objection.

Not yet done: the kernel side that populates `transformed.delivered` was not
read. That read is what closes this either way.
