This total is a floor that can RISE, not a burndown ceiling. CI compiles fail-fast:
while the library fails, no integration-test target is built, so its errors are not yet
in any job log. Clearing one layer reveals the next — measured, not predicted: after the
`personal_accounts` dead-code fix let the library compile, `cargo check --all-targets`
surfaced 5 previously invisible errors in `tests/task_upstream_recovery/helper.rs`.
Expect the number to grow before it shrinks.


## How to regenerate this number

```sh
f=docs/requirements/RELEASE-4.0.0-criteria-status.md
total=$(rg -c '^\| *(MIK-|[A-Z][A-Z0-9]+\.)' $f)
met=$(rg -c '^\| *(MIK-|[A-Z][A-Z0-9]+\.).*\| *MET' $f)
echo "core: $((total-met)) open of $total"
jq -r '.criteria[].status' docs/requirements/RELEASE-4.0.0-scope-status.json \
  | sort | uniq -c
```

(`RANKING`, `DISCOVERY`, `CATALOGUE`, `PIN`, `AUDIT`, `NFR.CONFORMANCE/WORKLOAD/UPGRADE/DEMO/BUILD`)
appear in it. Verified: `rg -c 'RANKING.1' criteria-status.md` returns 0 for all ten probes.
