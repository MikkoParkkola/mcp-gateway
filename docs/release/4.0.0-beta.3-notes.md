# mcp-gateway 4.0.0-beta.3

This is the third public pre-release of mcp-gateway 4.0. It is here so that people running
3.x or an earlier beta can try 4.0 against their own configurations and clients before the
final release, and tell us what breaks. What 4.0 is as a whole is in
[`docs/whats-new-4.0.md`](../whats-new-4.0.md); this page covers what changed since
[beta.2](4.0.0-beta.2-notes.md).

## New since beta.2

- **MCP Events (opt-in, `events.enabled`).** `events/list`, `events/subscribe` and
  `events/unsubscribe` over HTTP. Deliveries go through a durable outbox and are signed,
  retried, rate-limited and audited. Each attempt passes the firewall, tenant and access checks,
  and the subscriber's credential is re-checked before every delivery. Dead letters can be
  listed and replayed (`mcp-gateway events dead-letters`). A backend's own list-changed and
  resource-updated notifications, and task completion, can be subscribed to.
- **CLI and MCP capabilities run.** A capability with `service: cli` or `service: mcp` used to
  load and never run. It now runs its command with no shell, from validated arguments, in a
  private directory with a cleared environment, an output cap and a timeout. Only pinned
  capabilities whose command is on `capabilities.process_commands` run.
  `capabilities.process_execution: disabled` turns this off. The Google Workspace capabilities
  and `pyghidra_reverse` now run, and REST capabilities for Brave, Tavily, Firecrawl, Sentry
  and the Cloudflare v4 API join the catalogue.
- **Relay detection (off by default).** The new `security.firewall.collusion` section spots
  content that one caller was delivered and another caller then sends out, on the meta,
  direct and stdio routes. Set `action` to `observe` to log and audit it, or `block` to refuse
  the call before dispatch. It matches verbatim text only.
- **`security.posture: hardened`.** One setting raises the context-integrity preset, turns the
  firewall and anomaly blocking on, forces message signing, and refuses HTTP requests that carry
  no per-caller identity. The default, `standard`, changes nothing.
- **Helm chart auth.** `auth.mode: api_keys` and `auth.mode: oidc` render API-key and OIDC
  auth. `persistence` keeps the state volume on a claim. Existing `credential` and `mesh`
  values render as before.
- **Tasks.** A task can now stop to ask for input (`input_required`); answer with
  `tasks/update` and the same call resumes. A task notification carries the full task. A
  stdio gateway keeps durable tasks for its local operator, and stdio honours
  `notifications/cancelled`.
- **Grant changes are audited.** The `identity grants` CLI journals each change, the gateway
  records it exactly once, and every personal-capability call records its grant decision.
- **Easier setup.** `mcp-gateway add <name>` writes a built-in server's references, OAuth and
  HTTP settings (35 servers now), `mcp-gateway init` enables those that need no account, and
  `mcp-gateway list --available` browses them.
- **Security fixes.** This beta carries over a hundred security entries. Among those that also
  affect 3.x: dashboard sessions expire after 30 minutes idle or 8 hours, and logout ends
  them; the OAuth authorization code is no longer written to the debug log; OAuth secrets are
  never sent over plain HTTP to another host; and Unix secret and trust files must belong to
  the gateway's user or root. Each entry in `changelog.d/` in this tag names the versions it
  affects and what an operator has to do.

## Before you upgrade from beta.2

[`docs/UPGRADING-4.0.md`](../UPGRADING-4.0.md) is still the full list, with the action each item
needs. The changes since beta.2 most likely to affect an existing install:

- **Back up `tasks.store_dir` first.** Some failed upstream tasks are now stored in a newer
  record format, and an older gateway refuses a store that holds one. A backup taken after the
  upgrade may hold the new format too, so only a backup taken before it lets you go back.
- **Secret and trust files must belong to the gateway's user or root** (Unix), whatever their
  mode. `chown` them to the gateway's uid (`1001` in the container). Root-owned Kubernetes
  projections still load.
- **A stdio backend message is limited to 16 MiB.** A backend that sends larger single
  messages needs `backends.<name>.max_frame_bytes`.
- **`mcp-gateway plugin` is gone.** A `marketplace:` block now loads with a warning; add tools
  as `backends:` entries or capability files instead.
- **18 built-in server names without a maintained server were removed**, and `jira` is now
  `atlassian`.
- **A capability that needs a key or a login is listed only once it has one.** Calls to it by
  name work as before. `mcp-gateway cap list` shows what each hidden capability is waiting for.
- **With auth and identity grants on, a governance store that cannot open stops the start.**
- **Attestation `enforce` needs `GATEWAY_ATTESTATION_AUDIENCE`.** Tokens carry an audience
  claim, and a gateway accepts only its own.
- **Retired config keys load again with a warning** instead of refusing the whole config:
  `backends.<name>.idle_timeout`, `backends.<name>.circuit_breaker`, `server.ws_port` and
  `server.request_timeout`. Keys starting with `_` or `x-` are annotations and are ignored.
- **Log and output formats.** The firewall's "relay observed" warning always logs `server` and
  `tool`. `kubernetes controller --watch --format json` prints JSON Lines. The
  `doctor --shadow` header names `docs/SHADOW_SCAN.md`.
- **Library users.** Several public types gained variants or became `#[non_exhaustive]`, and
  `CacheScope::Public` is gone. See the upgrade guide.

## About this beta

**It is a beta, not 4.0.0.** It is not feature complete (see [Known gaps](#known-gaps)),
and it is published only to channels you have to opt in to. Nothing that installs "the
latest version" picks it up: the npm `latest` dist-tag, the `:latest` container tag, the
Homebrew formula and the MCP Registry entry all stay on 3.x, and no `:4.0` tag is created.

Please report problems, and upgrade friction in particular, as
[GitHub issues](https://github.com/MikkoParkkola/mcp-gateway/issues). Include the version
(`mcp-gateway --version`) and the smallest config that shows the problem, with secrets removed.

## Install

Pin the exact version. None of these commands resolves to the beta unless you ask for it.

| Channel | Command |
|---|---|
| crates.io | `cargo install mcp-gateway --version 4.0.0-beta.3` |
| npm | `npm install -g @mikkoparkkola/mcp-gateway@next` (or `@4.0.0-beta.3`) |
| Container | `docker pull ghcr.io/mikkoparkkola/mcp-gateway:4.0.0-beta.3` (`:4.0.0-beta.3-full` adds the Node.js, `uv` and `git` runtimes stdio backends use) |
| Helm | the chart in this tag (`deploy/helm/mcp-gateway`) defaults to image `4.0.0-beta.3` |
| Binaries | download from the assets below and check them with `sha256sum -c SHA256SUMS.txt` |

Homebrew is not updated for pre-releases. The container images are signed with cosign and
carry an SBOM attestation, the same as a final release. Verify them by digest as described in
[`docs/release/v4.0.0-prerelease-channel.md`](v4.0.0-prerelease-channel.md), using
`refs/tags/v4.0.0-beta.3` as the certificate identity.

The beta passes the same security and quality gates as a final release: the dependency and
image vulnerability scans, secret-leak lint, formatting, lints and the full test suite. The
one gate a beta does not have to pass is the 4.0.0 acceptance gate, which requires every
release criterion to be met. The open ones are listed next.

## Known gaps

4.0.0 is tracked against 134 release criteria. At this beta 127 are met, one is accepted as
shipping unmet, and the 6 still open are below in plain terms. All of the beta.2 gaps
not listed here have since been met.

**Validation**

- The real-backend workload benchmark against 3.5.x has not produced a passing run yet, so
  there is no end-to-end latency comparison with 3.x.
- The coverage and mutation evidence has to be graded again on the final revision.
- Every coverage or mutation shortfall on the final revision has to be closed with tests or
  waived in writing, module by module.
- How long the gateway keeps serving the older MCP revisions beside 2026-07-28 has not been
  decided yet. That decision waits for measured client data. Two criteria cover it.

**MCP Events**

- The automated end-to-end test passes, but the live run with a third-party client (subscribe,
  verify, deliver, unsubscribe over a tunnel) has not been recorded yet.

**Accepted for 4.0.0**

- Tool-discovery ranking is measured against frozen thresholds for selection quality only.
  Discovery turns, invalid tool calls and total tokens per completed task are not measured or
  held to thresholds in 4.0.0. This is accepted and will not block the final release.

The live list is the release ledger, `docs/requirements/RELEASE-4.0.0-scope-status.json`;
`python3 scripts/release/check_scope_acceptance.py --release` prints what is still open.
