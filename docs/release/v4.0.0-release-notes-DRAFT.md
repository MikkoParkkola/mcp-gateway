## Breaking changes

Eight, ordered by how likely they are to bite an existing install.

1. **`meta_mcp.exposed_meta_tools` is enforced** on both `tools/list` and `tools/call`
   (previously documented but inert). Unrecognised names are warned and dropped;
   omitting `gateway_invoke` is warned and then honoured; backend tools are
   unaffected. A waiver of NFR.COMPAT.3 is recorded — enforce-in-4.0 was chosen over
   warn-in-4.0 / enforce-in-4.1. (**I**)
2. **`list --json` shape changed.** `BackendInfo.env` is now a list of variable
   *names* (`Vec<String>`, values never exposed) and `.command` is an optional
   summary struct (`BackendCommandInfo`, presence-only, arguments never exposed);
   `.url` is reduced to its origin. Anything parsing this output must be updated.
   (**V** — `src/gateway/ui/backend_ops.rs:40`)
3. **Protocol `2024-10-07` is no longer advertised.** `SUPPORTED_VERSIONS` is
   2025-11-25 / 2025-06-18 / 2025-03-26 / 2024-11-05. **Action needed: none for
   conforming clients.** `2024-10-07` was never a real MCP revision, and nothing is
   rejected that was previously accepted: `negotiate_version("2024-10-07")` returns
   `"2025-11-25"` — the same fallback any unrecognized version string gets, before and
   after this release. Only what `server/discover` *claims* changed. See
   `docs/UPGRADING-4.0.md` §3. (**V** — `src/protocol/mod.rs:54`,
   `tests/integration.rs:26,37`)
4. **OAuth credentials are keyed by issuer.** 3.x tokens are not migrated: expect one
   re-authentication per OAuth backend on first use. No config change required. (**I**)
5. **A malformed line in an `env_files` file now fails startup** (previously skipped
   silently). The error names the offending line. (**I**)
6. **Error budgets / circuit breaker no longer count HTTP 429 and equivalents**
   (`too many requests`, `rate limit`, `RESOURCE_EXHAUSTED`, `throttled`).
   Suppressions are counted by `mcp_error_budget_suppressed_total` (GH #475). If you
   alert on budget samples, your signal changes. (**I**)
7. **One licence: PolyForm Noncommercial 1.0.0 across the whole repository.** The MIT
   core carve-out and the MIT core allowlist file are removed (ADR-013);
   `LICENSE-EE.md` is marked SUPERSEDED. Commercial use now requires a commercial
   licence. (**I**)
8. **`server.modern_protocol` defaults to `true`** — the 2026-07-28 stateless/modern
   path is served by default. Note `2026-07-28` is deliberately *absent* from
   `SUPPORTED_VERSIONS`: it is reached per-request via `_meta`, not via `initialize`.
   Opt out with `server.modern_protocol: false`. (**V** —
   `src/gateway/router/handlers.rs`, `MODERN_VERSIONS` gate)

## Upgrading from 3.5.x

Six items. The first four are the verbatim on-upgrade notice items; the last two
are not in that notice and are the ones most likely to surprise you.

1. **Re-authenticate each OAuth backend once.** Credentials are now keyed by issuer
   and 3.x tokens are not migrated. No config change.
2. **Check your `env_files`.** A malformed line now fails startup instead of being
   skipped; the error names the line. Fix or remove it before upgrading a running
   install.
3. **Protocol `2024-10-07`: no action.** It is no longer advertised, but it is still
   negotiated exactly as before — to the `2025-11-25` fallback. The startup notice's
   advice to upgrade such a client is advisory only; see `docs/UPGRADING-4.0.md` §3.
4. **Re-point rate-limit alerting.** HTTP 429 and equivalents no longer consume the
   error budget or trip the circuit breaker; watch
   `mcp_error_budget_suppressed_total` instead.
5. **Audit `meta_mcp.exposed_meta_tools`.** It is now enforced. If the list was
   written when it was inert, the surface your clients see will change on restart.
   Unrecognised names are dropped with a warning; omit `gateway_invoke` only
   deliberately.
6. **Update anything parsing `list --json`.** `env` is now a list of names and
   `command` an optional presence-only struct; `url` is reduced to its origin.

If you need the pre-4.0 stateless behaviour, set `server.modern_protocol: false`.
