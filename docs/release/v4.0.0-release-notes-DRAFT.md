## Step 4 — Breaking changes

**v4.0.0 does have breaking changes** — this is not a case of a major-version
bump with no breaking content:

1. `exposed_meta_tools`, once set, now actually restricts the Meta-MCP surface.
   A deployment that set it expecting no effect gets tools hidden and refused
   on the next restart. (V — read the enforcement code and the existing draft's
   commit history.)
2. `list --json` output shape changes: `BackendInfo.env` becomes a list of
   names, `.command` a summary struct, from commit `3047b916` "fix(security):
   report backend names and counts, never configured values (#439)", whose
   message states this explicitly. (V — read commit body.)
3. `2024-10-07` is no longer advertised as a supported protocol version (I —
   CHANGELOG).

No other removed public functions, renamed CLI flags, or other config-schema
key changes were found by grepping commit subjects for "BREAKING" (6 hits, 5
were false positives — the word appears in prose, not as a breaking-change
declaration) or by reading the CHANGELOG `[4.0.0]` section (no `Breaking`
heading present there). (V for the grep; I for exhaustiveness — 471 commits
were not read individually.)

## Release notes draft (user-facing prose)

*Marketing language, superlatives and emoji intentionally omitted per house
style.*

v4.0.0 adds optional support for the 2026-07-28 MCP protocol revision, keeping
the previous protocol generation available side by side (opt in via
`server.modern_protocol`; default is off). It closes a gap where the
`exposed_meta_tools` configuration field was documented as a Meta-MCP
allow-list but had no effect — the field is now enforced on both tool listing
and tool calls, including under Code Mode and in the `initialize` preamble.
Operators who had already set this field will see previously-callable
meta-tools hidden or refused after their next restart.

This release also tightens diagnostic output: backend configuration values
(URLs, environment variable contents, session identifiers) are no longer
echoed verbatim into logs or into `list --json` output. `BackendInfo.env` and
`.command` change shape in that JSON output as a result — anything parsing it
programmatically should be re-checked.

OAuth credentials are now stored keyed by issuer rather than by a shared key,
and dynamic client registration validates the issuer returned during
authorization before redeeming it, closing a cross-IdP credential mix-up.
Existing sessions will be asked to re-authenticate after the upgrade.

Firewall call budgets are now keyed on the calling principal rather than the
session, closing a way to reset an exhausted budget by opening a new session.
Destructive tool calls on the modern protocol path are now refused or
confirmed based on the backend's own `destructiveHint` annotation.

One known limitation ships recorded rather than fixed: on the modern protocol
path, a multi-round tool exchange that passes through an enforced
content-integrity transform (`Strip` or `Summarize`) currently loses its
continuation state, ending the exchange without an error. A caller sees an
apparently successful result and does not learn that the follow-up round is
unavailable. A patch exists but has not been merged.

`2024-10-07` is no longer advertised as a supported protocol version; clients
that only request that version should upgrade or continue on the previous
release line.
