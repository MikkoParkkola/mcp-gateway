# v4.0.0 — release notes (DRAFT, not publishable)

Status: **draft**. Nothing below has shipped. Every branch this describes is at
step 0 of the five-step delivery chain — no push, no PR, no merge. Confidence
markers are per-claim: **V** = read at source or observed in test output this
session, **I** = one source, **A** = asserted by an agent and not independently
checked. Anything marked **A** must be verified before this becomes public text.

## Theme

v4.0.0 is a **protocol-conformance and enforcement release**. The work is
concentrated in three places: bringing the gateway in line with the 2026 MCP
protocol drafts, closing controls that were documented but not enforced, and
correcting keys that were derived from the wrong identity.

There are no new capability backends and no change to the Meta-MCP tool count
in this release. The context-savings claim is unchanged.

## Enforcement — controls that were documented and did not act

### `exposed_meta_tools` is now honoured  (V)

The config field shipped with a doc comment promising an allow-list: name a
subset of meta-tools and the rest become neither listable nor callable. The
predicate implementing it existed, was tested, and had **no caller outside
tests**. An operator setting `exposed_meta_tools: ["gateway_invoke"]` got a
gateway that still listed and still executed every meta-tool — a field that
read as a restriction and enforced nothing.

It is now consumed on both `tools/list` and `tools/call`, wired from config at
server construction. A refusal on an unexposed tool is worded exactly like the
unrecognised-tool fallback, so hiding a tool cannot confirm it exists.

Two follow-on defects were found by review and fixed in the same change:

- **Code Mode was exempt.** `gateway_search` and `gateway_execute` come from a
  second builder the governed set never consulted, so they stayed callable
  under any allow-list — and `gateway_execute` reaches every backend tool.
  Repaired at the derivation, not the call site: the governed set now chains
  every builder, and a test fails if a future builder is left out.
- **`initialize` announced four meta-tools unconditionally.** The discovery
  preamble hardcoded four names into the `instructions` field, which reaches
  every client before any `tools/list`. It now emits only the exposed ones.

Behaviour change for operators: a non-empty `exposed_meta_tools` starts being
honoured. It takes effect on **restart**, not on `gateway_reload_config`.

### Firewall call budgets are keyed on the principal  (I)

Budgets were keyed on the session. A caller could reset an exhausted budget by
opening a new session. Now keyed on the principal.

### Transparency-log correlation uses the OTel trace id  (I)

The correlation key was the session id, which does not survive a gateway hop.
Now the trace id, which does.

### Tenant guard wired into `check_request`  (I)

The guard existed and was not on the request path.

## Protocol conformance — MCP 2026 drafts

### Multi-round tool requests (MRTR)  (A — cluster carries WIP commits)

- An input request the client never declared is refused.
- An idempotency key is no longer settled on an interim result — settling early
  made a retry return the interim answer as final.
- **Open:** MRTR.2. On an enforced content-integrity path (`Strip`,
  `Summarize`), the delivered result is a string, and the scalar-wrap exit
  builds a fresh success envelope from that text alone — discarding
  `requestState`, the handle a multi-round exchange needs to continue. The
  caller sees success and the exchange has silently ended. Patch drafted, not
  applied, not reviewed.

### Extension negotiation in `initialize`  (A)

MIK-7272.EXT.1 wired. Branch carries a WIP snapshot commit.

### Cache scope resolved from a decision table  (I)

Each cacheable method is scoped by its own table row rather than by a shared
helper, with a test asserting the table decides every cacheable endpoint. The
helpers the table replaced were deleted.

## Known residuals — shipped as recorded limitations, not fixed

| residual | effect | why not in this release |
|---|---|---|
| MRTR.2 scalar-wrap envelope | an enforced transform ends a multi-round exchange | patch drafted, unreviewed |
| admin gate precedes the exposure gate | an unexposed **admin** meta-tool answers `requires admin access`, disclosing existence | reordering the router's pre-dispatch blocks is a separate change |
| destructive-confirmation elicitation precedes the exposure gate | an unexposed destructive meta-tool prompts the operator, then refuses | same pipeline, same disposal — fixing one leaves the other open |
| authorisation and firewall scan precede the exposure gate | audit records exist for a call that is then refused | requires the router to carry the governed set (typed-registry change) |
| dispatch arms are not checked against the governed set | a `match` arm with no builder entry is ungovernable and fails open | a `match` cannot be enumerated at runtime; the fix is routing dispatch through the builder table |

Recorded, needing no action: a backend tool surfaced under `surfaced_tools` is
unaffected by a non-empty `exposed_meta_tools` — surfaced names are not in the
governed set.

## Not in this release

No new capability backends. No change to the Meta-MCP tool count, the
context-savings benchmark, or `benchmarks/public_claims.json`. No change to the
licensing split.

## Upgrade notes

**Breaking for operators who set `exposed_meta_tools` and relied on it being
inert.** Any deployment that set the field expecting no effect will now have
meta-tools hidden and refused. Deployments that never set it are unchanged —
an absent or empty list exposes everything, as before.
