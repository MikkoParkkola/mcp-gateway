- **`init` no longer writes the admin token into the config.** `mcp-gateway init` now stores the generated admin token in the store chosen by `secrets.store` and writes only a reference into `auth.bearer_token`, so the config file and its samples hold no secret. See UPGRADING-4.0 and the QUICKSTART section on reading the token back. (MIK-9430)
  Affects: configs created by `init` on 4.0.0 pre-releases, which hold the token as plaintext; 3.x unaffected. Operator action: none for a new `init`; to move an existing literal `auth.bearer_token`, set it to `env:MCP_GATEWAY_TOKEN` or re-run the store step, and rotate the token if the old config was shared or committed.
