- **A repeated task call and `tasks/get` are checked against current policy.** A task-augmented `tools/call` repeated with the same idempotency key and body, and `tasks/get` on a finished task, used to return the stored result without the invocation policy (identity grants, attestation, kill switch, capability disable, profile, withheld tools). Both now re-check the calls that produced the result first; a fresh task is still checked by its worker. Task records name those calls (record version 5); see `docs/UPGRADING-4.0.md` item 105 for rollback. (#2450)
  Affects: 4.0.0 pre-releases only; 3.x unaffected. Operator action: back up `tasks.store_dir` before upgrading if a rollback to a pre-release may be needed.
