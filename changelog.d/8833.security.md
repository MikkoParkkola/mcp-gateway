- **Backend upstream events on identity-bound backends are observed per subscriber.** A backend reached with a propagated identity (`signed_assertion`, `token_exchange`, `passthrough`) or a managed or external account used to refuse `backend.<name>` resource and prompt events (`-32014 identity_propagation`), because one shared listener would have observed under the gateway's credential and could have sent one user's changes to another. Each subscriber now gets a listener of their own: every request it sends carries that subscriber's credential (minted through the audited path, or their own passthrough token) and none of the gateway's, and each change reaches only the subscribers it was observed for. Queued deliveries made under a different grant, identity configuration or lease are buried, never sent. A passthrough token is held in memory only, zeroized on every end of its subscription, and only where core dumps can be disabled. (MIK-8833, MIK-8834)
  Affects: 4.0.0 pre-releases with MCP Events on a backend with `identity_propagation` or a `personal_managed` / `external` account; such subscriptions were refused there, so nothing was exposed. Operator action: none for most backends; on a `passthrough` backend, subscribers send `events/lease`, and the host should run encrypted swap or none (`doctor` warns).
