- **The web UI's backend add, remove and update now write gateway.yaml through the audited config writer.** On a gateway with an audit log, each one records a `config_backend_intent` event (with `operation` and `backend`, never a value) before the file changes, and a refused append writes nothing and answers 500. A crashed write's journal found by a backend route is recovered only after its `config_recovery_intent`. With auth on and no audit log, the routes answer 503 `audit_log_required`. A reload that refuses the new bytes now puts the old file back (it used to leave the file written and answer 500 "Config written but reload failed"). An edit that changes nothing still reloads, and on an audited gateway it now records its intent first; a refused append stops that reload. With no gateway.yaml, the routes, like discovery adopt, answer 409 `no_config_file` with a message naming `mcp-gateway init --profile local`. With no config reload running they answer 503 and write nothing. Write failures answer fixed text that quotes nothing from the file. (MIK-9230)
- **The older in-process write calls refuse on an audited gateway.** `ReloadContext::mutate_and_reload_outcome`, `write_and_reload_outcome` (and their `_within` forms) and `mutate_config_and_reload` with a reload context refuse before taking any lock when the gateway has an audit log or auth on, because they record no intent. (MIK-9230)
- **A crashed config write's manual recovery step no longer says to copy the staged original over gateway.yaml unconditionally.** It says to inspect the journal first, restore the staged original only if its SHA-256 matches the journal's `original_revision`, and for an `all_renamed` journal only delete the journal. (MIK-9230)
