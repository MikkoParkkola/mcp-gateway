- **The capability editor refuses a literal credential in a credential header.** Saving or validating a capability through the web UI now refuses a credential-named header (`Authorization`, `Proxy-Authorization`, `Cookie`, `x-api-key` and the like) whose value is not a reference: only `{env.NAME}`, `{keychain.NAME}`, `{oauth.NAME}` or a declared input with nothing baked into the file (no `static_params` entry, no default, no enum, const or examples), optionally after one scheme word such as `Bearer`, is accepted. A literal, a duplicate or colliding key, or a text the loader cannot parse is refused with the header's field path or a fixed message with the line and column, and the answer never carries the submitted bytes. Other headers are untouched. (MIK-9351)
