- **`audit verify` without a key can no longer pass signed records written during the run.** Without a shared secret, `audit verify` refuses a signed log, so a signed log is never passed with its signatures unchecked. It decided that from a first read of the log, then verified in a second read; a signed record written between the two was checked by hash only, and the run exited 0. The verifying read now notes every signature it parses, and a keyless run that saw one is refused with the same message, whatever the first read found. A run verifies the records its read reached; a record appended after that read is for the next run. A keyless run whose chain also failed keeps its failure report, with a note that signatures went unchecked. Library callers of `verify_audit_log` get the new `VerifyResult::signed_entry_seen` field, and a keyless caller should refuse on it as the command does; hash-only verification itself is unchanged. Code that builds a `VerifyResult` with a full struct literal needs `..Default::default()`. (MIK-9060)
  Affects: keyless `audit verify` on a live, signed log. Operator action: none. A keyless run racing a signed append now exits 1 where it exited 0; the same run with the signed record written a moment earlier was already refused.
