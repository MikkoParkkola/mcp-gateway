- **A direct backend request that answers "not found" now counts as its session's activity.** On `/mcp/{name}`, the caller's own session (`mcp-session-id`, counted only for its owner) is now read before the backend lookup, so the call is judged and routed under that session's routing profile. A request whose backend name is unregistered or hidden from the caller now resets the session's idle timer and adopts a provisional session, as a request to a present backend already did; before, it was answered before the session was read and did neither. A session kept alive only by such requests is reaped later than before.
  Affects: 4.0.0 pre-release builds; 3.x never counted a `/mcp/{name}` request as session activity. Operator action: none.
