- **An open `list_changed` stream ends when its agent, certificate or proxy no longer holds.** A
  `GET /mcp` stream or `subscriptions/listen` judged each notification by the identity it was
  opened under. An OAuth agent narrowed in the registry was still told about tools it can no
  longer see, and a stream kept its view after its client certificate's `notAfter` passed. Each
  notification now re-checks that identity. The agent's current registry scopes decide what it is
  told. The stream closes when its bearer validates as a different agent (or as an agent where the
  stream had none), when the certificate's `notAfter` has passed or the clock cannot be read, or
  when the proxy its identity headers came through is no longer trusted. A stream that is already
  dead when it opens is refused as an invalid credential is. Each closure counts once in
  `mcp_view_liveness_dead_total{reason="agent"|"cert"|"proxy"}`. A revoked certificate is still
  checked only at the TLS handshake (see docs/DEPLOYMENT.md). (MIK-8377)
  Affects: deployments with OAuth agent auth, mTLS client certificates or `trusted_proxy` caller
  identity. Operator action: none.
