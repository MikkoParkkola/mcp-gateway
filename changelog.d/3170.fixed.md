- **A retry after a lost round is told the outcome is uncertain.** When a dispatched call's request may have reached the backend and no answer came back (a transport failure, a timeout, or a config reload stopping the backend mid-call), a same-key retry was served the original error, as if the work had failed. It now gets the uncertain-outcome notice under the first caller's error code; the work still never runs twice. An answered error (a JSON-RPC error, or an HTTP 4xx refusal other than 400, 401, 403, 404, 407, 408 and 429) is served as before. A backend that could not take the request (`BackendUnavailable`, a tool-list timeout, a stdio backend with no writer) is now a pre-send refusal that frees the key, so the retry runs. See ADR-012 and `docs/UPGRADING-4.0.md`. (#3170)
