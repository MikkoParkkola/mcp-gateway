- **Shipped deploy files bind through `MCP_GATEWAY_SERVER__HOST`, not the hidden global host flag.** The Helm chart, the Kubernetes enterprise-alpha base, the single-node compose file, systemd unit and launchd plist, and the Dockerfile usage comment set the same bind address through the environment variable, which overrides the config file's `server.host` as the flag did, so every install binds where it did before. A new release check fails CI when a user doc, example or deploy file passes a hidden CLI command or flag, or names a hidden variable or config key in a deploy file. One difference: on a host that sets the hidden `MCP_GATEWAY_HOST` (for example in a systemd `EnvironmentFile` or with `launchctl setenv`), the shipped templates no longer override it, so that address now applies.
