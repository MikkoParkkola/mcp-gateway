- **No remaining runtime clock read stops the gateway on a host clock before 1970; library calls that need a time return `Result`.** Firewall audit rows (request, response and dispatch) and transparency-log segment open records are written undated (`timestamp: null` with `clock_invalid: true`; `segment_opened_at: null`, and an undated segment rotates by size only), where a dispatch row used to carry the epoch. A personal-account dispatch and an identity-grant change are refused before anything moves, and the CLI's `identity grants` and `trust lab` commands exit non-zero naming the clock. `Task::create`, `Task::complete(&Value)` and `Task::fail(&JsonRpcError)` return `Result` (the outcome is passed by reference, so a refused call loses nothing), `TaskModelError` is `#[non_exhaustive]` with `ClockUnreadable`, `complete` with a non-object result now returns `Err(InvalidInput)`, `CatalogTrustLab::evaluate_card` returns `crate::Result`, and `EraObservation::from_outcome` takes `Option<DateTime<Utc>>`. Affects 4.0.0 pre-releases only (MIK-8202).
