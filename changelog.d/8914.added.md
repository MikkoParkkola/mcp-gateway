- **Every audit record says which check decided the call.** Each invocation and refusal record in the transparency log now carries a `decision` object, covered by the entry hash and signature: the configuration revision in force when the record was written (a keyed digest of the applied config, grants file, env files and the values the load consumed; capabilities are not yet included), the running revision and any fields waiting on a restart, and the kind of check that allowed or refused the call (firewall, tool policy, backend scope, grant, cost budget, response gate and the rest). A refusal whose check is not yet named records `unrecorded`, never an allow. Older records without the object still verify. (MIK-8914)
