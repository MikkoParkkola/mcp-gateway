- **A sign-in a request started stays open after that request gives up.** When an OAuth backend's token lapsed during a request with its own short deadline (a tool-list fill, a warm start, or a task-recovery query), the browser sign-in that request opened was abandoned with it. Approving it then did nothing, and the next request opened a second browser tab. The sign-in now runs on its own: approving it stores the token, the next request uses it, and callers that retry share the same sign-in. A restart or stop still ends it at once, and every stage of the sign-in (waiting for the client, registration, the browser, the code exchange, saving the token) ends at one shared deadline, so delays can no longer add up.
