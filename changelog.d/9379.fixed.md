- **Relay detection tracks a plan task's stored result from the moment it is readable.** The relay replay snapshot of a completed plan or multi-target task is now written with the result itself, in the same task-store write, so a `tasks/get` or a task notification can no longer read the result before its snapshot exists. The snapshot is kept in memory only once a read delivers it: a read under `off` leaves nothing behind, any other action keeps it. A snapshot made by another gateway process cannot be matched by this one; a read of such a result is refused under `block` (`-32002`), and delivered, counted and audited under `observe`. (MIK-9379)
