- **The web UI's policies read says which settings a save can change.** `GET /ui/api/policies` now serves the two request checks (input sanitizing and SSRF protection) as in force, in every build. Every setting carries `read_only`, true unless the settings save can change it, taken from the save's own list of fields. Under the hardened posture SSRF protection is marked as held by the posture and read-only, since the posture turns it on at load whatever the file says. The tool policy's `enabled`, `default_action` and `use_default_deny` become setting objects with their paths, and the relay section's section-wide `read_only` is gone. This route is the bundled UI's private API.
