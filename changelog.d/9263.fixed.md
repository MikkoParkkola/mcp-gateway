- **Admin API: a refused policy write names where policy is set.** `POST /ui/api/control-plane/policies`, and a policy decision on `/ui/api/control-plane/decisions`, still answer 409 `policies_managed_in_gateway_config`; the reason now names every gateway config key that holds policy (`security.tool_policy`, `security.firewall.rules`, `security.firewall.credential_redaction`, `security.firewall.collusion`, `security.sanitize_input`, `security.ssrf_protection`) instead of only the last two. A policy write no longer answers 503 when the control-plane store is unavailable: that store never enforces policy, so the answer is the same 409 (or 403 for a non-admin) either way. Grant writes are unchanged. (MIK-9263)
