- **The `-full` image trusts only the pinned NodeSource key.** The image installs Node.js from NodeSource's apt repository through a key file it downloads at build time, and checks that file against a pinned fingerprint. That check had two gaps. It matched the fingerprint against any key record, so a file whose one primary key was some other key, carrying NodeSource's key as a subkey, passed. And apt trusted every key in the file, including a primary key with no user ID, which `gpg --show-keys` does not list. The check now requires exactly one primary key whose own fingerprint is the pin, and apt's `Signed-By` names that fingerprint, so apt selects that key and its subkeys alone. Exploiting either gap needed control of the HTTPS key download at build time. (MIK-8837)
  Affects: the `-full` image of 4.0.0-beta.1, beta.2 and beta.3, as built; a published image is affected only if its build fetched a substituted key file. Operator action: none; the next `-full` image carries the fix.
