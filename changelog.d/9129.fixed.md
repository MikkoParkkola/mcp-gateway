- **A per-user credential refusal is answered as a refusal on every route.** When a per-user backend refuses a call because the caller brought no credential, or because the credential failed its check at the send, `gateway_invoke` answered with an ordinary error result that called the problem a transient backend error and suggested retrying. It now answers with the same -32001 refusal the direct `/mcp/{name}` route gives, with no retry hint, and records the call as refused. The same refusal during the first listing of a backend's tools is no longer reported as an unreadable schema. Repeated refusals no longer count against the backend's error budget, so they can no longer trip the kill switch for every user. A client that read this refusal from an `isError` result on the meta-tools now gets a JSON-RPC error -32001 instead; see the upgrade guide. Affects gateways with per-user backends only. (MIK-9129)
