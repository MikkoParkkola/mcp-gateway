- **A client certificate that names no one is never a certificate identity.** `CertIdentity::from_der` now answers `None` for a certificate that parses but has no SAN URI and no CN, and is crate-private: it is reached only from the TLS acceptor's verified peer chain. The TLS identity layer still refuses such a certificate exactly as before (401, JSON-RPC -32000, before any route runs, `/health` included); it is never treated as "no certificate". (MIK-9206)
  Affects: library users of `CertIdentity::from_der`; mTLS deployments see no behaviour change.
  Operator action: none.
