- **A refusal's decision record names the rule that made it.** Firewall and tool-policy refusals now record a stable `rule_id`: the rule's kind and an HMAC of its configured definition under a key derived from the record key. The same rule keeps its id across restarts and reloads, an edited rule gets a new one, and a reader of the log cannot test guesses about a short rule. A block that no configured rule decided (a severity default, anomaly, tenant, budget or relay check) records its kind without a rule id. A stored task read that a check refuses (on `tasks/get`, or a task-status notification whose stored output is withheld) now names that check in its delivery record's `refused_by`: the kind, and the rule id when a configured rule decided. A stored result no longer served under the bindings that produced it is refused under the new kind `provenance`. The id is never sent to the refused caller. (MIK-9191)
