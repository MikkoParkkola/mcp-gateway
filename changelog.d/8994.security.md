- **A required identity binding's per-user sessions send only each user's own credential.** For a backend whose identity binding is required (`identity_propagation.required: true`, any session mode), a user's own session started with only the backend's static headers: its connect, `server/discover`, `initialize` and `notifications/initialized` reached the backend with no user's credential, or with a gateway-level one if a static header carried it, and its calls carried the static headers beside the user's credential. Every request on such a session now carries only the calling user's credential, never a static header or a gateway token; a request with no user in flight is not sent (no session `DELETE` on close, no late cancel notification), and a call carrying no credential is refused. Startup warns, per backend, naming each static header these sessions now leave off. A backend with an optional binding is unchanged. (MIK-8994)
  Affects: every gateway with a backend whose identity binding is required. Operator action: none unless such a backend needs a static header on per-user requests; see the startup warning and UPGRADING.
