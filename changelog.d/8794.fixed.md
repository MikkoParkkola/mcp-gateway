- Redacting a tool answer twice now changes nothing. Inside text that continues a connection string (`postgres://`, `mysql://`, `mongodb://`, `redis://`), a redacted span that held whitespace or was shorter than the marker is written with one leading space (` [REDACTED:credential]`), and a renamed key's collision counter is written ` #n`, so a second pass, such as a dead-letter event replay, no longer redacts the first pass's output again. All other redacted text is unchanged. A replayed event whose stored body was already redacted is recorded as `redacted`, not `pass`. (MIK-8794)
