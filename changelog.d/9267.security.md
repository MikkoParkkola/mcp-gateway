- **Relay detection records an answer when it is actually sent, under the settings in force then.** A result's relay receipts used to record when the answer was ready, before it was written. If relay detection went from `off` to `block` while an answer waited (a full stdio output queue, or an HTTP body not yet read), that answer was never recorded, and a later relay of its text by another caller was allowed. Receipts now record when stdout takes the frame (each batch item included), and on HTTP, the direct route and request-scoped streams when the server takes the body's first chunk. An answer never written records nothing. The setting at the write decides: `off` then records nothing, even for an answer prepared under `block`. A batch item is no longer excused by an earlier item of the same batch, because a client writes every item of a batch before it sees any answer. A retained answer's replay snapshot is now taken before the answer can be replayed, and it is kept or dropped by the setting at each write, so a replay delivered under `block` records even when the original was prepared under `off`. Task results are unchanged. (MIK-9267)
