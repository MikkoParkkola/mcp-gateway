- **Legacy SSE backends that answer on the stream now work.** A backend on the MCP 2024-11-05 HTTP+SSE transport answers each POST `202 Accepted` and sends the JSON-RPC response on its SSE stream, as the official SDKs' SSE servers do. The gateway read answers only from the POST body, so such a backend failed at `initialize` and never started. The gateway now keeps the SSE stream open and pairs each response with its request by id. A body answer is still used when a backend sends one. When the stream ends, waiting calls fail at once and the next call reconnects first; no call is sent twice. (MIK-8835)
