- **A credential's backend list now bounds what it reads in the web UI's Activity and status.** A key scoped to some backends read every backend's calls in Activity (list, export and receipts) when its identity mapped to an Auditor or Admin role, or when it was an admin key, and every non-admin caller's status counts covered every backend. Activity now shows a scoped key only calls on its backends, within what its role allows, and no gateway-wide audit rows (grant and policy changes, admin actions); a receipt it may not read answers as a missing one. Status counts only its backends, and the full status view needs an unscoped admin. An admin key with a list naming some backends no longer sees every backend in the control-plane snapshot, can no longer mint a dashboard link (a session is unscoped), and a session it minted ends on the reload that narrows it. A scoped key's control-plane snapshot shows no identity grants, local policies, store audit events or shadow-radar discoveries, and its counts, coverage and decision queue cover only what it is shown. An admin key with an empty list stays a UI-wide admin that calls no backend. See UPGRADING.
  Affects: 4.0.0 pre-release builds, which judged Activity, status and dashboard links by the admin flag and role alone. Operator action: an admin key meant to administer the whole gateway sets `backends: ["*"]`; read the full audit trail with an unscoped key.
