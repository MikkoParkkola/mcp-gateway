- The web UI's server list says what state each server is in and why: `running`, `paused` (failing, retrying on its own, with `next_retry_at`), `dormant`, `unhealthy`, `refused` (its runtime policy denies it), or `needs_sign_in`, with a one-line `reason` built from counts, never from a server's error text. `GET /ui/api/refusals` (admin only) lists what the gateway refused to apply: a server its runtime policy denies, a refused config reload, a refused add or edit, each with a stable cause code and a fix; causes are rebuilt from fixed wording, so a refused value is never repeated back. A server whose credentials go over plain `http://` because `allow_cleartext_credentials` is set is marked `cleartext_credentials_accepted`, and the gateway writes an audit record when such an override takes effect or ends, at start and on every reload, in HTTP and stdio mode alike. Existing `/ui/api/status` fields are unchanged. (MIK-8857)
