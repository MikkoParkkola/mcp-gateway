- **Config history and restore in the web UI's API.** `GET /ui/api/config/history` (admin only) lists the kept config versions and reload events, newest first, marks the version the gateway serves, and never returns a stored byte or diff. `POST /ui/api/config/restore` with `{"version": "<revision>"}` writes that version's gateway.yaml back byte for byte through the audited config writer, keeps the file it replaced as `gateway.yaml.<time>.rejected`, and lists the env files and grants a restore never writes. A CLI key, or a session a CLI key started, cannot restore. On a gateway with an audit log the restore is recorded before gateway.yaml changes, and a failed record refuses it with the file untouched.
