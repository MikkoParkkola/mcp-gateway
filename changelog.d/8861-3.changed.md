- **`auth.api_keys` applies on reload.** A key added, removed, edited or expired by a config reload is judged by the next request, and a dashboard link or session opened with that key by its next use; a request in flight keeps the table it started with, and spent rate-limit usage carries over. A reload whose keys would change multi-user status, collide with the running bearer, or name an unresolvable secret reference is refused whole, on stdio too, and the running keys stay in force. Every other `auth` setting still needs a restart. (MIK-8861)
