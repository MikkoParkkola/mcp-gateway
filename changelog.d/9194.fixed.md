- **A capability changed while the gateway was down now reaches the open decisions.** A capability file whose bytes no longer match its own `sha256:` pin was skipped at startup without a record, so it never appeared as a `capability_changed` decision until it changed again while the gateway ran. Startup, on HTTP and stdio, now checks every configured capability directory for pin mismatches before it reports ready, and a directory that fails to load is still checked. While that startup check runs, a file edit's reload waits for it (logging a warning if it waits long), and the admin capability reload answers a retryable error (-32000) instead of running beside it. (MIK-9194)
