- **The capability response cache is bounded.** It kept every response whose key was never read again for as long as the gateway ran; it now holds at most 10 000 entries (briefly exceeded by up to the number of concurrent writers, until the next store evicts back), evicting expired entries first and then the oldest. Each cache has its own bound: `cache.max_entries` still bounds only the Meta-MCP response cache, not this one (MIK-8740 will make it govern both). Which capability responses are cached, their TTL and their key are unchanged; the two caches now use the same cache code.
