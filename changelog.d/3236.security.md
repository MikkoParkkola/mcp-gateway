- **A key-server caller can no longer share a configured credential's identity.** A caller signed in through the key server, with an `/auth/token` token or a delegated OIDC bearer, was identified by the first 48 bits of a SHA-256 digest, the same space configured API keys and the bearer token use, so an API key configured by digest could carry an OIDC user's principal. These callers now get `kst:` or `oidc:` followed by a full SHA-256 digest, which no configured principal can equal. See UPGRADING-4.0 item 154. (#3236)
  Affects: 3.5.0, 3.5.1 and the 4.0.0 pre-releases with the key server enabled. Operator action: update any log or audit query that matched a key-server caller's 12-hex principal.
