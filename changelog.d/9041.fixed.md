- **A Windows lock no longer fails with "Access is denied" while another handle releases its old file.** When a lock file that was not owner-only is replaced, and some other handle (an indexer or antivirus scan) still has the old file open, Windows keeps its name pending deletion for a moment, and a new file cannot be created under that name. The lock read that moment as a hard error and gave up. It now waits it out, within the lock's usual bound, and takes the lock once the name is free. A folder this account cannot create files in is still refused at once, as before. (MIK-9041)
  Affects: Windows only. Operator action: none.
