- **A credential in a backend's command or URL is refused instead of written into gateway.yaml as text.** The web UI's backend add, update and add preview answer 422 by field (`secret_in_command`, `secret_in_url`), and `mcp-gateway add` exits 2, when the command or URL that would be saved holds a credential: userinfo in the URL, a query parameter or command flag named like a credential (`token`, `api_key`, `password`, `Authorization`), a `NAME=value` argument with such a name, or an `Authorization:` header argument, with a literal value of any length. Ordinary queries (`?transport=sse`), `${VAR}` text and secret references are saved as before. Give the credential as an env value instead (`-e NAME` or `--env-file` on the CLI, an env field in the web UI), which goes to the secret store; the gateway does not expand `${VAR}` inside a command or URL. `mcp-gateway add -e` now takes an environment variable name, never a value. (MIK-9352)
  Affects: every release before 4.0.0. Operator action: replace a credential written into a backend's command or URL with an env value or a header reference, and use `-e NAME` or `--env-file` in scripts that passed `-e NAME=value`.
