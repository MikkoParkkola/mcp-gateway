- **The config writer reads gateway.yaml through the same mode and owner check as every loader.** The web UI's config writer reread gateway.yaml with a plain read under its lock, then validated the bytes and wrote them back owner-only. If the file turned writable by another local account (group or world write) or came to be owned by one after the adopt route's own checked read, that account's edit was rewritten as a trusted owner-only file and loaded. The writer now refuses such a file before it records an intent, creates a secret entry or writes anything: the discovery adopt route answers 503 "gateway.yaml could not be loaded" with no path in the body, and a gateway.yaml removed at that point answers 409 `no_config_file` instead of a 500. (MIK-9299)
  Affects: an admin using the web UI discovery adopt route on a gateway whose gateway.yaml another local account can write or owns.
  Operator action: none for a gateway.yaml that is owner-only (chmod 600); if an adopt is refused this way, fix the file's mode or owner as the startup refusal for gateway.yaml describes and retry.
