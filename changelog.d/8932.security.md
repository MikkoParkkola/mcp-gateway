- **A firewall rule whose `match` glob does not parse no longer matches every tool.** The firewall compiled such a rule as `*`, so a typo like `exec_[` in an `allow` rule allowed every tool call whatever its scans found. With the firewall on, gateway.yaml now fails to load and the error names the rule's path, `security.firewall.rules[N].match`, not its text. A rule that reaches the firewall without the load (a program embedding it) blocks its finding types on every tool, whatever its action. (MIK-8932)
  Affects: every release since 2.6.0 with `security.firewall.enabled` on and a rule whose `match` is not a valid glob. Operator action: fix or remove the rule the startup error names.
