- **A subscription's stored identity is verified again when the events store reads it back.** A per-user event subscription keeps the identity its backend observes the subscriber as, and the events store reads that row back from disk on every start. It was read straight from the file, so a stored identity with an empty or blank issuer or subject loaded as an identity that names nobody. It now comes back only through the gateway's checked identity constructor: such a row observes as no one, gets no listener and no shared credential, has its queued deliveries cancelled, and is revoked at start with a warning naming its handle. `VerifiedIdentity` and `TemporaryToken` in the library's `key_server` module no longer implement `Deserialize`; nothing in the gateway reads either back. (#4629)
  Affects: unreleased 4.0.0 code only; no released version, 3.x or a 4.0.0 pre-release, stores per-subscriber identities. Library users who deserialized `VerifiedIdentity` or `TemporaryToken`, possible since 3.x, can no longer read either from bytes; they come only from the gateway's own verification. Operator action: none. A row revoked this way is logged at warn level with its handle; its subscriber subscribes again.
