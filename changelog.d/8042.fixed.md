- **Config writes to `gateway.yaml` no longer overwrite each other.** Web UI backend edits
  and every CLI write (`add`, `remove`, `setup`, `cap discover --write-config`, `init`,
  `upgrade`, `--force` included) load, edit and write the file under one config lock, so
  two writers, from one gateway or two, can no longer undo each other's change. The lock is
  a hidden `.gateway.yaml.lock` file next to the config, kept there on purpose. A CLI write
  that meets another writer's lock says `Waiting for ...` and continues once it is free; if
  it stays held for 30 seconds the command writes nothing and exits non-zero, asking you to
  retry. `init` keeps a config that appears after its own check, and a write whose text
  would not load is refused instead of saved.
