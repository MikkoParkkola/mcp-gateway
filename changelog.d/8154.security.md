- **Input sanitization runs once, on the whole request, before any check reads it, on every route.** Before, `/mcp` and stdio sanitized after some checks had already read the request, the direct route sanitized only the tool arguments and ignored `security.sanitize_input`, and `passthrough: true` exempted a backend on the direct route alone. Now `/mcp`, `/mcp/{name}`, stdio and task submits sanitize method, params and `_meta` at intake. The request `id` and the signing and chain nonces are validated, never rewritten. A call whose every backend target is passthrough is forwarded as sent on every route; a tool the caller cannot see is judged as absent, so a NUL probe cannot tell the two apart. (MIK-8154)
  Affects: deployments with `passthrough: true` backends, and clients of `/mcp/{name}`.
  Operator action: none, unless a passthrough backend relied on `/mcp` or stdio stripping control characters.
- **Tool arguments sent as a JSON string are sanitized too.** The step decodes them, sanitizes the object and re-encodes it, so a NUL escaped inside the string is refused instead of appearing when the call decodes it. The idempotency key and `gateway_invoke`'s argument nonce are validated like the other protocol fields: a NUL or a control character in them is refused. (MIK-8154)
  Affects: clients that send `arguments` as a JSON string.
  Operator action: none.
- **A call exempted from sanitization is refused if its passthrough backend, or its playbook, changes before it runs.** Intake records the backend instance and the playbook definition it judged the exemption on; a config reload in between answers "The backend changed after this call was admitted; retry the call" or "The playbook changed after this call was admitted; retry the call", and nothing is sent. (MIK-8154)
  Affects: deployments that reload config while passthrough calls are in flight.
  Operator action: none; clients retry.
- **A keyed `/mcp/{name}` call from a caller with no verified execution principal is refused -32003, as on `/mcp`.** Before, the direct route accepted it under its idempotency cache alone. (MIK-8154)
  Affects: clients that send idempotency keys to `/mcp/{name}` with no verified identity.
  Operator action: none.
