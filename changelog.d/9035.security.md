- **A backend can no longer echo a credential the gateway injected back to the client.** When a backend's `secrets:` rules inject a value into a call (as an argument, a header or a query parameter), anything that backend sends back is scrubbed of that value before the gateway parses, logs, retries, caches or stores it. That covers answers and errors, notifications, change-notice URIs, a WebSocket frame, a stdio line and an A2A reply. Each occurrence becomes `[redacted]`. Its percent-encoded form is matched too. Progress tokens, subscription tags and A2A task ids still route by what the backend sent; only the copy that leaves the gateway is scrubbed. A signed answer still verifies against the bytes the backend signed; a signed answer whose top-level key name is itself an injected value is refused, since no view of it is both scrubbed and what was signed. An answer whose `error.code` is the value, or one from a backend rotating values faster than the redaction grace allows, is replaced by a fixed refusal. Diagnostics name lengths and positions instead of quoting backend text. A rule value under 8 bytes logs one warning per rule at its first send. (MIK-9035)
  Affects: backends with `secrets:` rules. Operator action: none.
