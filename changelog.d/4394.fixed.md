- **A re-admitted playbook task now refuses a playbook reloaded before it runs, as a synchronous call does.** A task submitted while input sanitizing was off, whose worker ran after a reload turned sanitizing on, is re-checked before it runs. For a playbook call that is not sanitize-exempt, that check recorded the playbook's definition and then dropped it, so a playbook reloaded between the check and the run ran its new definition. The run now compares against the definition the check judged and refuses a changed one, with "The playbook changed after this call was admitted; retry the call". Its arguments were sanitized either way. (MIK-8956)
  Affects: tasks running `gateway_run_playbook`. Operator action: none.
