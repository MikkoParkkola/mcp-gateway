- **Cancelling a task now cancels its upstream task.** When a task's backend accepted the call as an upstream task (`tasks.recovery_adapters`), the owner's `tasks/cancel` sends that backend one `tasks/cancel` naming the backend's own task id, through the trusted recovery adapter. It is sent once per task, best effort; a cancel that lands before the backend's reply arrived can only close the stream, and a gateway stopped between the claim and the send leaves the upstream task running (MIK-8267). Task records of such a cancel are written as version 7: back up `tasks.store_dir` before rolling back to a beta (#3718).
