- **`cap import --auth-key` takes only a credential reference.** The value must be one of the forms the gateway resolves (`env:NAME`, `keychain:NAME`, `oauth:PROVIDER`, `file:PATH`, `{env.NAME}` or a variable `NAME`), checked by the same parser the resolver uses. Anything else is refused with exit 2 before anything is written, and the refusal never repeats the value. Before, the value was written into the capability's YAML as given, so a secret typed there landed on disk in plain text and the capability then failed to resolve it.
  Affects: 3.5.2 and the 4.0.0 pre-releases. Operator action: none for a script that passes a reference; one that passes the secret itself should export it and pass `env:NAME`, then check capability YAML written before for a plain secret in `auth.key`.
