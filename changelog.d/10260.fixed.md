- **An unsubscribe answers success only once the removal is on disk.** When the directory sync after
  deleting a subscription's file failed, the gateway logged a warning and answered `{}`; a power cut
  before the directory reached disk could bring the subscription back and resume deliveries to its
  callback. A failed sync is now an internal error, the subscription stays live, and the next
  unsubscribe finishes the removal. A backend's withdraw and a revoke keep the row the same way and
  retry. The events store also syncs its subscription directory when it opens; a sync that fails there
  stops gateway startup with the directory named, as any other events store error at open does.
