- **The tls commands no longer replace an existing certificate or key.** Running `tls init-ca` again into the same `--out` used to overwrite `ca.key`, so the old CA key was lost and every certificate it had issued stopped verifying; `tls issue-client --cn ca` into the CA's directory did the same. `tls init-ca`, `tls issue-server` and `tls issue-client` now stop before generating or reading any key when anything is already at `<stem>.crt` or `<stem>.key` (a file, a directory or a symlink, even a dangling one), or when that cannot be checked, and they write nothing. The error names the path and says to remove it first or choose a different `--out`. The check runs when the command starts: anything that creates these files while it runs, another tls command or any other process, can still race; the rerun case is closed.
