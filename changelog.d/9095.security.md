- idempotency: a call refused inside its backend's own send, before any byte leaves (a secret rule that cannot be applied, a withheld tool, a credential the slot needs and the call lacks, a failed slot start, an open circuit, a full slot), is recorded as refused before its backend: its delivery record says refused, its idempotency key is released so a same-key retry runs, a task stores the gateway as its error's author and a plan notes no relay replay call for it. A key is released only when the delivery provably sent nothing: a call whose earlier round or step already reached the backend keeps its key, including a bridged retry refused before its send, a bridged exchange that ends in an error or is dropped (a deadline, a spent budget, a relay refusal, a legacy call dropped while the gateway asks the client) and an HTTP resend after an expired session that never connected. A same-key retry of such a call is answered with the may-have-run notice instead of running again
  Affects: 3.x up to 3.5.1 for the HTTP resend after an expired session (3.5.1 released the key on every failed call); no released version for the other cases. Operator action: none.
