- **A backend that refuses a credential with HTTP 401 or 403 gets the managed-account refresh, whatever its body says.** A backend that answered 401 with a JSON-RPC error body was read by the body, so a managed account got neither the forced refresh nor the reconnect offer. The status now decides; the caller sees the status rather than the backend's own error text, as for a plain-text 401. A 401 saying the session expired still re-initializes the session, and a plain-text "session expired" now does too. A backend's own JSON-RPC error that happens to use code 401 is no longer read as a credential refusal; a CLI capability's refusal still is.
  (MIK-7717, MIK-7926)
