- **A non-ASCII `agent_id` query parameter now decodes as UTF-8.** The query-string
  label decoded each byte as a separate character, so `agent_id=caf%C3%A9`, and a
  raw `café`, became `cafÃ©` and did not match the same id sent in the `x-agent-id`
  header or listed in the allowlist. It now decodes as UTF-8; a value that is not
  valid UTF-8 yields no declared label, as an unreadable header already did. `+` and
  a malformed `%` escape still stay literal. (MIK-8498)
  Affects: clients sending a non-ASCII agent id in the query string.
  Operator action: none; an allowlist entry written in the garbled form (`cafÃ©`)
  should be corrected to the real id.
