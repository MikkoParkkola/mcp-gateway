- **Per-client rate limits and circuit breakers belong to the credential, not its
  display name.** Each API key keeps its own configured `rate_limit` and its own
  client circuit breaker even when another identity carries the same name: another
  API key (possible only where a config skips load validation, which refuses
  duplicate and empty key names), the static bearer (`bearer`), the dashboard session,
  or an OIDC identity. Two key-server tokens for one OIDC identity still share one
  bucket and one breaker. A dashboard link's session expiry is taken from the key that
  authenticated the request, matched by credential. Reported in GHSA-mvjf-g2ff-vvf5.
  (MIK-8489)
  Affects: gateways with `auth.api_keys` entries that set `rate_limit`, or that enable
  `auth.client_circuit_breaker`.
  Operator action: none; upgrade to this release.
