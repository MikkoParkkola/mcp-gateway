- The grant-change journal and its lock now follow the grant file's real path, so a gateway and the `identity grants` CLI that spell one grant file two ways (a symlink, relative against absolute) share them: CLI changes are recorded as `add`/`replace`/`revoke` instead of `out_of_band`, and the two sides lock each other out. A CLI change made through a symlinked grant path now edits the file it points at and keeps the link, including the first change through a link whose target does not exist yet. (MIK-7715, #3055)
  Affects: the 4.0.0 pre-releases. Operator action: none. A gateway whose grant path spelling differed from the CLI's reads the CLI's journal for the first time after upgrading, and records its earlier entries once, beside the `out_of_band` records already made for them. A journal an earlier pre-release kept beside a symlinked spelling of the grant path is moved beside the real file on the first locked read or change, or copied there when the two are on different filesystems. A symlink chain that never resolves is refused instead of being replaced by a file.
