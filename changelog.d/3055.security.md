- The grant-change journal and its lock now follow the grant file's real path, so a gateway and the `identity grants` CLI that spell one grant file two ways (a symlink, relative against absolute) share them: CLI changes are recorded as `add`/`replace`/`revoke` instead of `out_of_band`, and the two sides lock each other out. A CLI change made through a symlinked grant path now edits the file it points at and keeps the link, including the first change through a link whose target does not exist yet. (MIK-7715, #3055)
  Affects: the 4.0.0 pre-releases. Operator action: none. A gateway whose grant path spelling differed from the CLI's reads the CLI's journal for the first time after upgrading, and records its earlier entries once, beside the `out_of_band` records already made for them. A journal kept beside a symlinked or relative spelling of the grant path stays on disk but is no longer read or appended to; a CLI change recorded only there before the upgrade, and not yet reloaded by the gateway, is recorded as `out_of_band`.
