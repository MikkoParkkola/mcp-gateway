- **A backend's error text is screened like its results.** A JSON-RPC error a backend returned
  on the per-backend route (`/mcp/{name}`), whether answered or as a failed dispatch, reached the
  caller verbatim, and a followed task's failure skipped the configured response firewall. Every
  backend error now passes the same content inspection, context integrity and response firewall
  as a result, through one shared screen: a block answers with the firewall's refusal, a
  redaction is delivered redacted, and a screened answer is what an idempotent retry replays. An
  account-refusal marker is honoured only on an error the screen passes, and backend failure
  logs carry the error code instead of the backend's text (MIK-8139).
  Affects: 4.0.0 pre-releases and 3.x, per-backend route and upstream tasks. Operator action:
  none; an error a firewall rule refuses now arrives as the firewall's refusal.
