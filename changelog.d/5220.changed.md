- **`api` saves and validates a capability's YAML.** A PUT to `/ui/api/capabilities/NAME` (with or without `?validate=1`) and a POST to `/ui/api/capabilities/NAME/validate` now send the `--data` body unchanged as `application/x-yaml`, the type the web console sends. Every other route still requires JSON, and its refusal now says which routes take YAML.
  Affects: scripts that sent a JSON body to a capability's save or validate route. Those bytes now go out unchanged as YAML, which the gateway reads the same way. Operator action: none.
