- MCP Events: a webhook subscription whose event type a capability reload no longer offers, or no longer fully serves (a filter key or payload field it relies on is gone), is now held instead of deleted. A held subscription receives nothing, its queued records still drain, and it resumes on its own when the route serves it again; otherwise it ends at its lease or at the configured maximum lifetime from when it was first held. A refresh of a held subscription is accepted and answers `held` with the reason, the key and when it ends. The cap refusal lists the caller's held types, and `GET /ui/api/events/held` (admin) lists held subscriptions per type. The 30-second withdraw grace pass and its test environment variable are gone. (MIK-8057, MIK-8076)
  Affects: 4.0.0 pre-releases only; 3.x has no MCP Events. Operator action: none.
