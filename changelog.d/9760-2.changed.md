- **Strict keys in capability files; `weather` takes coordinates; MusicBrainz is paced.** A capability file whose top level, a provider, or a provider's `rate_limit` carries a key no field reads now fails to load, naming the file, the key and the nearest valid key; `metadata`, a provider's `config`, and keys starting `_` or `x-` stay free. `weather` no longer takes `location`: `latitude` and `longitude` are required (look a place up with `geocode` first), its output schema is Open-Meteo's real response, it credits Open-Meteo, and it is paced at one request per 250 ms. `musicbrainz_search` is now paced at one request per second and no longer retried automatically; its old `metadata.rate_limit` note is gone. A GraphQL or JSON-RPC provider on a host another provider paces fails to load, or is unloaded when a later load or registration paces its host, and a call to such a host is refused.
  Affects: 4.0.0 pre-releases and earlier. Operator action: run `mcp-gateway cap validate` over your own capability files before upgrading and fix any key it names; callers of `weather` pass coordinates instead of `location`.
