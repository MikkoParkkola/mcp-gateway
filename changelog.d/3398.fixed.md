- **A damaged task record can no longer let a retried call run twice.** When a stored task's idempotency key cannot be read unambiguously, the gateway now refuses every new keyed call with code 409 and a message that says such calls are paused until the record is repaired or removed. Before, such a row released its key, so a client retry was admitted as new work and its backend ran again. Keys already held and unkeyed calls work as before. The refusal lifts on its own: the expiry sweep reads the row again and clears it without a restart. A repaired row keeps its key, so its retry never runs again; restart to read a repaired task. Removing the file releases the key, so a retry of that call runs again. While it holds, the log names each file on every sweep, `mcp_task_store_skipped_records{class="sealed"}` counts the rows, `/health` reads `degraded` (`/livez` and `/readyz` are unaffected), and the admin `/health` view names each file by full path with the action that clears it. A record-named FIFO in the task store is now refused as unsafe instead of hanging startup. (#3398)
