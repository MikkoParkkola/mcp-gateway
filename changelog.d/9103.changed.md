- **A same-key call while a backend's question waits for its answer is answered "in progress".** When a backend answers a `tools/call` by asking the client a question, the call's idempotency key is now held for that question's continuation instead of freed: a fresh call with the same key that does not present the continuation's `requestState` is answered "Duplicate request in progress" and does not run the tool again; the continuation that presents it runs. If the continuation is not used before it expires (300 s), the key answers the may-have-run notice. A question the gateway cannot hand back as a continuation (an anonymous caller, a question the client did not declare it can answer, a round a response gate replaced, a mint refused for want of a slot) keeps the key as may-have-run too: a same-key retry gets the notice, and a rerun needs a new key. This reverses two earlier releases of the key: a legacy exchange that minted a continuation (no session channel, or a bridged exchange that ran out of rounds), and a question refused as undeclared (`-32021`). Affects 4.0.0 pre-releases only.
