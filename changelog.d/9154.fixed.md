- **A task read answers the per-user lender's refusal as that refusal, not as a retry.** When a stored task's read had to fill the caller's own catalogue on a per-user backend and that backend's lender refused the caller (a required binding whose credential mint gave the caller none), `tasks/get` answered `-32603` "temporarily unavailable, retry" with `retryable` and `retry_after_ms`, so a client retried a call the gateway refuses every time. It now answers what the direct and meta routes answer for the same refusal: `-32001` with the lender's message and no retry hint. The refusal is kept only for that fill's retry window; a read after it asks the lender again. Any other failed fill (a backend error, a timeout, a fill still running for another reader) is answered as retryable, as before.
