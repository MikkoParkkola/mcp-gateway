- **The protocol-revision measurement window is per transport and restart-safe for HTTP.** A new setting, `server.protocol_revision_window: off | record`, defaults to `off`, which changes nothing. With `record`, each HTTP `serve` process opens its own segment in `protocol-revision-telemetry/window.json` before it serves, updates it every 5 s and seals it when shutdown starts. From that point, a request that reaches counting is refused with HTTP 503 and its own id, and is not served. Stdio counts are kept apart and are never certified. A request with no protocol revision is broken down by named client or User-Agent family; the breakdown is bounded and raw agents are never stored. The RFC-0060 U1 decision reads only the sealed segments from the declared production writer, so a crash, an overlapping or foreign gateway, or a coverage gap blocks the decision instead of skewing it. 4.0.0 ships with no measured data; the measurement itself is MIK-8442.
