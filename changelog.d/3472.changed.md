- **One `url` key per backend.** A backend's address now takes a single `url` key; its scheme picks the transport (`http://` or `https://` for HTTP, `ws://` or `wss://` for WebSocket). `http_url` and `ws_url` keep working. Run `mcp-gateway upgrade` to rewrite them as `url` in place: it keeps every comment, lists the lines it changed, and changes nothing on a second run. `mcp-gateway add`, the setup wizard and `init` now write `url`. Setting `url` beside `http_url` or `ws_url` is refused, naming both. A backend that ends up with two transport keys once the file and the environment merge (say `http_url` in the file and `MCP_GATEWAY_BACKENDS__<NAME>__WS_URL` in the environment) no longer loads: before, the second was dropped without a word; now the error names both keys, and you keep one. `MCP_GATEWAY_BACKENDS__<NAME>__URL` is refused too, naming the `__HTTP_URL` and `__WS_URL` variables that work. (MIK-8044)
