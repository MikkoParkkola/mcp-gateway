- **Windows lock files are owner-only, and a lock directory open to every account is refused.** The grant journal, the audit-log segment lease, OAuth client registration and token refresh, the control-plane store and protocol telemetry took their cross-process lock on a `.lock` file that was created with its directory's inherited ACL, and an existing one was used whatever its permissions. Another local account that could open it could hold it and stall the gateway's writes (no data was exposed: a lock file is empty). Those locks now create the file owner-only and replace an existing one that is not owner-only once nothing has it open; a file still held open elsewhere (for example by an older gateway during an upgrade) is waited out up to the lock's usual deadline, then refused with the file, the rule it fails and what to do. A lock directory that Everyone, Anonymous or a specific other account may create files in is refused. One that only `BUILTIN\Users` or Authenticated Users may create files in (common outside the user profile) is used, with one warning naming the directory, the group and the repair, and `mcp-gateway doctor` reports it as a `lock-directories` warning. (MIK-8933)
  Affects: Windows only, every release with these locks; unix unchanged. Operator action: none in the usual case, since the gateway replaces such files itself. When it refuses a lock file, stop the process that holds it. When it refuses a lock directory, or warns about one, remove the other accounts' rights to create files there as the message says.
