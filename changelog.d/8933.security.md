- **Windows lock files are owner-only, and lock directories other accounts can write are refused.** The grant journal, the audit-log segment lease, OAuth client registration and token refresh, the control-plane store and protocol telemetry took their cross-process lock on a `.lock` file that was created with its directory's inherited ACL, and an existing one was used whatever its permissions. Another local account that could open it could hold it and stall the gateway's writes (no data was exposed: a lock file is empty). Those locks now create the file owner-only, replace an existing one that is not owner-only once nothing has it open, and refuse a lock directory that lets another non-admin account add, delete or change files in it. A file still held open elsewhere (for example by an older gateway during an upgrade) is waited out up to the lock's usual deadline, then refused with the file, the rule it fails and what to do. (MIK-8933)
  Affects: Windows only, every release with these locks; unix unchanged. Operator action: none in the usual case, since the gateway replaces such files itself; when it refuses a lock file, stop the process that holds it, and when it refuses a lock directory, remove other accounts' write rights on that folder as the error says.
