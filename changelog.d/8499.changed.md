- The input sanitizer (`security.sanitize_input`, on by default) no longer rebuilds a clean request: it now edits the request in place and copies only what it rewrites. Sanitizing a clean 1 or 3 MiB `tools/call` allocates a fixed amount (it allocated about 9 MB and 27 MB), so a refused 1 MiB call no longer costs about 9 MB more with the sanitizer on. An object with a key to rewrite is rebuilt by moving its members instead of copying them, so one control character in an argument key no longer buys a copy of everything beside it (it cost about 5.8 MB at 1 MiB). What it refuses and rewrites is unchanged. Measured on the router test fixture (body in one chunk, firewall off). Known limit in 4.0.0: rebuilding one very large flat object with a key to rewrite still allocates its index in proportion to its number of keys (MIK-8499; follow-up MIK-8541).
