- **On Windows, a private save refuses a file another account owns.** A config or state save that writes an owner-only file (OAuth storage, history, journals, certificates and the like) used to replace a file another account owned with one owned by the gateway's account. It now saves only a file the gateway could itself have created: one owned by its own account, or by the default owner its token gives new files (on an elevated administrator, the Administrators group). Any other owner is refused with `foreign-owner`, naming both accounts, before anything is written; a file whose owner cannot be read is refused with `descriptor-unreadable`. On an elevated gateway, an owner-only file owned by the Administrators group becomes owned by the gateway's user after a save, which keeps it owner-only. A file on a volume that keeps no access lists (FAT, exFAT) saves as before.
  Affects: 4.0.0 pre-releases. Operator action: none, unless a save reports `foreign-owner`; then run the gateway as the file's owner, or give the file to the gateway's account.
