- **On Linux, a config save keeps the file's security label, or refuses.** The shared writer behind every config and state save now copies a file's `security.selinux` and `security.SMACK64` labels onto the new copy before writing any data, and confirms them by reading them back. If it cannot, the save is turned down with `label-not-kept` and the file stays as it was; the admin UI answers with a 409 and the CLI exits non-zero. When it replaces a file or saves an owner-only one, it also removes any access list the new copy picked up from its folder. As a result, a file without an access list of its own, in a folder with a default access list, now keeps its mode across a save (0640 stays 0640 when the gateway can keep the file's group) instead of being cut to 0600.
  Affects: 4.0.0 pre-releases. Operator action: none, unless a save reports `label-not-kept`; then let the gateway's account set that label in the folder, or remove the label from the file (see the upgrading guide).
