- **The web UI can add a URL server that needs a key in a header, and a plain-http add with credentials gets its cause and fix instead of a 500.** The add form now takes `headers`; a value that reads as a secret is kept in the secret store and gateway.yaml holds its reference. An add that would send credentials over plain http to another machine is refused with the refusal list's own cause and fix (HTTP 422) before anything is stored, where a plain-http URL with a query used to fail with "the backend change was not written" (HTTP 500). Setting `allow_cleartext_credentials: true` in the same request accepts it and is named in the audit record; it never lifts a credential written into the URL. Loopback and https need nothing.
  Affects: 4.0.0 pre-release builds. Operator action: none.
