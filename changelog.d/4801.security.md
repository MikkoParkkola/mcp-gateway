- **Chain and playbook step seals, and a stored task's own seal, are no longer served over bytes the egress firewall redacted.** A step answer is sealed when it is made; the egress firewall later redacts the delivered answer, and the step seal's readable payload carries the unsalted digest of the unredacted step, so a client could test guesses of a removed value offline. While the firewall scans responses and a redacting policy applies, every `public_signature` in the answer is now removed before the scan, at any depth and in JSON text, `tasks/get` and task notifications included; the fresh top-level seal, applied after the scan, still covers what is delivered. An answer the firewall rewrote whose text names `public_signature` without parsing as JSON is refused. See UPGRADING-4.0. (MIK-9428)
  Affects: 4.0.0 pre-releases only; 3.x unaffected. Operator action: none.
