- **A web UI settings save is audited once, before and after.** Before it writes, a settings save appends an intent record (who, the file revision it started from, the fields it changes) to the audit log, and its admin action record then carries `save_outcome` (`applied`, `unchanged`, `refused`, `stale`, `rolled_back` or `indeterminate`) with the same intent id. With auth on, a save whose intent cannot be written is refused with nothing changed. The answer carries a `notices` list: `OUTSIDE_CHANGE_APPLIED` when the save's reload also loaded edits made to gateway.yaml outside the UI, and `NOT_AUDITED` when auth is off and no audit log is open. Turning auth on from the UI is refused (409 `AUDIT_LOG_REQUIRED`) unless the audit log the next start opens is enabled and writable. See `docs/UPGRADING-4.0.md`.
