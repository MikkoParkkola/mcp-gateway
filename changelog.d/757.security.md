- The key server no longer issues a full-access token for a scope request that misses its policy. From 2.10.0 through 3.5.1, a token request whose requested backends or tools overlapped nothing in the matching policy rule got empty scope lists, and an empty list means "all": the token reached every backend, or every tool. The exchange now answers 403 and issues no token (UPGRADING item 93). Affected: 2.10.0 through 3.5.1, with the key server enabled; 4.0.0-beta.1 and later carry the fix. Action: upgrade. Then, in the key server's audit log, check each issued token whose `backends` or `tools` list is empty against the policy rule that matched: an empty list is expected only where the rule grants everything. Revoke any such token still live with `DELETE /auth/token/{jti}`. (#757)
  Affects: 3.x up to 3.5.1 and earlier 2.x releases with the key server enabled; the 4.0.0 pre-releases carry the fix. Operator action: check each key-server token issued with an empty backends or tools list against its matched policy rule and revoke any still-live mis-scoped token with DELETE /auth/token/{jti}.
