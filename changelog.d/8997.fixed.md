- **`security.response_inspection.enabled: false` now turns response inspection off.** The setting was read only to decide whether to switch on action mode, so with `enabled: false` every answer was still inspected: findings were added to the answer as `_security_findings`, a "Response inspection finding" warning was logged for each, and the inspection ran on every call. Now nothing is inspected, annotated, logged or blocked by it, and `enabled: false` wins over `action_mode: true`. The firewall's own response scan (`security.firewall.scan_responses`) and context integrity are separate switches and are unchanged; the default (`enabled: true`, observe mode) is unchanged. (MIK-8997)
  Affects: gateways that set `security.response_inspection.enabled: false`. Operator action: none; expect no `_security_findings` and no inspection warnings while it is off.
