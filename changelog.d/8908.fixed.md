- **Backend `env` and `headers` accept secret references.** An enabled backend's env or header value that is a whole `env:NAME`, `file:/abs/path` or `keychain:NAME` reference now resolves to the secret, used as stored (a `file:` value drops one trailing newline, as in every slot); before, it reached the backend as the reference text. A disabled backend keeps its text until it is enabled. Every save path (the web UI's add and edit, `mcp-gateway add`, `discover --write` and the setup import) refuses a reference that does not resolve before writing, naming the field (the web UI answers 422), and a config edited by hand with one fails to load the same way. `mcp-gateway get` and the web UI's config read show a reference as written, never its value. (MIK-8908)
