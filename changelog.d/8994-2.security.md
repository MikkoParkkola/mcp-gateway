- **A required identity binding's per-user sends recheck the user's credential each time, and A2A per-user sessions send only it.** Each send on such a per-user session (a call, a retry, a session-expiry re-handshake, a legacy SSE reopen, an era re-probe, a notification) first rechecks the dispatch's credential: a managed account's grant through its custody, any other credential against its published expiry. A grant revoked or a credential expired during a call refuses that call's next send and closes that user's session; a routine token refresh refuses only that call, and the user's next call is served. Each send uses only the credential of the call that caused it. On an A2A backend with a required binding, a user's own session sends no static header and no URL credentials, fetches the agent card under the user's credential, and sends nothing (no cancel, no poll) once the user's call has ended. Each refused send is counted in `mcp_gateway_per_user_send_refused_total`, by reason. (MIK-8994)
  Affects: gateways with a backend whose identity binding is required, managed accounts and A2A agents included. Operator action: none; see UPGRADING.
