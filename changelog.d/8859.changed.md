- **The shadow scan offers adoption only for a server the gateway can run exactly as its client does.** A server found in a client config is no longer proposed for adoption when the gateway would run it differently, or would copy a secret into gateway.yaml as text. That covers a variable the gateway would not expand (`${input:...}`, or any `${...}` in a command, argument, working directory or URL), a non-string value, a client setting it does not carry (a sandbox, `envFile`, client OAuth, a timeout, a relative working directory, a socket endpoint), an entry its client keeps disabled, a template with a non-empty default (`${KEY:-value}`), literal text beside a variable (`sk-${SUFFIX}`; a single scheme word such as `Bearer ${TOKEN}` is fine), a template read as a secret reference (`file:${HOME}/token`), a URL carrying a credential (a user name or password, a fragment, or or any query string), and credentials sent in cleartext to another host. Such a server is reported with "request owner" and a risk naming the reason and what to change, for example: move the whole value into a variable or secret, then rescan. (MIK-8859)
