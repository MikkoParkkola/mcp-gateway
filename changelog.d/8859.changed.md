- **The shadow scan offers adoption only for a server the gateway can run exactly as its client does.** A server found in a client config is no longer proposed for adoption when the client expands a variable the gateway would not (`${input:...}`, a `${...}` in a command, argument, working directory or URL), when a value is not a string, when a template carries a non-empty default (`${KEY:-value}`, whose default would be written into gateway.yaml as text), when a template would be read as a secret reference (`file:${HOME}/token`), or when its URL carries a credential (a user name or password, or a query parameter such as `api_key`, `access_token` or `X-Amz-Signature`). Such a server is reported with "request owner" instead. (MIK-8859)
