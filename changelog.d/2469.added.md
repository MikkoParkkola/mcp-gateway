- **The protocol-revision measurement window is per transport and restart-safe for HTTP.** It is set by `server.protocol_revision_window: off | record` (default `off`); with `record`, a shutting-down gateway refuses (503) requests that arrive after its segment seals. Each HTTP `serve` process records its own segment in `protocol-revision-telemetry/window.json` every 5 s and seals it on shutdown. Stdio counts are kept apart. The RFC-0060 U1 decision reads only a sealed prefix of clean segments from the declared production writer, so a crash, a concurrent or foreign gateway, or a coverage gap blocks the decision instead of skewing it. Requests with no protocol revision are broken down by named client or User-Agent family (bounded; raw agents are never stored). A v1 window is refused, never converted: archive it before starting a window. The v1 library items (`DurableWindow`, `load_durable_window`, `production_retirement_decision[_at]`, `DURABLE_WINDOW_SCHEMA`) are removed. See UPGRADING item 107. (#2469)
