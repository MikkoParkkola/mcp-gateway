- **Editing a backend no longer turns a stored secret into plain text.** When an env value of a backend holds a secret reference (`env:`, `file:` or `keychain:`), a new value typed over it in the web UI is now stored as a secret whatever the variable is called, as long as it is 8 bytes or more. A shorter value is refused with `secret_too_short`, naming the field and never the value, before anything is stored or written. An empty value, a template or another reference is still written as given, and values that hold no reference keep the old rule. If another writer turns the value into a reference between the edit's read and its write, the edit answers 409 and changes nothing. Before, a value under a name that did not look like a credential (for example `DATABASE_HOST`), or a short one, was written into gateway.yaml as typed, replacing the reference.
  Affects: 4.0.0 pre-releases. Operator action: if you edited a backend's env values in the web UI on a pre-release, check gateway.yaml for a value that used to be a reference and now holds the secret itself; set it again to store it.
