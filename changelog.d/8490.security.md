- **The Linux keychain store passes every secret name to `secret-tool` as a value, never as an option.**
  The secret name grammar allows a leading `-`, and `secret-tool` read such a name as one of its own options.
  With a name that is its help option (`--help`, or `-h`), a save printed the help, stored nothing and still
  reported success, a delete left the entry in place, and a read could return the help text as the secret; other
  names it parses as options, such as `-x` or `--`, failed with an error and stored nothing. Every `secret-tool` call now puts
  `--` before its attribute pairs. The store's entry points also refuse a name outside the secret
  name grammar (letters, digits, `.`, `_`, `-`; 1 to 128 characters) before any process starts,
  with one fixed message that never repeats the name.
  Affects: 4.0.0 pre-releases on Linux whose secrets store uses the Secret Service (`keychain`, or `auto` where the keychain probe passed); 3.x has no secret saves. Operator action: a secret saved under a pre-release with a name `secret-tool` parsed as an option (such as `--help`, `-x` or `--`) was never stored; save it again after upgrading.
