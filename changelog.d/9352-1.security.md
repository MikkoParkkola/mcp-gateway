- **Credentials given to `mcp-gateway add`, `setup` and `discover --write` are kept out of gateway.yaml.** `add`'s env values (`-e NAME`, `--env-file`) and a registry server's token, and the servers `setup` imports, now go through the rule the web UI backend panel uses: each literal env value whose name ends in a credential word (`DB_PASSWORD`, `OPENAI_API_KEY`) and each header value, at least 8 bytes long, is saved in the secret store (`secrets.store`) and only its reference is written. Other values (`DEBUG=1`) are written as typed. `add` prints each stored field and its reference; `--keep-as-text KEY` (or `header:NAME`) writes that value as typed instead. `discover --write` used to store every literal a client file held, so an ordinary setting such as `DEBUG=1` was redacted from tool results wherever it appeared; it now stores by the same rule, and still stores a value shaped like a secret reference (`file:/x`) under any name, so the gateway never reads it as one. Values written before 4.0.0 are not moved. (MIK-9352)
  Affects: 4.0.0 pre-releases and earlier. Operator action: replace any secret a CLI command wrote into gateway.yaml before 4.0.0 with an `env:` or `keychain:` reference under the same key, or add the backend again.
