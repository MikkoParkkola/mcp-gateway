- **Credential redaction keeps JSON text parseable.** When a tool answer's text is a JSON document, including `gateway_invoke`'s pretty-printed answer, a database connection string in it used to be redacted together with everything after it up to the next space, so the delivered text was no longer JSON. The redactor now replaces the same characters only inside the JSON strings they cover and keeps the quotes, commas, braces, keys and numbers between them, so the text still parses and a string value hidden before stays hidden. The direct route's provenance receipt now records the row count of such an answer instead of none. Text that is not a JSON object, array or string is redacted as before. Two cases still take the whole-value redaction, so that answer's JSON may not parse: a credential that starts inside a JSON key, and a text over 1 MiB (MIK-8772, planned for 4.0.1). A number after a connection string in compact JSON text is not hidden (MIK-8757). (MIK-8745)
