- **Credential redaction keeps JSON text parseable.** When a tool answer's text is a JSON document, including `gateway_invoke`'s pretty-printed answer, a database connection string in it used to be redacted together with everything after it up to the next space, so the delivered text was no longer JSON. The redactor now replaces the same characters only inside the JSON strings they cover and keeps the quotes, commas, braces, keys and numbers between them, so the text still parses and a string value hidden before stays hidden. The direct route's provenance receipt now records the row count of such an answer instead of none. Text that is not a JSON object, array or string is redacted as before. A credential that starts inside a JSON key is replaced inside that key, which takes the first free `#n` suffix in its object so no entry is lost (MIK-8772). This holds for texts over 1 MiB too (MIK-8774). A number after a connection string in compact JSON text is not hidden (MIK-8757). (MIK-8745)
