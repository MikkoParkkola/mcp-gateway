- **A backend with per-user sessions only gets no gateway shared session.** A backend whose identity binding is required with `session_mode: per_user`, or one bound to a managed account or to an external account with per-user sessions, still had a shared session opened by the gateway itself: warm-start listed its tools, the health loop probed it, and a restart from the dashboard rebuilt that session. Each of these requests carried no subscriber's credential, and a cold caller's `tools/list` could show a tool list fetched under that shared session. The shared session is now refused before anything is sent, the backend's status reads `per_user`, and a cold caller's first `tools/list` waits, at most 30 s, for that caller's own list instead of the shared one. Not covered: a subscriber's own per-user session still starts (connect, discover, initialize) with only the backend's static headers, before that subscriber's credential is applied (MIK-8994). (MIK-8962)
  Affects: every gateway with a backend whose identity binding is required with per-user sessions, or that is bound to a managed account or to an external account with per-user sessions. Operator action: none; expect `per_user` in that backend's status and no health data for it.
