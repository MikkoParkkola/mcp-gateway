- **A capability file changed behind its pin is acted on as the capability it was loaded as.** The gateway names the changed file's capability by the path it was loaded from, never by a name or pin the changed bytes declare, so a change that renames the capability unloads the loaded one at once rather than at the next reload, and a file declaring another capability's pin can no longer unload or relabel that capability. The warning it logs names the trusted capability and escapes the path, so the changed bytes cannot forge a log line. (MIK-8868)
