- **The config read names whose secret each reference is.** `GET /ui/api/config` gains `secret_reference_records`: one record per backend `env` or `headers` slot that holds a reference, with the server's name, the kind (`env` or `headers`), the field's name and the reference as written (never a value), sorted by server, then kind, then field. The flat `secret_references` map is unchanged, but its keys join those parts with dots, so a server or field name that holds a dot makes a key ambiguous; read the records to know which server a slot belongs to.
