- Added `GET /ui/api/settings/secrets/unused` and `DELETE /ui/api/settings/secrets/unused/{name}?store=files|keychain` for a gateway admin: the first lists the secret entries the index records that no source names (the config, its env files, the process environment or a capability file), with their store and write time; the second deletes one of them. The delete holds the reload, config and vault locks, re-reads every naming source just before the store delete, and refuses an entry any source still names, an entry a `file:` reference or a second hard link reaches, and any delete while a config write is unsettled. A listing reads only and never shows a value. On Windows a files-store entry is listed but its delete is refused, because the gateway cannot yet check the file's links there; keychain entries are deleted on every platform.
