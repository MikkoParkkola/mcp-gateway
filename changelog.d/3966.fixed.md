- **`mcp-gateway add filesystem`, `add memory` and `add sequential-thinking` now write current, non-deprecated pins.** The registry pinned `@modelcontextprotocol/server-filesystem`, `-memory` and `-sequential-thinking` at the date-based `2026.8.31`, which npm now marks deprecated ("Date-based versions are no longer published. This package has resumed semantic versioning at 1.0.0"). The three entries now pin `1.0.0`, upstream's final legacy release. Existing configs keep their pins; this changes what `add` and `init` write. Three differences you can see after moving to `1.0.0`. **`sequential-thinking` is no longer marked read-only or idempotent:** a `gateway_list_tools` call that asks for the `selector` or `extractor` role no longer lists it (ask for `action`, or for no role), and its results are no longer eligible for the response cache, which is correct for a tool that keeps the thought history. `mcp-gateway init` enables it by default, so new setups see this at once. **`memory` is stricter and starts empty:** it rejects a relation that names an entity that does not exist, and an entry added on the new pin starts a fresh graph in its own `npx` cache, so set an absolute `MEMORY_FILE_PATH` first if your graph matters. **`filesystem`** waits for the client's roots before serving tool calls and fails visibly when started with no directories and no roots. Operator action: none to keep working; to move an existing entry, re-add it or edit the version in your config. (MIK-8510)
