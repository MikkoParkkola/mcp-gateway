- **Stopping a stdio backend no longer scans every process on the host first.** On Linux, the record of a backend's descendants taken before its first stop signal used to read all of `/proc`, 32 to 62 ms on a busy host and growing with the host's process count, inside the stop's time budget. It now walks only the backend's own process tree, about 1.5 ms for a small tree. Each walked process is read through its own `/proc` entry held open for the walk, so a process that reuses a pid is never read or signalled in its place, and a snapshot cut short by a stalled host reads again before the first signal, so a descendant whose parent exits is still stopped. A sweep whose stopped backend has exited now finishes in one or two passes instead of re-reading until its time slice ends.
  Affects: 4.0.0 pre-releases on Linux. Operator action: none.
