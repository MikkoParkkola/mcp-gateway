- **Stopping a stdio backend no longer scans every process on the host first.** On Linux, the record of a backend's descendants taken before its first stop signal used to read all of `/proc`, 32 to 62 ms on a busy host and growing with the host's process count, inside the stop's time budget. It now walks only the backend's own process tree: about 1.5 ms for a small tree when warm on an otherwise idle host (slower on a busy one, and once after a rebuild a single snapshot took over 20 ms). Each walked process is read through its own `/proc` entry held open for the walk, so a process that reuses a pid is never read or signalled in its place. A snapshot cut short by a stalled host reads again, up to four times, so a descendant whose parent exits before the first signal is still stopped unless all four readings are cut; a descendant none of them recorded can then escape the stop, which logs the shortfall. In acceptance runs, a sweep whose stopped backend had exited finished in one or two passes instead of re-reading until its time slice ended.
  Affects: 4.0.0 pre-releases on Linux. Operator action: none.
