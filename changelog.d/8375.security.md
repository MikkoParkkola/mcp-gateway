- **A config that will not load no longer prints the value it refused.** A wrongly typed value (a token where a number goes, `!!int` on a secret, a bad or over-long duration, an env override of the wrong type) was quoted in the load error on stderr, in `doctor`, and in the log line of a refused reload. A config that fails to parse or to match its expected types now reports the key, the file, the line and column where known, and the type expected, never the value; this covers the gateway's own field parsers (durations, `known_agents`) too. `doctor`'s suggested fix for such a config is now `mcp-gateway doctor --config <file>`; it named `validate`, which never loads the gateway config. (MIK-8375)
  Affects: anyone whose config error output reaches logs, CI or a terminal recording.
  Operator action: none.
