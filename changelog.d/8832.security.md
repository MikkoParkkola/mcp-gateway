- **A credential beside the gateway's own continuation token is redacted again.** Inside JSON text, the egress redactor keeps a value that is the gateway's own continuation token. It did so by dropping every credential match that touched that value. A connection-string match runs to the next whitespace, so in compact JSON such as a `dsn` value followed directly by a `next` continuation, the match crossed the continuation and was dropped whole. The connection string, password included, reached the client. Now only the continuation's own bytes are left out of the match, so the credential beside it is redacted and the continuation still arrives byte for byte. A pattern is reported only where it still redacts something. (MIK-8832)
  Affects: the 4.0.0 release line since #4110; no published release, 3.x and 4.0.0-beta.1 to beta.3 unaffected. Operator action: none.
