Configuration history: every config reload, whether at startup, from a file change or from the web UI (with the admin who made it), is recorded with its time, source and outcome, and each applied version keeps the exact bytes of gateway.yaml and its env files in `config-history.json` in the data directory. The file is owner-only and bounded (50 versions or 32 MiB, 1,000 events or 4 MiB, 30 days; the running version is never dropped), and a file other users can read, or a symbolic link, is refused and left as it is. Values taken from the process environment and `file:` secrets are never stored. Saves run off the reload path under a 5-second deadline, so a stalled disk cannot hold a reload or the gateway's start, and a failed save keeps the history in memory without overwriting the file.
