## A required identity binding's per-user sessions send only the user's own credential

**Startup:** no notice, a log warning per backend with a required identity binding and static headers, naming each header its per-user sessions leave off (names only, never values)

A backend whose identity binding is required (`identity_propagation.required: true`, whatever its `session_mode`) is reached per user through that user's own session. In 3.x that session still carried the backend's static `headers` and any gateway OAuth token: on every call, beside the user's credential, and alone on the session's own start (connect, `server/discover`, `initialize`, `notifications/initialized`), which went out before the user's credential was applied. In 4.0.0 every request on such a session carries only the calling user's credential.

- What changes: static headers are not sent on per-user requests to such a backend, its calls included. A per-user session's start is made with the user's credential. A request with no user in flight is not sent: closing the session sends no `DELETE` (the backend expires the session itself), a call that is cancelled sends no cancel notification afterwards, and a legacy SSE stream that drops between calls is reopened by that user's next call. A call that carries no credential is refused.
- What stays: a backend whose binding is optional keeps its static headers on every request, as before. A shared session to a backend, where one exists, still sends them.
- What you do: nothing, unless such a backend needs a static header on per-user requests. A credential that identifies the gateway rather than the user does not belong on them; one the backend needs per user belongs in the binding. Startup names every header these sessions leave off.
