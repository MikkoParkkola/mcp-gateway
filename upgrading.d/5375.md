## Windows owner-only saves keep the file's owner

**Startup:** no notice, the owner is checked each time an owner-only file is saved

Several of the gateway's files are kept owner-only: OAuth storage, history, journals, certificates, counters. Saving one writes a fresh owner-only copy, owned by the account the gateway runs as, and swaps it in. Until now that happened whatever account owned the old file, so a file belonging to someone else was quietly handed to the gateway's account.

Now the gateway saves such a file only if it could have created it itself. Its owner must be the gateway's own account, or the default owner Windows gives new files the gateway creates. Any other owner stops the save with `foreign-owner` before anything is written, and the message names the file's owner and the gateway's account. A file whose owner cannot be read stops with `descriptor-unreadable`. A file on a volume that keeps no access lists (FAT, exFAT) has no owner to keep and saves as before.

One change in ownership to expect: on a gateway that runs elevated as an administrator, Windows gives new files the Administrators group as owner. Such a file, after an owner-only save, is owned by the gateway's user instead. This is deliberate: an owner can always change who may open a file, so leaving the group as owner would let any administrator open it, which an owner-only file must not allow.

When `foreign-owner` appears: run the gateway as the account the message names as the file's owner, or give the file to the gateway's account (for example `icacls <file> /setowner <account>`).
