## An import keeps existing capability files

**Startup:** no notice, nothing changes at startup

`cap import`, `cap import-url` and the web UI's OpenAPI import create a capability file only where none exists.
A tool whose file name is already taken is reported with the name and what to do, its file is left unchanged, and
the other tools are still written. The web UI import checks every configured capability directory and answers 409
when every selected tool was refused.

`cap import` now prints its summary after writing and exits 1 when any tool was not written, an existing name
included, as `cap import-url` already did. In 3.x it exited 0 whatever happened, so a script that relied on that
may now see 1.

Re-importing a document no longer refreshes its tools: remove the capabilities it created, then import again.
