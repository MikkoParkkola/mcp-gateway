## The one-shot host resolver check is removed

**Startup:** no notice

**What you gain.** One DNS-rebinding defence. Inside the gateway, clients that follow tool-supplied URLs pin every resolved address at connect time through `PinningResolver`; nothing public offers a second, one-shot check that a later lookup could bypass. Operator-configured backends are trusted and not pinned, and with `capabilities.egress_proxy` set the proxy resolves names itself; both exceptions are unchanged.

**What you lose.** The path `mcp_gateway::security::resolve_and_validate_host` no longer resolves.

**What you do.** Do all three; each closes a gap the others leave open.

1. Call `mcp_gateway::security::validate_url_not_ssrf` on the request URL and on every redirect hop. A URL whose host is an IP literal never reaches a DNS resolver, so the pin cannot see it.
2. Build the reqwest client with `.no_proxy()`. Through an environment proxy, the proxy resolves the name and the pin is never consulted.
3. Wrap your `HostResolver` in `PinningResolver::new` and set it as the client's `dns_resolver`. It refuses a name that resolves to a private or reserved address, the same ranges the removed function checked. The gateway's configurable destination policy and allow-list are internal to the gateway and do not apply to a resolver built this way.
