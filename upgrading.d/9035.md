## Injected credentials no longer come back through a backend

**Startup:** no notice, a log warning at the first send of a rule value under 8 bytes

**What you gain.** A backend that echoes the credential a `secrets:` rule injected (in a result, an error, a notification, a resource URI, a stream frame) no longer hands it to the client, to the response cache or to the logs. Each occurrence, verbatim or percent-encoded, becomes `[redacted]`.

**What changes.**

- Text in a backend's answers that equals an injected value is replaced, even inside unrelated words. A very short value, such as `1` or `abc`, can blank ordinary text; the warning names the rule so you can lengthen it.
- An answer whose JSON-RPC `error.code` is the injected value is replaced by the gateway's refusal (`-32603`).
- A signed answer (signature chain) whose top-level key name is an injected value is refused the same way. This fires only when a key name holds a secret.
- A backend whose rules resolve a new value faster than the redaction grace (24 hours, or longer when a timeout or a cache lifetime is longer) can hold at most 1,024 values at once. Past that, its answers are refused until older values age out, and one warning names the backend.
- Diagnostics about a backend's frames name lengths and positions instead of quoting the frame.
- The call's audit record says `response_effect: rewritten` when, during that call, the gateway removed an injected value from something the backend sent. That can be a page, a handshake or a retried attempt you did not receive, so `rewritten` does not mean the answer you got was edited. An answer replaced by the gateway's refusal records `refused` only when that refusal is what the caller received.

**What stays the same.** Calls, routing, progress and subscriptions. A signed answer still verifies. Backends without `secrets:` rules are unaffected.

**Limits.** A value retired more than its grace after its last send is no longer redacted. Percent-encoded spellings are matched in form and RFC 3986 encoding, each with uppercase or lowercase hex; a value encoded twice, or with mixed-case hex within one value, is not matched, and neither is base64 inside a composite value (such as a Basic auth header echoed back).
