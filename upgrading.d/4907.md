## `audit lookup-email`

**Startup:** no notice

Run `mcp-gateway audit lookup-email --email-stdin --url https://gateway.example.invalid`, then type or paste the email and press Enter (or feed it from a file or a secret manager you control; do not `echo` it on the command line, which writes it to your shell history). The command asks a running gateway's `POST /ui/api/key-server/audit/lookup-email` and prints the typed answer as JSON: the matching rows, `next_cursor`, `scan_exhausted`, `cursor_reset`, `unreadable` and `scope`. Bound the first page with `--limit`, `--from` and `--to`. For the next page, feed the previous answer's `next_cursor` back on stdin with `--cursor-stdin`, for example `jq -r '.next_cursor // empty' < page1.json | mcp-gateway audit lookup-email --cursor-stdin --url https://gateway.example.invalid` (after the last page jq prints nothing, and the empty stdin is refused before any request); a page takes `--limit` but no window, since the token carries the first page's.

The email is never an argument (it would land in shell history and in every process listing), so there is no positional email and no email option: exactly one of `--email-stdin` (the first page; one line, at most 1 KiB) and `--cursor-stdin` (every later page; one line, at most 2048 bytes) is required. The page token is a short-lived capability for one page of that email's answer, so it is stdin-only too: there is no `--cursor` option, and a typed `--cursor` is refused by the argument parser without printing its value. Any other value typed as an argument (a positional email or token, `--email-stdin=...`, `--cursor-stdin=...`, or a token given to `--limit`) is refused with a fixed message that never repeats it; it has still reached your shell history and the process listing, so give both on stdin only. This covers any command line that names `audit lookup-email`, wherever the value was typed; only a value given to `--url`, `--from`, `--to` or a TLS file flag is taken as that flag's value (a missing file's error names its path). `hash-key`, which reads its API key from stdin, gets the same fixed message for a key typed as an argument ("The API key is read from stdin only"); scripts that matched its old parse-error text need the new one. A page token is single use and lives five minutes: a throttled request (HTTP 429) leaves it redeemable, a successful answer that was lost on the way has already spent it (ask for the first page again). Treat saved output as sensitive until its `next_cursor` is spent or has expired. The credential comes from `MCP_GATEWAY_TOKEN` and is never read from the command line. TLS flags are those of `dashboard-link`. A redirect is not followed, a cleartext non-loopback URL is refused, and nothing is written to disk. Any HTTP, authentication, read or decode failure is a nonzero exit, and its message never contains the email or page token read from stdin, or the credential. The gateway's lookup budget applies (two lookups at once, then one every six seconds).
