## An invalid firewall rule glob refuses the config

**Startup:** no notice; refuses to start

Before 4.0.0 a rule's `match` glob that did not parse, such as `exec_[`, was read as `*`. An `allow` rule with a typo then allowed every tool call whatever its scans found. With `security.firewall.enabled` on, the gateway now refuses the config and names the rule by position, `security.firewall.rules[N].match`. A disabled firewall runs no rules, so its rules load as before.

- What you lose: a config with a broken glob that used to start.
- What you gain: a typo in a rule can no longer open the firewall.
