## Linux saves keep security labels

**Startup:** no notice, the label is checked each time a file is saved

Every config and state save writes a fresh copy beside the file and swaps it in. On Linux that copy used to get whatever label and access list its folder hands to new files. An administrator's own label on the file, or a stricter one, was lost on the first save, and a folder's default access list could open the new copy to readers the old file kept out.

The gateway now copies the file's `security.selinux` and `security.SMACK64` labels onto the fresh copy while it is still empty and closed to everyone, then reads them back to confirm. When it replaces a file, or saves one as owner-only, it also removes any access list the fresh copy got from the folder.

One visible side effect, for a file in a folder with a default access list when the file itself carries no access list (for example, one created before the folder's list was added): it now keeps its own mode across a save, so a 0640 file stays 0640. Before this change the copy kept the folder's list and the gateway cut the mode to 0600 to compensate. A file that carries an access list of its own, as files created in such a folder usually do, is still narrowed to owner-only, as before. Brand-new files still take what the folder gives them, and backups still stay owner-only in such a folder.

When a save is turned down (`label-not-kept`; the file is not touched and the message gives the file, the label's name and the gateway's user id):

- The host runs SELinux or SMACK, the file carries a label different from the one its folder gives new files (for example after `chcon`), and the gateway's account is not allowed to set it: no relabel permission in its SELinux domain, or no `CAP_MAC_ADMIN` for SMACK.
- The label cannot be read at all (an error other than "no label" or "not supported"), or a backup of a labelled file goes to a filesystem that cannot store the label.
- In the unusual case of a policy that lets the gateway set a label but not write a file carrying it, the save stops with the system's own permission error instead, and the file is likewise left alone.

The `label-not-kept` refusal never reaches hosts without SELinux or SMACK, or files the gateway created itself. The removal of a folder's inherited access list, and the mode change that comes with it, applies on every Linux host.
