## Remote commands exit with the shared exit table

**Startup:** no notice, nothing changes at startup

What you gain: a script can tell the failures apart. `dashboard-link`,
`events dead-letters` and `audit lookup-email` exit as `api` does: 2 for a
usage error (bad arguments, settings, stdin or `--from`/`--to`), 3 when the
credential is missing or refused, 4 when the gateway lacks what was asked for,
5 when the gateway cannot be reached or a read's answer is lost, 6 for a
gateway error, and 8 when a `replay` may have run but its answer was lost.
Every error says what to do next on its second line. docs/CLI.md lists the
codes.

What you lose: every failure used to exit 1, and stderr began with the command
name (`dashboard-link:`, `events dead-letters:`, `audit lookup-email:`). Both
are gone. `api`'s remedy for a missing or refused credential now names
`MCP_GATEWAY_TOKEN`; it no longer points at a `login` command, which does not
exist yet.
