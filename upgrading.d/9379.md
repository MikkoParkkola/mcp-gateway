## Plan task rows carry their relay replay snapshot

**Startup:** no notice

**Who is affected.** Gateways with relay detection on (`security.firewall.collusion`) that run plan or multi-target tasks, and anyone planning to downgrade such a gateway.

**Before.** A completed plan task's relay replay snapshot lived only in memory and was captured after the result became readable, so a read in between delivered the result untracked. A restart lost every snapshot.

**After.** The snapshot is written with the result, in the same task-store write, under a new task record version. Only rows that carry a snapshot are written at that version; every other row keeps its version and its bytes. A row with no room for its snapshot stores a marker in its place, and a read of it is treated as untrackable. The snapshot is tied to the gateway process that made it: after a restart, a read of an older row is refused under `block` and delivered, counted and audited under `observe`, until the task expires. Under `off`, reads are delivered as before.

**What you do.** Nothing for an upgrade. Do not downgrade past this version while task rows that carry a snapshot exist: an older gateway refuses those rows. Let such tasks expire, or remove the task store, before a downgrade.
