## `accounts.schema_version` is optional; `validate` colour follows the terminal

**Startup:** no notice

What you gain: one line less in an `accounts` block. Without `schema_version`
it loads as `accounts.v1`, the only accepted value. `mcp-gateway validate`
colours its output only when stdout is a terminal and `NO_COLOR` is unset or empty,
so output piped to a file or another program is plain without a flag.

What you keep: a written `schema_version` is still checked, and any value
other than `accounts.v1` still fails the load. `--no-color` still forces plain
output; it is no longer listed in `--help`.

What you lose: nothing. A script that relied on `validate` colouring output
sent to a pipe now gets plain text, which is the `NO_COLOR` convention's
default for non-terminals.

What to do:

- Nothing.
- Optionally delete `schema_version: accounts.v1` from your `accounts` block.
