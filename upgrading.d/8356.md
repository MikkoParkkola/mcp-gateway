## Per-user backends answer from the caller's own catalogue

**Startup:** no notice

**A call is judged by the caller's own catalogue.**
- What you lose: on a per-user backend, a tool the shared catalogue lists but the caller's own catalogue
  withholds (an invalid input schema) or does not list is no longer dispatched. It answers -32601, exactly
  as an unknown name does, on every entry: `/mcp`, stdio, `/mcp/{name}`, `gateway_invoke` and
  `gateway_execute` steps. The argument-key setting (`input_schema_enforcement`) no longer turns this off.
  The old "the backend does not list a tool named ..." text no longer reaches a caller of a per-user backend.
- What stays the same: shared-catalogue backends answer exactly as before, text included. A tool the
  caller's catalogue offers is dispatched as before, with one credential resolution per call.
- What you gain: a caller can no longer learn from a call's answer which tools another user's catalogue has.
- What you do: nothing. A client that matched the old text should treat -32601 as "no such tool".

**Name-only listings wait for the caller's own catalogue.**
- What you lose: the disabled-capabilities list, predictions, tool counts (the `initialize` greeting
  included), `gateway_list_servers`, spec-preview names and `tools/resolve` leave out a per-user
  backend's tools until the caller's own catalogue has been read once; a count that leaves one out says
  "at least". A managed account whose grant was rotated or revoked is read again before these answer.
- What stays the same: `gateway_list_tools` and search read the caller's catalogue as before; the
  surfaced tools in a plain `tools/list` still show the shared entry to a caller whose catalogue has not
  been read.
- What you gain: these listings never name a tool from someone else's catalogue.
- What you do: list the backend once as the caller (`gateway_list_tools`) when you want its tools in them.

**On `/mcp/{name}`, the dispatch guards run after authorization.**
- What you lose: a tool disabled by the kill switch now gets its refusal after the target's
  authorization and the request firewall rather than before them.
- What stays the same: the refusal itself, and that nothing is sent.
- What you gain: a tool the caller cannot see is answered as unknown before any guard can name it.
- What you do: nothing.
