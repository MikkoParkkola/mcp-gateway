change: OIDC discovery and JWKS fetches refuse a redirect to another origin (scheme, host and port); a same-origin redirect is still followed
action: None, unless your issuer serves its discovery document or keys through a redirect to another host; then set that provider's `jwks_uri` to the final URL

## OIDC fetches stay on the origin they were sent to

**Startup:** no notice. The check runs when keys are fetched, so an affected
provider shows up as tokens that fail to verify.

What you gain: the signing keys the gateway trusts for `key_server.oidc` and
Cloudflare Access come from the URL you configured (or the one the issuer's
discovery document names), not from wherever a redirect points.

What you lose: an issuer whose discovery URL or JWKS URL answers with a
redirect to a different host, port or scheme no longer verifies. The fetch
fails with "OIDC refuses a redirect off the fetched URL's origin". An explicit
`jwks_uri` is used without fetching discovery, so it fixes either case.

What to do:

- Nothing, if your issuer answers directly or redirects only within its own
  origin.
- Otherwise, find the final URL (for example
  `xh --follow --headers https://idp.example/.well-known/jwks.json`) and set
  it as that provider's `jwks_uri`.
