## Denying an access request is a governance audit event

**Startup:** no notice

A deny writes one `control_plane_audit` record (action `mutate_grant`) whose `ui_decision`
body names the exact refusals it closes. The open decisions are rebuilt from the governance
audit at startup, so a denied request stays closed after a restart.

**Older gateways** read the record as a plain grant-mutation audit event and ignore the body,
so a request denied on this version shows as open again there.

**Retention:** the governance log keeps a fixed 4 segments of 16 MiB. If a deny leaves that
log while the refusals it closed are still kept in the invocation log, the request shows as
open again after the next restart. Nothing is granted; deny it again.

**Library API:** `ControlPlaneAuditEvent` gains `ui_decision: Option<UiDecisionRecord>`;
a struct literal adds `ui_decision: None`.
