## The public error enum is non-exhaustive

**Startup:** no notice

**What you gain.** New error variants can arrive in a minor release without breaking your build. This release adds variants of its own, so a `match` that lists every variant would break now anyway; marking the enum non-exhaustive makes this the last time.

**What changes.** Code outside this crate that matches `mcp_gateway::Error` exhaustively no longer compiles (`error[E0004]: non-exhaustive patterns`). Add a wildcard arm:

```rust
match error {
    mcp_gateway::Error::BackendNotFound(name) => { /* ... */ }
    _ => { /* every other error, including ones added later */ }
}
```

**What stays the same.** The gateway binary, its configuration and its wire responses. `matches!`, constructing variants, and any `match` that already ends in a wildcard arm.
