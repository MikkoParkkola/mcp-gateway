## Library: an OAuth transport always has a login gate

**Startup:** no notice

**A request-time login outlives the request that began it, for library-built transports too.**
- What changes: before, an `HttpTransport` whose `OAuthClient` had no login gate ran a request's token step inline, so a caller that gave up (a timeout or a dropped future) also ended the browser login it had opened. The transport now gives such a client its own gate, and the login runs in a task of its own, as it already did for every transport the gateway builds. Approving it later stores the token, and the next request uses it.
- What stays the same: a restart or stop (closing the transport) still ends the login, and a client that already has a gate keeps it.
- What you do: nothing, unless your code depended on dropping a request to cancel its login. To end a login, close the transport.
