change: On the meta route (`gateway_invoke`, `gateway_execute`, `gateway_run_playbook`), a per-user backend's refusal of the caller (no credential for a lent-only slot, or a credential that failed its check at the send) is now a JSON-RPC error -32001, as on the direct `/mcp/{name}` route, instead of a tool result with `isError: true`, a `BACKEND_ERROR` recovery hint and a suggestion to retry
action: A client that read this refusal from an `isError` result on `gateway_invoke` should read the JSON-RPC error instead, and not retry it: the caller needs its own credential first
---
## A per-user credential refusal on the meta route is a JSON-RPC error

**Startup:** no notice

**Who is affected.** Clients of a gateway with per-user backends (`identity_propagation.session_mode: per_user`) that call those backends through the meta-tools. The direct `/mcp/{name}` route already answered this way and does not change.

**Before.** When the gateway refused the call because the caller brought no credential for a lent-only per-user slot, or because its credential failed its check at the send, `gateway_invoke` answered with an ordinary tool result: `isError: true`, a `_recovery` hint with `error_code: BACKEND_ERROR` and `retry: true`, and the text "retrying once is safe". The same refusal during the first listing of the backend's tools read as "the gateway could not read this tool's input schema", and every such refusal counted against the backend's error budget.

**After.**

- The answer is the JSON-RPC error the direct route gives: code -32001 with the refusal's message, no tool result and no recovery hint. A retry without a credential gets the same answer.
- In a playbook, a step refused this way answers as a step the gateway refuses; in a `gateway_execute` chain, the chain's error keeps -32001 and names the refused step.
- The refusal is recorded as refused, and it no longer counts against the backend's or the tool's error budget, so repeated refusals cannot trip the kill switch for every caller. A backend's own -32001 is unchanged: it is still the backend's error.

**What you do.** If your client branched on `isError` or on `_recovery.error_code == "BACKEND_ERROR"` to detect this case, branch on the JSON-RPC error code -32001 instead, and ask the user to connect the account (or present a credential) rather than retrying.
