## Relays are refused until a live config is published

**Startup:** no notice

Relay detection judges each relay under the generation the request is pinned to, else the one published now. The `mcp-gateway` binary publishes its live config before the listener serves and before stdio reads its first line, so this never happens there. An embedding that builds a gateway and serves before publishing one had no generation to judge under; such a relay is now refused with "Relay detection blocked: no live config published; relays refused until one is", and the refusal is logged.

- What you lose: an embedding that serves before publishing a live config gets relay refusals until it publishes one.
- What you gain: relay detection fails closed instead of letting a relay through unjudged.
