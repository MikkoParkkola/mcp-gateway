## Verified identities can no longer be built or changed outside the gateway

**Startup:** no notice

**Who is affected.** Code that links the `mcp-gateway` library and reads, writes or builds a `key_server::oidc::VerifiedIdentity`. Operators who only run the gateway binary are not affected.

**Before.** The type's five fields were public, so outside code could build an identity with a struct literal that no verification produced, or change one after the gateway verified it.

**After.** The fields are private. Reading works through the accessors: `subject()`, `email()` and `issuer()` return `&str`, `name()` returns `Option<&str>`, `groups()` returns `&[String]`. A struct literal, a functional update (`VerifiedIdentity { subject, ..other }`) and a field assignment fail to compile (`E0451`, `E0616`). Serializing an identity is unchanged, so audit output is the same.

**What you do.** Replace each field read with its accessor. If your code built identities, for example in tests, it now has to obtain them the way the gateway does, from a verified token: a `VerifiedIdentity` stands for a verification the gateway made.
