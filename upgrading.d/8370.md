## The dashboard's tools table shows counts, not outcomes

**Startup:** no notice

What you gain: the `/dashboard` table no longer calls a failed call a
success. It is titled "Calls per tool (cumulative since start, top 10)" and
shows the tool, its server and its call count.

What you lose: the status column. Every row said OK, because the stats behind
the table count attempts and record no outcome, so the column carried no
information.

For library users, in `mcp_gateway::gateway::ui`:

- `CallStatus` is removed.
- `RecentCall` is renamed `ToolCallCount`, keeping `tool`, `server` and
  `count`. Its `status`, `timestamp` and `latency_ms` fields are removed.
- `DashboardState::recent_calls` is renamed `tool_counts`.

There is no replacement for the removed fields: the data was never real. In
every row the gateway built, `status` was `Success`, `timestamp` empty and
`latency_ms` `None`.

What to do:

- Nothing, as an operator. Each call's outcome is recorded in the
  transparency log (`outcome`).
- In library code, rename `RecentCall` to `ToolCallCount` and `recent_calls`
  to `tool_counts`, and drop any use of the removed fields.
