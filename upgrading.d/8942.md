## Server state follows `MCP_GATEWAY_CONFIG_DIR`

**Startup:** no notice, starts with empty history

In 3.x the server wrote `usage.json` (the usage counts that rank search results), `transitions.json` and `costs.json` under `~/.mcp-gateway` even when `MCP_GATEWAY_CONFIG_DIR` pointed somewhere else. 4.0.0 writes them under that directory, as it already did for the upgrade stamp. A relative value resolves against the gateway's working directory.

If you do not set `MCP_GATEWAY_CONFIG_DIR`, or set it to the full path of `.mcp-gateway` in your home directory, nothing changes (a literal `~` is not expanded). Otherwise the first 4.0.0 start begins with empty usage, transition and cost history.

- What you lose: without the copy, search ranking history, transition history and today's spend.
- What you gain: one directory holds all of a gateway's state, so two gateways with their own `MCP_GATEWAY_CONFIG_DIR` no longer share these files.
- What you do: stop the 3.x gateway and let it exit (it writes the files on a graceful shutdown), then copy whichever of `usage.json`, `transitions.json` and `costs.json` exist in `~/.mcp-gateway` into your configured directory before the first 4.0.0 start.

`costs.json` holds today's spend against the daily budgets, and 4.0.0 puts it back on start; without the copy, the first 4.0.0 start begins the day's budgets at zero. A file saved on an earlier day is not carried over.

Before downgrading to 3.x, stop 4.0.0 and copy the three files back to `~/.mcp-gateway`: 3.x reads them only from there, so history 4.0.0 recorded under `MCP_GATEWAY_CONFIG_DIR` is not seen otherwise.
