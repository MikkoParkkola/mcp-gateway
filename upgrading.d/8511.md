## The reference servers move to 2.0.0

**Startup:** no notice, nothing changes until you add or edit one of these servers

What you gain: `mcp-gateway add filesystem|memory|sequential-thinking`, and
`mcp-gateway init` (which turns memory and sequential-thinking on), write the
maintained 2.0.0 releases. 1.0.0 is upstream's final release of the legacy
line and gets no further fixes.

What you keep: every config you already have keeps `@1.0.0`; the registry is
read only when a config is written. The filesystem server keeps the folders
you pass on its command line exactly as before: 2.0.0's stricter roots
handling applies only to clients that offer MCP Roots, and the gateway does
not offer them to its backends.

What you lose: nothing on Node 24. On Node 22 the 2.0.0 servers run, but npm's
"requires Node 24" warning goes to the server's own error output, which the
gateway never shows, so you will not see it.

What to do:

- Nothing, to keep working.
- Check your Node.js version (24 or later is recommended for 2.0.0):

  ```sh
  node -e 'process.exit(+process.versions.node.split(".")[0] >= 24 ? 0 : 1)' && echo "Node 24 or later"
  ```

- To move an existing memory server to 2.0.0, keep its graph: memory stores it
  next to the installed package unless `MEMORY_FILE_PATH` names an absolute
  path, and a new version installs into a new folder. In this order:
  1. Stop the memory backend first (remove it from the config, or stop the
     gateway), so nothing writes to the graph while you copy it.
  2. Copy the old `memory.jsonl` to a folder of your own. It sits inside the
     `@modelcontextprotocol/server-memory` package folder in the npm cache; when
     `mcp-gateway doctor` prints a hint for the memory backend, it names that
     cache folder.
  3. Set `MEMORY_FILE_PATH` to the copy's absolute path in the backend's
     `env`, change `@1.0.0` to `@2.0.0`, and start it again.
- To go back, change `@2.0.0` to `@1.0.0`.
