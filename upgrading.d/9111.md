## A backend the routing profile leaves out answers as an unregistered one under mTLS or agent auth

**Startup:** no notice

- What changes: under an mTLS policy or agent auth, a backend the caller's routing profile leaves out is left out of that caller's listings, and a call naming it answers exactly as a call naming a backend that does not exist and that the same profile leaves out.
  - On `POST /mcp` (`gateway_invoke` and the other meta-tools) the routing profile still judges the name by name, registered or not, so the profile's answer no longer tells the caller whether the backend is registered.
  - On `/mcp/{name}` 3.x applied no routing profile and served the call. 4.0 applies the profile there; under an mTLS policy or agent auth a backend it leaves out answers as an unregistered backend.
- What stays: with no mTLS policy and agent auth off, a call naming a backend the profile leaves out answers as it did before this change. A backend the profile admits answers as before.
