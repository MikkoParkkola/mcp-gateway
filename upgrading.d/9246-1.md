## Deferred upstream tasks are withheld after a restart or a secret rotation

**Startup:** no notice, a task stored by a 4.0 pre-release build is withheld at its next read

What changes: a call a backend runs as an upstream task keeps a keyed
fingerprint of the secrets it was sent with. The task is polled and its
result delivered only while the backend's secret rules resolve to the same
values in the same gateway process. After a rotation or a restart, and for
a task stored by a 4.0 pre-release build (nothing records what it
injected), the task ends withheld with a fixed message instead of its
result: an echo of a secret the gateway can no longer redact is never
delivered.

What to do: before resubmitting a withheld task, establish what its
upstream operation did, and resubmit only when that is safe or the call is
idempotent.

Rolling back below 4.0.0: an older build cannot read a deferred upstream
task stored by 4.0.0, completed ones included; it skips each such row at
load with a warning naming the file, and loads the rest of its task store.
Let those tasks finish, or cancel them, before rolling back.
