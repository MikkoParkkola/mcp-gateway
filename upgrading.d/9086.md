## `/mcp/{name}` answers a send-time credential refusal with 403

**Startup:** no notice

- What changes:
  - /mcp/{name}: a call refused at send time for lacking its own credential now answers 403 (was 500). A client that retries on 5xx no longer retries it, and should not: the same call is refused again until it carries the user's credential.
  - The same holds for a call whose credential fails its per-send recheck: a revoked grant, or a credential past its expiry. It answers 403 (was 500), and is refused again until the grant is restored or the credential renewed.
  - A call on `/mcp/{name}` to a backend reached only with each user's own credential, made without one, is refused before anything is sent. It was answered HTTP 500, as if the backend had failed; it is now answered HTTP 403, as `POST /mcp` already answers it.
  - The delivery record of that answer says `response_effect: refused`.
- What stays: the JSON-RPC error code (-32001) and message are unchanged, and a backend's own failure is still answered 500.
