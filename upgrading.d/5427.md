## A web UI write refused before anything was attempted answers 409

**Startup:** no notice

A 4xx means nothing was attempted; a 5xx means the outcome is not
confirmed. These web UI write refusals attempted nothing, so they now answer
**409** with the body they had before:

- the config is being written by another request (key create, key revoke,
  the backend routes, the config restore, discovery adopt): was 503, now 409
  with `Retry-After: 1`;
- a capability directory lock held by another write (`lock_busy`): was 503,
  now 409 with `Retry-After: 1`;
- the settings save while a config write recovers, or after gateway.yaml
  changed and could not be previewed again: was 503, now 409 with
  `Retry-After: 1`;
- no audit log configured (`audit_log_required` / `audit_unavailable`, on the
  backend routes, the config restore, key create, key revoke, discovery adopt
  and the settings save): was 503, now 409, no `Retry-After`;
- gateway.yaml could not be loaded, reload is not enabled, or the config file
  path is not available, on a write route: was 503, now 409, no
  `Retry-After`;
- the writer refused gateway.yaml before changing it and left nothing behind
  (another user owns it, its access list or security label would not be kept,
  or another process changed it): on key create, key revoke, discovery adopt
  and the settings save, was 500, now 409 with the writer's code and text
  where the route shows them; the backend routes and the config restore
  already answered 409.

Unchanged: an audit log that refused a started append stays 503; a timeout or
an unavailable dependency stays 503 (the secret store, the control-plane
store, the clock, a scan that timed out, a config history that could not be
read); the settings diff, a read, keeps its 503s; and the control-plane
refusals described above keep theirs.
