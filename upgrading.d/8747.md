## A keyed replay is refused across protocol revisions

**Startup:** no notice

**What you gain.** A replayed answer always matches the revision that asks for it. A
2026-07-28 client no longer receives a legacy answer whose public receipt fails to verify, and a
legacy client no longer receives members it never negotiated.

**What you lose.** Reusing one idempotency key for the same call under the other protocol
revision used to return the stored answer. On `/mcp` and stdio it now returns JSON-RPC error 409
(HTTP 409 on `/mcp`), with `data` `{"reason": "idempotency_era_mismatch", "stored_era",
"request_era", "already_executed": true}`.

**What you do.** Retry the refused call with the protocol revision it was first sent with; the
stored answer is served as before. Do not resend it under a new key: the call already ran, and a
new key would run it again. The direct route (`/mcp/{name}`) is unchanged.
