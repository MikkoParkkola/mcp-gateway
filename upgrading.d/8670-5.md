## A divergence record uses the runtime substrate type

**Startup:** no notice

**What you gain.** One substrate type. A divergence record names its two sides with the same spelling the `substrate_override` config key accepts, so the two can no longer drift apart.

**What you lose.** The path `mcp_gateway::runtime::SubstrateTag` no longer resolves. A `DivergenceRecord` you serialized with an earlier version, holding `GVisor` or `AppleVm`, no longer deserializes.

**What you do.** Replace `SubstrateTag` with `mcp_gateway::runtime::Substrate`; the variant names stay `GVisor` and `AppleVm`. To print a side, use `Substrate::name()`. The registry is in-memory only: the gateway stores no records, so there is nothing to migrate unless your own code saved serialized records.
