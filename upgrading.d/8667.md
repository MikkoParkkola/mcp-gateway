## One tool-usage row in the library

**Startup:** no notice

What you gain: one type per row. A user's saved tool profile holds the same
`ToolSuggestion` the live profile reports, and the dashboard's tools table
holds the same `stats::TopTool` that `gateway_get_stats` reports.

What you keep: every file. `profiles.json` and the ranking `usage.json` keep
their keys, field order and bytes; a tool row written before `last_used_secs`
existed still loads, as `None`.

What you lose: one name in the Rust library API.

| Removed | Use instead |
|---|---|
| `mcp_gateway::tool_profiles::persistence::PersistedToolUsage` | `mcp_gateway::tool_profiles::ToolSuggestion` |

The dashboard row `gateway::ui::ToolCallCount`, added on the 4.0 line and never
released, is folded into `stats::TopTool` the same way; the MIK-8370 entry
names `TopTool` directly.

What to do:

- Nothing, if you only run the gateway.
- In Rust code that links the library, rename `PersistedToolUsage` to
  `ToolSuggestion` and drop any `.into()` between the two.
