## YAML is checked before parsing

**Startup:** no notice

What changes for operators: YAML text from configuration, capability, skill,
trust-card, protocol-import, Kubernetes manifest and admin-UI paths is now
checked before it reaches the parser. Hostile nesting, alias expansion and
`%TAG` floods are refused in milliseconds instead of minutes or gigabytes.
Overhead is under 0.1 ms on shipped configuration and capability files,
linear in size (about 60 ns per byte).

What changes for anyone matching on error text: every YAML syntax error's
wording now comes from the guard. Line and column still point at the fault.
For example, a flow sequence left unclosed:

- before: `did not find expected ',' or ']' at line 4 column 1, while parsing a flow sequence at line 3 column 4`
- after: `YAML refused: unclosed bracket at line 3 column 4`

What changes for multi-document Kubernetes manifests: `documents()` is now
all-or-nothing. A stream with any refusal (syntax, depth, size, alias, `%TAG`
or expansion) is refused as a whole before any document is read, so
`mcp-gateway kubernetes plan` on a manifest whose first document has an
invalid name and whose later document is malformed now reports the later
document's syntax error instead of the first document's validation error:

- before: the first document's `InvalidName` for `--all` won.
- after: `YAML refused: unclosed bracket at line 6 column 7` wins.

What changes for multiline quoted values: a quoted value left unclosed, or
a quoted continuation indented no more than its key, is now refused. For example:
`fs:` with `description: "first line` on the next line and `more: text"`
at the same indent:
- before: loads today, folding to `first line more: text`.
- after: `YAML refused: quoted text is not closed, or continues with too little indentation, at line 3 column 3; close the quote, or indent the continuation lines, or use a block scalar (| or >)`
Fix: close the quote, or indent the continuation lines more than the key, or
use a block scalar (`|` or `>`).

The limits: 16 MiB per text, nesting to 128 levels, 64 aliases per stream,
64 `%TAG` directives per input, 64 MiB of alias expansion per document,
anchor and alias names in `[A-Za-z0-9_-]`, no anchor-name reuse within one
document, and no raw U+0085/U+2028/U+2029 line breaks.

What stays the same: every YAML file the backend accepted still loads with
the same value; only refused input changes, and it was refused before too
except above the limits.
