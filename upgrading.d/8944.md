## Windows saves keep a file's access list

**Startup:** no notice, a refused save is an error at save time, not at startup

**What you gain.** Before, a save replaced the file with one carrying its folder's inherited access list, so a file you had made owner-only became readable by every account the folder lets read. Capability files can hold literal tokens. A save now creates the replacement with the file's own list and checks it before writing any data.

**What stays the same.** A new file takes its folder's list, as before. A file whose list is inherited from its folder keeps getting that list. On a volume that keeps no access lists (FAT, exFAT) nothing changes.

**What can now be refused**, each with the file left untouched and a stable code in the message:

- `foreign-owner`: the file's owner is not the owner the gateway's own new files get in that folder. For a gateway running elevated that owner is Administrators, so its own files still save. Repair: give the file the owner the message names, or run the gateway as the file's owner.
- `acl-mismatch`: the list cannot be copied exactly, usually because the file was moved in from another folder and still carries that folder's inherited entries. The message names the first difference. Repair: `icacls <file> /reset`.
- `security-label`: the file, or the replacement the folder would give it, carries an integrity label or access policy the gateway cannot copy. Repair: remove the label or policy from the file or the folder.
- `undecodable-ace`, `descriptor-unreadable`, `volume-query-failed`: the list holds an entry type the gateway does not read, or the list or volume could not be read. Repair: as the message says.

**What you do.** Usually nothing. Follow the message for a refused save.
