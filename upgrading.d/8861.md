## Two security flags apply on reload; `environment` names the gateway

**Startup:** no notice

**What changes.** Turning `security.sanitize_input` or `security.ssrf_protection` on or off and
reloading the config changes the next request; before 4.0.0 the change waited for a restart and
the reload reported `security` as needing one. A change to only those two no longer does. A change
to any other `security` field still needs a restart and is still reported. A request that is in
flight when a reload lands keeps the values it started with. The hardened posture still forces
`ssrf_protection` on.

**The new key.** `environment` is an optional label such as `staging` or `prod` that the web UI
shows, so an operator can tell which gateway a window belongs to. Nothing can infer it, which is
why it is a setting rather than automatic. It applies on reload, and leaving it out shows no name.
A misspelt key is refused at load, as every unread key is.

**Also reported now.** A reload that changes only `idempotency`, `events`, or a `server` field
other than `host`, `port` and `public_url` is now reported as a change that needs a restart;
before, it was not reported at all.
