## An unminted keyed retry is refused on every route, the direct route included

**Startup:** no notice

**What changes.** On an optional (`required: false`) identity-propagation backend, a keyed retry whose per-caller mint now fails (or a passthrough retry that forwards no credential) is not served the stored result the first, per-user call produced. The direct `POST /mcp/{backend}` route now answers it as `/mcp` and stdio already did: HTTP 200 with JSON-RPC `-32603` "identity propagation minted no credential for backend '<server>'; a stored result is not served without one", not marked retryable, and nothing is sent to the backend. Previously the direct route served the stored per-user result under the static credential.

**Availability trade.** The direct route judges the retry, not the stored call. When an unminted call's cached answer has expired and only the execution store still holds it, its unminted retry is refused too, as on `/mcp`: the gateway never runs a keyed write a second time, so it refuses rather than guess. An unminted retry whose cached answer is still held is served as before.

**Signed calls.** Under `security.posture: hardened` the refused call's signing nonce stays spent. Retry with a fresh nonce and the original idempotency key: once the mint succeeds again, that retry is served the stored result, with nothing sent again.
