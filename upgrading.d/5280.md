## A refused signing envelope is recorded and follows the log's outage rule

**Startup:** no notice, nothing changes at startup

With message signing on, a `tools/call` whose id the answer cannot carry, or whose tool name changes when it is
sanitized, is refused before it reaches a tool. That refusal now leaves one audit record (outcome `denied`, kind
`syntax`), like the malformed-nonce refusal beside it. When the audit log fails closed and cannot be written, the
refusal answers that the log is unavailable (HTTP 503 on `/mcp`, `-32005` on both transports, with no id) where it
used to answer HTTP 400. Every other signing refusal already answers that way during an outage.
