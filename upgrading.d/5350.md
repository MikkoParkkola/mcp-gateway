## Local command errors print two lines

**Startup:** no notice, nothing changes at startup

When a local command fails, stderr now holds exactly two lines: `error: <what happened>`, then one line saying what
to do. Anything the command printed to stdout before failing stays. The exit code is 1, or 2 when the command was
called wrong, and `--json` does not change the error into JSON. This covers `init`, the `tls` commands, `doctor`,
`identity grants`, `import preview` and `import apply`, `ranking eval`, `setup wizard`, `setup export`, `stats`,
`upgrade` and `cap import-url`; the other local commands follow in a later release and keep their current output.

Exit codes that change:

- `doctor --shadow --shadow-format <unknown>`: 1 becomes 2.
- `tls issue-server` and `tls issue-client` with a `--ca-key` path that is not valid UTF-8: 1 becomes 2.
- `identity grants grant` and `identity grants revoke` with an argument that cannot be read (a timestamp that is not
  RFC3339, `--agent` together with `--any-agent`, a subject without `AUTHORITY:SUBJECT`): 1 becomes 2. A grants file
  that cannot be read or written still exits 1.
- `import preview` and `import apply` with `--format json`, when the result cannot be written as JSON: 0 becomes 1
  (the error was printed, but the command reported success).

Unchanged: `doctor` still exits 1 when its checks fail or its config does not load, with its report on stdout and
nothing on stderr, and `validate` keeps exit 2 for a file it cannot parse.

Two paths that exited 1 silently now say why: `setup export` when some client configs could not be written, and
`upgrade` without `--quiet` when keys it cannot remove keep the config from loading.

`cap import-url` now lists a capability file it could not write as a `FAIL` row on stdout, beside the `OK` rows,
instead of on stderr; stderr ends with the two error lines.
