## A task without the grant or admin standing is refused at submit

**Startup:** no notice

What you gain: a caller that may not run a tool cannot create a task for it.
The gateway no longer stores a task record or takes an idempotency key for a
call it will refuse, and the caller learns of the refusal at once.

What changes: submitting a task without the grant now returns the same error
as a direct call, instead of a task handle that later fails. This covers a
personal capability the caller holds no identity grant for, and an admin
capability called by a non-admin. The status, code and message are the
direct call's. The refused submit keeps no idempotency key, so retrying with
the same key after the grant is given starts a new task.

What to do: a client that read such a refusal from a task's terminal error
reads it from the submit response instead.
