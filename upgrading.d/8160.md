## stdio confirms destructive task calls, as HTTP does

**Startup:** no notice

What you gain: a destructive surfaced tool cannot be started as a stdio task
without the same confirmation an HTTP caller gives. Before this release
stdio admitted such a call as a task with no confirmation at all.

What changes: a modern `tools/call` with a `task` member, of a surfaced tool
whose catalogue entry is `destructiveHint: true` (or cannot be read), over a
stdio session with its task store open, is answered with the confirmation
question first. The grant is bound to the one stdio process that asked: a
grant from another process, or from HTTP, is refused. A retry of a task
already admitted returns that task's handle without asking again.

Calls without `task`, legacy-revision calls and non-surfaced tools are
unchanged, on stdio as on HTTP.

What to do: nothing, if your stdio client already answers confirmation
questions over HTTP. Otherwise answer the question, or call the tool without
`task`.
