## Revoke an API key through the UI API

**Startup:** no notice

`DELETE /ui/api/keys/{name}` requires gateway admin credentials and a JSON body
with `revision`; `expected_key_tag` optionally binds the intended identity and
is required when the named key is already absent. `If-Match` does not replace
the body revision. Revocation requires an available audit log and reports
success only after the audited write and confirmation that the selected
identities are absent from live authorization. The response contains `name`,
`revoked` and `revision`, never a secret. Self-revocation is supported; retain
another admin credential if you need continued access. No configuration
migration is required.
