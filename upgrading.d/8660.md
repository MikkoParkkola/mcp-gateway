## Redirects: five followed, and the CLI follows none

**Startup:** no notice

**What you lose.** A source that reached its content only after six or more redirects now stops at the
fifth: the registry install and the spec import with SSRF protection off used to follow ten. The registry
install also stops using an environment proxy, pins DNS to public addresses and gives up after 30 seconds.
`mcp-gateway stats`, the `mcp-gateway doctor` backend and runtime probes and
`mcp-gateway skills import <url>` no longer follow a redirect at all, so an `http://` URL that a
reverse proxy redirects to `https://`, or a GitHub page link that redirects to the raw file, now stops
there. Capability discovery that was silently redirected into a private address now reports an SSRF
refusal instead of finding nothing.

**What you gain.** One limit, the one every place already documented: five redirects followed, the
sixth refused. The OAuth client keeps its own limit for now. The CLI commands say exactly where the redirect went, for example
`the gateway URL redirected to https://gw.internal/mcp; point stats at the final URL`, instead of
failing on the page they landed on. `stats` also stops going through an environment proxy and gives
up after 10 seconds; `skills import` gives up after 30.

**What you do.** Use the URL the message names. A backend or spec behind more than five redirects
needs its final URL configured.
