## Per-key budgets apply only to API keys

**Startup:** prints a notice

**What you gain.** A `per_key` budget belongs to the API key it names. Before this
release, spend was charged under the caller's display name whatever the credential,
so the static bearer, named `bearer`, spent from the budget of an API key named
`bearer`, and any identity whose display name matched a `per_key` entry drew on it.

**What you lose.** A `per_key` entry that matched a caller other than an API key by
its display name stops applying to that caller: the static bearer (`bearer`), a
dashboard session (`dashboard`), an OIDC or key-server identity (its actor id), or
callers with auth off (`anonymous`). Their spend still counts in the gateway-wide
total, in `budgets.daily` and in `budgets.per_tool` limits, but is no longer listed or
limited per key.

**What you do.**

- Read the startup log: the gateway warns once for each `per_key` entry that names
  no configured API key, and for every entry when auth is off. Those entries limit
  no caller. An entry for an API key of that name keeps working.
- To keep a cap on the static bearer, the dashboard, an OIDC or key-server identity
  or auth-off callers, use `budgets.daily` (the gateway-wide daily limit) or a
  `budgets.per_tool` limit, or have the caller use an API key.
