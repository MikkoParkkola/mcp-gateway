## A budget added at restart counts the day's earlier spend

**Startup:** no notice; a call a newly budgeted name could not afford is refused as a budget refusal

A budget set for a tool or key for the first time by a config edit
applied at restart is charged the spend that name may already have
made that day in the shared overflow total, exactly as a budget added
by a live reload is. `costs.json` records the names budgeted since the
gateway started (`tool_owned`, `key_owned`) and the overflow total when
each row was created (`tool_born`, `key_born`). A file written before
these fields existed restores as before and seeds nothing. A 3.5.x
gateway reads a file 4.0 wrote: it ignores the new fields and keeps the
per-tool and per-key totals.
