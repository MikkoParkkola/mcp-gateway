## A stop's saves fit a container's stop grace

**Startup:** no notice

What you gain: a container stop no longer loses what the gateway recorded.
Docker and compose send SIGTERM, then kill the process 10 s later. The gateway
now saves its usage counts, tool transitions, call counters, spend and health
history about 20 ms after the stop signal and every second after that, until it
stops its backends. A kill loses at most what was recorded since the last save
landed: about a second, plus the time one write takes; a write slowed by the
disk can stretch that. Health and call-counter changes the backend stop itself
makes, after the last save, are not saved, as before. Before,
a client holding an event stream, or a request whose backend never answered,
held those saves back for the listener grace (17 s at the default
`server.shutdown_timeout` of 30 s), and a kill at 10 s lost that session's
records. Open event streams, `GET /mcp` and `subscriptions/listen`, now end at
the stop signal; a listen stream gets its graceful end.

What changes on disk: `usage.json`, `transitions.json` and the tool-profile file
are now replaced by rename, as the other state files already were, so a crash
or a kill during a save leaves the old file or the new one, never a cut one. The
new file takes the writing process's owner and the umask mode. On macOS an ACL
entry the directory passes on can apply, and the old file's own deny entries are
not carried over. Another hard link to the file keeps the old bytes.

What you lose: nothing for a gateway run as one user. A setup that hard-links
`usage.json` or `transitions.json`, or relies on another owner or on per-file
macOS ACL entries, has to set that up again after each save: during a stop, up to 1 save per
second.
