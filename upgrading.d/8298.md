## Patterns a section cannot match are refused

**Startup:** refuses to start, naming the entry and the replacement

Some sections match only a fixed grammar. A `*` anywhere else used to load as a
literal character, so the rule matched no tool or backend: a deny that denied
nothing, or an allow that granted nothing. Those entries are now refused, at
start-up and at hot reload, whether or not the section is enabled.

| Section | What it matches |
|---|---|
| `security.tool_policy.allow`, `.deny` | an exact tool name, or a trailing `prefix*` |
| `auth.api_keys[].allowed_tools`, `.denied_tools` | an exact tool name, or a trailing `prefix*` |
| `key_server.policies[].scopes.tools` | an exact tool name, or a trailing `prefix*` |
| `auth.api_keys[].backends` | an exact backend name, or `*` alone |
| `key_server.policies[].scopes.backends` | an exact backend name, or `*` alone |
| `agent_auth.agents[].scopes` | `tools:<backend>:<tool>:<action>`, backend and tool each an exact name or `*` alone, action `read`, `write`, `execute` or `*` |
| backend names (`backends.<name>`, `capabilities.name`) | may not contain `*` |

Suffix and contains patterns (`*_delete`, `*search*`) work in `routing_profiles`,
the mTLS policies and `secret_injection`, but not in the sections above. Copying
such a rule from those sections into a deny list used to leave it inert.

Configurations that loaded before and are now refused:

- a deny or allow entry such as `*_delete`, `a*b`, `*search*` or `**` in a tool
  list. A deny list can use the broader `a*`; otherwise list the exact tools.
- `key_server.policies[].scopes.backends: ["gh*"]`. It granted `github` to a
  client that named it in its request, and nothing to a client that did not,
  because the issued token's backend list matches exact names only. List the
  exact backends, or use `*`.
- a backend whose name contains `*`, including `capabilities.name`. Rename it.
- an agent scope that does not start with `tools:` (such as `surreal:*`). It was
  dropped silently and granted nothing; write `tools:surreal:*`.
- an agent scope whose action is not `read`, `write`, `execute` or `*` (such as
  `tools:gh:search:reed`). This one was **wider**, not inert: a misspelt action
  was read as `*` and granted read, write and execute. The scope parser now
  reads it as granting nothing, so an agent registered from code (not from the
  config file) with such a scope also loses that access.

The refusal is one line, for example:

```text
security.tool_policy.deny[2] = "*_delete" matches no tool: here '*' works only at the end, so there is no suffix match. List the exact tool names (suffix patterns work in routing_profiles, not here).
```
