## Saved state files keep their mode, and `~` follows one rule

**Startup:** no notice, a warning when no home directory can be determined and `security.transparency_log.path` starts with `~`

What you gain: the gateway rewrites its state files (cost totals, the skills
registry, the SIEM export cursor, the upgrade stamp, protocol-import drafts)
through one safe writer. A crash mid-save leaves the previous file, and a save
keeps the mode you set instead of resetting it.

What you keep: every file's contents and location. The mTLS key and OAuth
token files stay owner-only. Tool profiles, the ranking usage file and
transitions are still written in place, exactly as before.

What changes:

- A file you tightened stays tight. On Linux the full mode is kept when the
  gateway can keep the file's group and neither the file nor a default ACL
  on its folder adds an ACL; otherwise (including when that cannot be
  checked), and on macOS and other Unix systems, only the owner's permissions are kept.
  The result is never wider than what you set.
- Windows: a save keeps the file's own access list (see the item on Windows
  saves keeping a file's access list).
- `~` in a path means your home only as `~` or `~/...`. `~user/...` in
  `env_files` is no longer turned into a path under your own home; it is read
  verbatim (and so not found). `~//x` stays under your home in every path
  setting; it used to resolve to `/x` in some of them.
- A credential file path of exactly `~` now names your home directory.
- With no home directory, a bare `~` resolves to `./` (the current directory,
  as before, written differently), and the transparency log is written where
  the SIEM exporter reads it, relative to the working directory; one warning
  names the configured and the absolute path.

What to do:

- Nothing, to keep working.
- If an `env_files` entry used `~user/...`, write the full path.
