## Firewall rules the load refuses: no longer published by a reload or a write

**Startup:** no notice, a firewall-off start logs one warning per rule the firewall-on load refuses

**Who is affected.** Operators whose `security.firewall.rules` hold a rule the firewall-on load refuses: a `match` or scope entry that is not a valid glob, an empty `servers`, `keys` or `except` list, an exception that sets no field, a `keys` or exception `key` entry that names no configured API key (or any key reference while API-key authentication is off), or a folder rule (`allowed_roots`, `path_args`) the load refuses.

**Before.** `security.firewall.enabled` takes effect only on a restart, but a reload's rules join the running firewall at once. A reload or a write whose file said `enabled: false` skipped the rule checks, so it could put such a rule into a running firewall, where it blocked its scan types on every call or applied to no caller. A reload turning `auth.enabled` on (which also takes effect only on a restart) could add a rule scoped to an API key that no caller could carry until the restart.

**After.** While the firewall runs, a reload carrying such a rule is refused, whatever the file says about `enabled`, naming `security.firewall.rules[i]`; the running rules stay. A key reference is also refused while the running gateway has no API-key authentication, even when the reloaded file turns it on. A config write (the web UI, the reload write API, a CLI edit) that adds or changes such a rule is refused whether or not the firewall runs; the file is left unchanged. A write that changes something else keeps a rule already in the file as it is. `mcp-gateway init` and the `upgrade` URL rewrite carry the file through: they keep such a rule byte for byte, log one warning naming it, and succeed. A load with the firewall off still takes the file and logs one warning per such rule. The Policies screen's read model marks each such rule with the load's message and how it compiles meanwhile. A startup with the firewall on refuses such a rule, as before.

**What you do.** Fix or remove each rule a warning names. If a reload is refused while the firewall runs, fix or remove the rule, or set `security.firewall.enabled: false` and restart the gateway. If a reload is refused because the running gateway has no API-key authentication, remove the keyed reference, or restart the gateway so `auth.enabled` takes effect.
