## A CLI config write refuses a write the gateway left pending

**Startup:** no notice

**Who is affected.** Operators who edit the config with the CLI while a gateway runs on it. When the gateway's own config write fails and its rollback fails too, it leaves a replace journal next to `gateway.yaml` (`.gateway.yaml.replace-journal`, with the original staged beside it).

**Before.** The next CLI write put the original back, then made its edit, and nothing reached the gateway's audit log.

**After.** The CLI write stops with "Not saved: … has a write the gateway left pending …", changes nothing, and keeps the journal and the staged original.

**What you do.** Start or reload the gateway, which recovers the pending write, then run the command again. If a gateway that keeps an audit log is running, reload it rather than restarting: the reload records the recovery in the audit log.
