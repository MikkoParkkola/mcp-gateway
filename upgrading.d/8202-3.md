## A clock before 1970: undated cost, profile and breaker records, durable upstream cancels

**Startup:** no notice

What you gain: on a host whose clock reads before 1970 (a dead RTC, an unsynced VM), cost accounting, tool profiles and circuit breakers no longer stamp 0 or judge windows they cannot date, and an upstream cancel claimed while the clock is dark is no longer lost when the gateway restarts. Idle pool and breaker timing now run on the monotonic clock, so a dark wall clock neither hides nor fakes idleness.

What changes:
- Cost records carry `timestamp: Option<u64>`: `None` where the read failed. An undated call still counts in the lifetime sums, but enters no time window, and a key with no dated spend is never swept as idle.
- Per-key rolling windows are `Option`: `WindowStats.tokens` and `WindowStats.cost_usd` are `None` where the clock cannot date them. (`BudgetStatus`, which this release first gave an `Unknown` variant, is removed in the same release; see "The per-key rolling budget that nothing enforced is gone".) Session starts (`SessionCost::started_at`, `SessionCostSnapshot::started_at`) are `Option<u64>` the same way.
- The budget enforcer's UI snapshot carries `taken_at: Option<u64>`; the cost-save path keeps a concrete reading, so `saved_at` in `costs.json` is always dated. The dashboard's cost cells render "unknown" where the API reports `null`.
- Tool profiles carry `created_at: Option<u64>` (`ToolProfile`, `ProfileSnapshot`) and `last_used_secs: Option<u64>` (`ToolSuggestion`). The persisted forms change the same way: `tool_profiles::persistence::PersistedUserProfile::created_at` and each persisted tool row's `last_used_secs` are `Option<u64>` (the row type is `ToolSuggestion` since MIK-8667; see that entry). Persisted profiles read both a number and `null` for those fields, so files written before this change still load. An undated entry never sorts as the most recent: at equal call counts it sorts after dated entries.
- `CircuitBreakerStats::last_trip_ms` is `Option<u64>`: `None` for a trip made while dark (or no trip yet). The breaker-status JSON reports `null` there, the error text reads "an unknown time ago", and the monotonic `retry_after_ms` is still reported.
- Pool idle timing and circuit-breaker open-state timing run on the monotonic clock. Behaviour on a correct clock is unchanged, except that per-user idle eviction with a sub-second TTL now measures the TTL instead of evicting every slot.
- An upstream cancel claimed while the store clock reads before 1970 is written to the task row undated and sent exactly once when the clock reads, surviving a restart in between. Retention holds a cancelled row past its TTL while that undated upstream cancel is still unsent and an upstream adapter is installed to send it, logging WARN once per row (`held past its ttl: its upstream cancel is unsent (clock before 1970)`, with the task id) and incrementing `mcp_task_cancel_held_past_ttl_total` once per row.
- Removed: the public `cost_accounting::persistence::now_secs` helper. Read your own clock; the gateway reads its clock through its internal clock module.
- Removed: the public `security::message_signing::MessageSigner::sign_response`, the v1 response signer. Nothing in the gateway called it, and it stamped `ts` 0 on a clock before 1970. Responses are signed by the v2 JSON-RPC envelope signer, which reads the clock through the gateway's clock module.
