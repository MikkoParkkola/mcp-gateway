change: A tool the caller may not see now answers exactly as a tool that does not exist. On a backend that means its tool policy or key scope denies it, its routing profile excludes it, its input schema is invalid, or its description failed the poisoning check. For a capability it means an admin-only capability for a non-admin, a personal capability with no grant, a key scope or a routing profile that excludes it. This holds on `/mcp` `gateway_invoke` and `gateway_execute` steps, stdio and `/mcp/{name}`; such a call is scanned by the request firewall and counted by its budget and anomaly controls like any other, writes the audit records a missing name writes, and is never dispatched; in Standard mode a call to a tool the backend's complete tool list does not declare is answered by the gateway instead of being forwarded; on `/mcp/{name}` the caller's credential is resolved only after authorization and the request firewall
action: Treat the missing-tool answer as "this caller has no such tool" and read the audit log for the reason; give backends that serve tools their list does not declare `input_schema_enforcement: Off`

## A tool you may not see answers as a tool that does not exist

**Startup:** no notice

**Refusals no longer name the hidden tool.**
- What you lose: a call to a tool your listings hide no longer gets a refusal naming why ("blocked by
  client policy", "not available in the routing profile", "requires an admin credential", "Identity grant
  denied", "is withheld: its description failed ..."). It gets exactly what a name the backend does not
  list gets: on `gateway_invoke` and `gateway_execute`, "the backend does not list a tool named ..." (or,
  when the gateway could not read the whole list, the truncated-list or unavailable text); for a
  capability, "Tool not found"; on a per-user backend, -32601 "Unknown tool".
- What stays the same: nothing hidden is ever sent to the backend.
- What you gain: a caller can no longer probe which tools exist by the refusal it gets, firewall-tripping
  arguments included.
- What you do: read the audit log, not the client's answer, to see why a call was refused (see below for
  what each refusal records).

**A refusal that applies to the caller, not the tool, also answers as a missing tool.**
- What you lose: when authorization refuses the caller for every tool (for example, agent authentication
  is enabled and the request carries no validated agent identity), a named call now answers as a missing
  tool, not with the 403 that named the cause.
- What you do: if every tool a client names is "missing", check the client's credentials and the audit
  log before the tool configuration.

**What a hidden call writes to the audit log.**
- A hidden backend tool on `gateway_invoke`, a `gateway_execute` step, stdio or `/mcp/{name}` writes one
  invocation record, `denied` with the real reason's code, where a missing name writes its own. With auth
  enabled (where the audit log fails closed), a write that fails answers 503 for both, so an outage cannot
  tell them apart.
- A hidden capability writes the invocation records an undefined one writes: none. An admin-rule or grant
  refusal stays in the grant decision record.
- A routing-profile refusal writes no invocation record, as before this change.
- Written best-effort: the identity-grant decision note of such a call, and the route's refusal record of
  a hidden surfaced name. A missing name writes neither, so a failed write is counted in
  `mcp_audit_append_failures_total` and logged at warn with the call's trace id, server and tool, never
  answered.
- What you do: alert on `mcp_audit_append_failures_total`, as for any audit gap.

**A reused idempotency key never reveals a hidden step.**
- What changes: a `gateway_execute` key used again with other arguments is answered with the key
  mismatch (409) even when one of its steps is hidden, as when the step does not exist. An exact replay
  gets a hidden step's current refusal only if the first run dispatched that step (its caller held it
  then); a step the first run answered as missing replays the stored answer. Results stored before this
  version carry no list of dispatched steps and keep the refusal, as before. A key reused after the
  session's routing profile changed is a mismatch too.
- What you do: use a new key for a new plan.

**A tool withheld for an invalid input schema is never dispatched.**
- What you lose: nothing a listing showed. Such a tool was hidden from every listing but could still be
  called by name on `gateway_invoke`, `gateway_execute`, stdio and `/mcp/{name}`; it is now answered as a
  missing name and not sent.
- What you do: fix the backend's schema to use the tool.

**The request firewall's stateful controls count withheld calls.**
- What you lose: a call to a hidden tool now reaches the request firewall, so it counts toward the
  caller's call budget and anomaly score, as a call to a missing name always has.
- What you do: nothing.

**In Standard mode, a call to a tool the backend's complete tool list doesn't declare is now answered by
the gateway instead of being forwarded. Backends that serve undeclared tools need
input_schema_enforcement: Off.**
- What stays the same: a truncated list, or one the gateway could not read, still forwards an undeclared
  name in Standard mode. Closed mode is unchanged.
- Known differences: with `input_schema_enforcement: Off`, and in Standard mode on a truncated or unread
  list, a missing name is forwarded while a hidden one is answered by the gateway. Under `Off` a tool
  hidden for an invalid schema is known only once the gateway has read that caller's tool list; before
  that it is forwarded like any unlisted name. On a per-user backend whose tool-list read fails, a missing
  name answers backend-unavailable while a hidden one answers -32601. These differ only during truncation
  or an outage, or by the operator's choice of `Off`.

**On `/mcp/{name}`, the caller's credential is resolved after authorization and the firewall.**
- What you lose: nothing.
- What you gain: a call the caller may not make, or that the firewall blocks, no longer makes the gateway
  resolve or mint the caller's credential.
- What you do: nothing.
