## Try a tool from the web UI

**Startup:** no notice

What you gain: an admin can run a tool from the web UI and see its result,
latency and receipt, under the same gates, budgets, firewall and audit as an
MCP call.

What you may notice:

- A tool runs without confirmation only when its server declared it
  read-only in the caller's own catalogue as of its last `tools/list`. On a
  backend with per-user identity propagation, a caller whose own catalogue
  has not been listed yet is asked to confirm, even for a tool that is
  read-only for others.
- Where message signing requires a nonce, the route does not mint one on the
  caller's behalf, so web UI tool calls are refused (403, reason `signing_required`) and
  nothing runs; use a signing client.
- At most 4 web UI tool calls run at once per gateway (a fixed limit, not a
  setting); the next is refused (403, reason `busy`) and nothing runs.
- Try runs tools that need no follow-up input. A tool that stops to ask a
  question (elicitation) or to request sampling cannot finish from the web
  UI: the route answers a 5xx ("the tool may have run"). Run such tools from
  an MCP client.
- A call that has not answered within 25 seconds is answered 504; it keeps
  running, holds a drain slot until it ends, and its records are still
  written.
