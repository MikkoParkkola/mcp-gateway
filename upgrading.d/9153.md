## Admin from SSO uses the role mapping a request arrived under

**Startup:** no notice

What changes: an OIDC caller authenticated through the key server (a
temporary token or a delegated bearer) is a gateway admin when
`control_plane.role_mapping` maps it to `admin`. That decision now uses the
mapping the request arrived under, on every route, as the rest of the
request's checks already did. Before, it read the mapping current when
authentication ran, so a reload landing between a request's arrival and its
authentication could make that one request admin by the new mapping while
its other checks used the old one. A request that arrives after the reload
gets the new mapping.

Unchanged: an open stream's later deliveries are judged by the mapping
current at each delivery, so a reload that removes an admin rule still stops
an open stream.
