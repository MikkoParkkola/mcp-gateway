## The other local commands print errors in two lines

**Startup:** no notice, nothing changes at startup

Every local command now fails as `init`, `doctor` and the other commands of the first note do: stderr ends with two
lines, `error: <what happened>`, then one line saying what to do, and the exit code is 1, or 2 when the command was
called wrong. This adds `accounts`, `add`, `remove`, `list`, `get`, `audit verify`, `audit show`, the `cap` commands,
`hash-key`, `kubernetes`, `skills`, `tool`, `trust`, `validate` and `provenance public-key`. A note a command prints
first, such as a skipped path or a tool it could not write, stays above the two lines.

Exit codes that change:

- `kubernetes controller --watch` with `--interval-seconds 0`: 1 becomes 2.
- `accounts migrate-credentials` without `--config`: 1 becomes 2.
- `accounts init-store` without `--config`: 1 becomes 2.
- `cap test` with `--args` that is not valid JSON: 1 becomes 2.
- `trust lab evaluate --update-baseline-registry` without `--baseline-registry`: 1 becomes 2.
- `tool invoke` with `--args` that is not valid JSON: 1 becomes 2.

`trust lab evaluate` now refuses the missing `--baseline-registry` before it evaluates, so a `--write-baseline` file
is no longer written first. `tool invoke` with stdin that is not JSON, or a `key=value` without `=`, still exits 1.

The `trust` commands with `--format json` exit 1 with the two error lines when the report cannot be written as JSON;
before, they printed the error and exited 0.

Unchanged: a verdict keeps its code and its output. `validate` exits 1 for findings and 2 for a file it cannot
parse; a failed `audit verify` chain, `hash-key --verify` with a different key (`hash-key: the key does not match`),
a blocked `kubernetes` plan or controller report, a failed `trust validate`, an enforced `trust lab evaluate` block,
and an `INVALID` `provenance verify` or `audit verify --export` exit 1. Exits that were 2 stay 2: `hash-key`'s input
refusals, `add` with `-e NAME=value`, a credential in `--command` or `--url` or an unreadable `--env-file`,
`cap import` with an `--auth-key` that is not a reference, and `validate` with no capability file.
