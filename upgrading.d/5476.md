## Activity: invalid calls move from blocked to failed

**Startup:** no notice

**Who is affected.** Operators who filter Activity by outcome, or export it,
and scripts that read the bundled UI's Activity API with `outcome=blocked`.

**Before.** `outcome=blocked` listed calls a rule refused and invalid calls
(an unknown tool name, arguments that did not parse). The counters already
counted invalid calls as errors, so the blocked number and the blocked list
held different sets. A response the firewall refused was recorded as an
error on the direct route and as `ok` on `/mcp`.

**After.** `outcome=blocked` lists only calls a rule refused: a policy, a
scope or grant check, or the firewall, on the request or on its answer.
Invalid calls are listed under `outcome=failed`, in the list, its counts and
both exports. A refused answer is recorded `denied` with code -32600 on both
routes and counted as a block.

**What to do.** Read invalid calls under `outcome=failed`.
