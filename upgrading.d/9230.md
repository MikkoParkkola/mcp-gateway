## Backend routes write through the audited config writer

**Startup:** no notice

- What changes: the web UI's backend add, remove and update routes splice one backend into gateway.yaml in place or refuse, under the same writer as discovery adopt.
  - With no gateway.yaml they answer 409 `no_config_file` with the message "no gateway.yaml exists yet; create one with `mcp-gateway init --profile local` (see QUICKSTART), then retry", and write nothing. Discovery adopt's 409 now carries the same message. Run `mcp-gateway init --profile local`, then retry.
  - A reload that refuses the new bytes now rolls gateway.yaml back to the old bytes. It used to leave the new bytes written and answer 500.
  - On a gateway with an audit log, each edit records `config_backend_intent` first, and a refused append answers 500 and writes nothing. An unchanged edit also records it, and a refused append stops its reload.
  - With auth on and no audit log they answer 503 `audit_log_required`. With no config reload running they answer 503.
  - `ReloadContext::mutate_and_reload_outcome(_within)`, `write_and_reload_outcome(_within)` and `mutate_config_and_reload` with a reload context refuse on a gateway with an audit log or auth on.
- What stays: the routes' own answers (201, 204 or 200 on success, 404 for an unknown backend, 409 for a duplicate or an edit that cannot be made in place, 422 for an unresolved secret reference), and the CLI writers.
