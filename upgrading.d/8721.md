change: `gateway_list_servers` reports `tools_count` as null, not 0, while a backend's tools are not known to the caller (`tools_known: false`)
action: A client that read `tools_count == 0` as "no tools" should check `tools_known`, or treat null as "not known yet"; a number, including 0, still means a known count

## `gateway_list_servers` `tools_count` is null until the tools are known

**Startup:** no notice

**What you gain.** An agent no longer mistakes a backend whose tools have not
been loaded yet, or that it cannot see, for a backend with no tools, and gives
up on it.

**What you lose.** `tools_count` is no longer always a number: it is JSON
`null` whenever `tools_known` is `false`. A client that parsed it as an integer
must accept null.

**What you do.** Treat a null `tools_count` as "not known yet" and read
`tools_known`; call `gateway_list_tools(server)` to load a backend you are
allowed to use. A `0` still means a backend that is known and serves no tools.
