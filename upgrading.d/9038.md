## A refused backend redirect fails once, without a retry

**Startup:** no notice

**What you gain.** A backend's HTTP answer can redirect the gateway. The gateway follows a redirect only to the same origin, and only to an address the SSRF rule allows. A refused redirect was reported as a transport error, so the failsafe retried the call and sent the request to the backend again, to be refused again. It is now a refusal, which is not retried.

**What changes.** The call fails once, with `-32600`:

- a redirect to another origin: `redirect target is cross-origin to the transport base URL; refusing to replay per-user credentials to a different origin`, with the base and target URLs;
- a redirect to a loopback, private or metadata address: `SSRF blocked` and the reason.

Neither is retried.

**What you do.** Nothing. A backend whose endpoint redirects to another origin never worked through the gateway; configure the URL it redirects to.
