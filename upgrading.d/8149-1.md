## stdio honours `security.sanitize_input`

**Startup:** no notice; the setting is read when stdio starts

What you gain: one meaning for `security.sanitize_input` on every transport.
Before this release only `/mcp` applied it; a stdio client's requests reached
the backend as sent, whatever the setting said.

What changes: with the setting on, stdio sanitizes each request at intake,
in the same place and order as `/mcp` (before the signature, the shape and
any check reads it). A string carrying a NUL byte is refused with `-32600`
"Input contains null bytes which are not allowed"; other control characters
are stripped. With the setting off (the default) nothing changes.

What to do:

- Nothing, if the setting is off, or your stdio clients send plain text.
- Otherwise, if a stdio tool call must carry a NUL byte or a control
  character, encode it (base64, an escape the backend decodes), or set
  `security.sanitize_input: false`.
