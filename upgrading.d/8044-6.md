## The examples show only the keys a normal setup needs

**Startup:** no notice

The shipped examples and the user docs now list only the keys a normal
setup needs. A key that the gateway tunes itself is hidden: it still loads
and still applies, and `mcp-gateway doctor` lists it when a config sets it.

- What you lose: nothing in a config you already have. An example you copy
  afresh no longer sets these values, so the default applies:

  | Example | Setting | The example set | Default now |
  |---|---|---|---|
  | `gateway.example.yaml`, `examples/gateway-full.yaml`, `examples/servers.yaml` | backend health-check interval | 30 s | 10 s |
  | `gateway.example.yaml` | first retry delay | 0 s | 100 ms |
  | `examples/config-fulcrum.yaml`, `examples/config-bundles.yaml` | graceful shutdown window | 5 s | 30 s |
  | `examples/gateway-full.yaml`, `examples/config-fulcrum.yaml`, `examples/config-bundles.yaml` | name of the capability backend, which prefixes capability tools | `fulcrum` or `my-gateway` | `gateway` |
  | `examples/token-exchange-live.yaml` | lifetime of a token the key server issues | 300 s | 3600 s |
  | `examples/token-exchange-live.yaml` | OIDC discovery for the demo issuer | off | on, falling back to the issuer's JWKS |
  | `examples/per-client-tool-scopes.yaml` | successes that close a half-open circuit breaker | 2 | 3 |

- What stays the same: every other removed value was already the default.
  `http_url` in the examples became `url`, which reaches the same backend.
- What you gain: examples and docs that show only what a normal setup sets.
- What you do: nothing, unless you copy an example afresh and want one of the
  old values. Then set it in your own config; the key still works.

`examples/circuit-breaker.yaml` is removed: with its hidden keys gone, it showed
nothing.
