## Remote commands take `--gateway`, or `MCP_GATEWAY_URL`

**Startup:** no notice, nothing changes at startup

What you gain: one name for "which gateway" on every remote command, and an
environment variable, so a shell or a service can set it once. The order is
the flag, then `MCP_GATEWAY_URL`, then the address in `--config`
(`docs/CLI.md`, "Where remote commands send their request").

What you keep: `--url` and `-u` are hidden aliases of `--gateway` on these five
commands, so existing scripts run unchanged. `add --url` is a different flag
(the backend's own address) and is untouched.

`cap import --auth-key` now checks its value before writing anything: it takes
the credential references the gateway reads (`env:NAME`, `keychain:NAME`,
`oauth:PROVIDER`, `file:PATH`, `{env.NAME}` or a variable `NAME`), and refuses
anything else with exit 2, never repeating the value.
