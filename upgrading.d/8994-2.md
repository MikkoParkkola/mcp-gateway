## A required identity binding's per-user sends recheck the user's credential each time

**Startup:** no notice

- What changes:
  - A backend whose identity binding is required rechecks, before EACH send of a user's call, that the user's credential may still be sent. A managed account's grant is rechecked through its custody; any other credential is checked against its published expiry, and a JWT's own `exp` may only shorten that.
  - A grant revoked during a call refuses the call's next send (a retry, a session-expiry re-handshake) and closes that user's session. A token refreshed during a call refuses only that call; the user's next call is served.
  - On an A2A backend with a required binding, a user's own session sends no static header and no credentials written into `a2a_url`, fetches the agent card under the user's credential, and sends nothing once the user's call has ended: a task left running at the agent is not cancelled by the gateway.
- A legacy SSE stream that drops between a user's calls stays closed until that user's next call reopens it, so server notifications sent while it is closed are not received.
- What stays: an optional binding and every backend's shared session are unchanged.
- Residual: consent withdrawn between a send's custody release and its one account read is caught by the user's next call, not that send.
