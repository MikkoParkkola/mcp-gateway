## `keychain:` is a secret reference prefix

**Startup:** no notice; refuses to start

gateway.yaml secrets accept `env:NAME` and `file:/abs/path` references. 4.0.0 adds `keychain:NAME`, which names an OS keychain entry (ADR-028). A literal secret that happens to start with `keychain:` is now read as such a reference.

- What you lose: a literal secret spelled `keychain:...`.
- What you gain: secrets kept in the OS keychain, referenced by name.
- What you do: if a literal secret starts with `keychain:`, put it in an env file and reference it as `env:NAME`, or in an owner-only file referenced as `file:/abs/path`.

Before downgrading below 4.0.0, convert every `keychain:` reference to `env:` or `file:`. Older releases read `keychain:NAME` as the literal secret.
