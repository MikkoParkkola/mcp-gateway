change: The library's whole-file config writers are deprecated; `edit_config` and `edit_config_text` replace them
action: Library users only — move `write_config` calls to `edit_config`, `write_config_text` to `edit_config_text`, and `write_config_and_reload[_outcome]` to `mutate_config_and_reload`

## Whole-file config writers are deprecated in the library

**Startup:** no notice, a library API change rather than a change to running behaviour

**What you lose.** Nothing yet. `config_persistence::write_config`,
`config_persistence::write_config_text`, `config_reload::write_config_and_reload` and
`config_reload::write_config_and_reload_outcome` still work, but they now raise a deprecation
warning and are planned for removal in 5.0. Each replaces `gateway.yaml` from a copy the caller
took earlier. A change another writer made after that copy is lost, and nothing reports it.

**What you gain.** `config_persistence::edit_config(path, mode, edit)` loads the file, runs your
edit and writes the result under one hold of the config lock, so no other writer's change is
lost. It keeps the file's comments where it can, and returns the comment lines it had to drop.
`CommentLoss::Refuse` refuses a write that would drop comments, and `CommentLoss::Rewrite`
rewrites the whole file. `config_persistence::edit_config_text(path, edit)` does the same for an
edit made on the file's text, and refuses text that does not parse as a config (a parse check, not a full
validation).

**What you do.** Only if you call the library from Rust code. Pass your change as a closure:
`edit_config(path, CommentLoss::Refuse, |config| { /* change config */ Ok(()) })` in place of
loading the config, changing it and calling `write_config`. From async code, use
`mutate_config_and_reload`. The `mcp-gateway` command and its config files need no change.
