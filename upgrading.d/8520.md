## Surfaced tools reload without a restart

**Startup:** no notice

Editing `meta_mcp.surfaced_tools` used to be reported as restart-pending. A
reload now applies it: the list is validated as at startup, swapped in, and
announced to listeners with one `tools/list_changed` when it changed.

What you lose:

- **A queued or parked surfaced task can be refused.** A task records the
  server its surfaced name pointed to when it was created. If a reload moves
  that name to another server, or removes it, before the task runs or
  resumes, the task settles with "surfaced target changed since the task was
  created" (outcome `not_executed`) and no backend is called. Call the tool
  again to run it on the new server.
- **A downgrade cannot read parked surfaced tasks written by this version.**
  A parked surfaced task's input round now carries a `surfacedServer` field,
  and an earlier 4.0 build refuses a round with a field it does not know.
  Before downgrading, let parked surfaced tasks finish, or cancel them.

What you gain: surfaced tools change without a restart, and a task never runs
on a server other than the one it was admitted for.

A task parked by an earlier build carries no recorded server and resumes on
the live surfaced map, as before.
