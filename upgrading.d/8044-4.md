## Settings that now derive their values: refresh buffer, JWKS fallback, capability directories

**Startup:** no notice

**An unset OAuth refresh buffer follows the token's lifetime.**
- What you lose: nothing you set. A `token_refresh_buffer_secs` you set is used as before.
- What stays the same: a token with no stated lifetime, and every token shorter than 50 minutes, refreshes 300 s before expiry, as before. A token shorter than 300 s refreshes at every check, as it did.
- What you gain: a long-lived token refreshes at 10 % of its lifetime before expiry (a 24-hour token about 2.4 hours early), so one slow refresh does not leave it expired.
- What you do: nothing. Remove `token_refresh_buffer_secs` unless you need a fixed value.

**A key server provider falls back to the issuer's JWKS when discovery cannot be reached.**
- What you lose: nothing. A discovery document that answers but fails its checks (issuer mismatch, a cleartext `jwks_uri` off this machine) is still refused, and an explicit `discovery_url` that fails is still an error.
- What stays the same: `jwks_uri` overrides both; `auto_discover: false` goes straight to `{issuer}/.well-known/jwks.json`.
- What you gain: when the derived discovery URL cannot be reached (connection error, timeout, a non-2xx status, a body that is not a discovery document), keys come from `{issuer}/.well-known/jwks.json`. The fallback stands at most five minutes before discovery is tried again, and is logged once.
- What you do: nothing.

**The local capability commands read the directories the gateway serves.**
- What you lose: without `-C` or `MCP_GATEWAY_CAPABILITIES`, `tool list`, `tool inspect`, `tool invoke`, `tool completions` and `skills generate` no longer read `./capabilities` when a gateway config names other directories. A config that does not load now stops them with "could not load <file>; run `mcp-gateway doctor --config <file>` to see why", and an explicit `--config` naming a missing file is an error.
- What stays the same: `-C` and `MCP_GATEWAY_CAPABILITIES` still name one directory and win. With no config at all, `./capabilities` is read, as before.
- What you gain: the commands list, inspect and run the same catalogue the gateway serves: every configured directory in order (env overlay and `${VAR}` included; a later definition of a name wins; a missing directory is warned about and skipped). `tool completions` now also reads `.yml` files.
- What you do: pass `-C <dir>` where a script relied on `./capabilities` beside a config that names other directories.
