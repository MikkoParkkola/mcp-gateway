## A malformed CLI argument template is refused when the capability loads

**Startup:** no notice; a capability file with a malformed CLI argument template is refused when it loads

**What you lose.** A CLI capability whose `args`, `each`, `json` or `stdin` template breaks a
rule loaded on earlier builds, was listed and searchable, and failed every call. It is now
refused when it loads, and it is left out of the registry index. The rules are the ones a call
already enforced: one placeholder per argument; a parameter only as the value of a fixed option
(`--to={to}`) before `--`; an `each` as one bound `--x={item}`; one placeholder per JSON or
stdin string.

**What you gain.** A broken definition surfaces when it loads, with the message its first call
would have given and the provider it is under, instead of as a call error the caller cannot fix.

**What you do.** Nothing, unless a private CLI capability is refused at load. Then fix the
template the message names. No shipped capability is affected.
