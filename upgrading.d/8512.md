## `mcp-gateway doctor` warns about deprecated npm pins

**Startup:** no notice

What you gain: doctor tells you when a stdio backend pins a registry npm
package to a version npm marks deprecated, in npm's own words, with the
registry's current version as the fix. Until now an old pin was silent:
the backend kept working on a version its publisher had retired.

Who is affected: anyone who runs `mcp-gateway doctor` with a stdio backend
whose command pins a registry package through `npx`. Doctor now sends
those package names, and only those names, to registry.npmjs.org; your
backend names, pinned versions and settings stay on the machine, and npm
sees this host's IP address. A failed or slow lookup prints nothing and
never fails doctor.

What to do:

- Nothing, to use the check.
- To skip the lookup, pass `--no-registry-check`, set
  `MCP_GATEWAY_DOCTOR_NO_REGISTRY_CHECK=1`, or use
  `security.posture: hardened`. This skips the gateway's own npm registry lookup; it does not stop npx or other servers started by --start-stdio from contacting npm, so air-gapped hosts should not use --start-stdio.
- When doctor warns, edit the pin in that backend's command to the version
  the hint names. For `memory`, follow the hint's copy-first steps so the
  graph survives the move.
