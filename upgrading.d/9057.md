change: The gateway's own refusals count as never sent, are not retried, and keep their code in a chain
action: None, unless your code reads Error::is_pre_dispatch() for a refusal

## A gateway refusal counts as never sent

**Startup:** no notice

**What changes.** `Error::is_pre_dispatch()` returns `true` for `Error::Forbidden` and `Error::GatewayRefused`: both are raised before the request reaches the backend. A refused call releases its idempotency key, so a same-key retry after the cause is fixed runs. A playbook or chain that ran a step before the refusal keeps its key: a same-key retry is answered from the stored result.

A playbook step under `on_error: retry` that meets a gateway refusal is tried once. A chain that ends on a gateway refusal answers with that refusal's code (for example -32000), not -32603.

**What you do.** If your code reads `is_pre_dispatch()` to decide whether a call may have run, a refusal now reads "not sent". For a playbook or chain, that describes the refused request only; an earlier step of the same run may have run.
