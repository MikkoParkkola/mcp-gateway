## Discovered secrets go to the secret store

**Startup:** no notice

**What changes.** `mcp-gateway cap discover --write-config` used to copy every env and header value from another app's MCP config into gateway.yaml as text. A literal value now goes to the secret store chosen by `secrets.store`, and the file holds its reference; a `${NAME}` template and an empty value are copied as written. A server is skipped, with each reason and field named on stderr (never a value), when its name is the capabilities name or not a valid backend name, or when the gateway could not run it exactly as the client does: a client-only `${input:...}` value, literal text beside a template, a template with a literal default, or a URL with a password, query or fragment. Command arguments are copied as written: move a secret out of a server's arguments before writing it. When no server can be written, nothing is written and the command exits non-zero.
