## Passthrough backends: event subscribers lease their own token

**Startup:** no notice, a subscription on a passthrough backend waits for its lease

**What you lose.** Nothing that worked before: backend upstream events on a `passthrough` backend
were refused in earlier 4.0 builds. INV-4 ("passthrough stores nothing") gains one scoped
exception, below.

**What you gain.** A subscriber of `backend.<name>.*` events on a `passthrough` backend gets them,
observed with their own backend credential. Subscribing alone starts nothing: the subscription
waits, sending nothing to the backend, until the subscriber calls `events/lease` on
`POST /mcp/{name}` with `{"subscription": <the subscription's id>}` and their token in
`x-mcp-passthrough-authorization`. The gateway answers that request itself; the backend never sees
it.

The token is held **in memory only**, for that one subscription's listener. It is never written
to disk, a log, a snapshot or an answer, and it is wiped when the subscriber's last subscription
on the backend ends, when the token or subscription expires, after at most 12 hours, on a `401`
from the backend (state `credential_rejected`), when the backend's identity configuration
changes, when the subscriber's gateway credential is revoked, and on restart (subscriptions then
wait for a new lease). A new lease replaces the old one.

A lease is refused with `-32014` when the token is not a JWT with a numeric `exp`
(`passthrough_token_no_expiry`), expires within a minute (`passthrough_token_expired`), or when
the gateway cannot disable core dumps (`core_dump_guard_unavailable`, with `detail`
`setrlimit_core`, `prctl_dumpable` or `platform_unsupported`). Before its first lease the gateway
sets its core-file limit to zero and, on Linux, marks itself not dumpable; on Windows leases are
refused. Admins see each held credential, never the token, at `GET /ui/api/events/leases`.

**What you do.** Have each subscriber send `events/lease` after subscribing and before its token
expires. Swap is the host's: run the gateway with encrypted swap (dm-crypt or zram) or none;
`mcp-gateway doctor` warns when a passthrough backend is configured and an active swap entry is
not verified encrypted.
