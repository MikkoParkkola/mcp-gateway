## The public credential calls return a wiped, unprinted value

**Startup:** no notice

What you gain: the two library calls that resolve a caller's minted
credential handed it out in a plain vector, freed unwiped when you dropped it,
and printed in full by `{:?}`. Now the value is wiped when it is dropped and
its `Debug` shows header names only.

What changes:

- `resolve_propagation_headers` returns
  `mcp_gateway::identity_propagation::PropagatedHeaders`;
  `resolve_propagation_credential` returns `(PropagatedHeaders,
  Option<String>)`.
- `PropagatedHeaders` reads as a slice of `(name, value)` pairs through
  `Deref`. It has no `Clone`, no `Display`, and no way to take the inner list
  out. Formatting the borrowed slice (`{:?}` on `&*headers`) still prints the
  values; only the type's own `Debug` redacts them.

What you see: this is a breaking change to two public signatures. Code that
embeds the crate and bound either result to a plain vector stops compiling,
for example:

```text
error[E0308]: mismatched types
  expected `Vec<(String, String)>`, found `PropagatedHeaders`
```

What you do: read the headers by borrowing them through the slice, for
example `for (name, value) in headers.iter()`, or pass `&headers[..]` where a
`&[(String, String)]` is taken. If you need an owned list, call
`headers.to_vec()`; that copy is yours, and nothing wipes it for you.

Operator action: none, unless you embed the `mcp-gateway` crate in your own
Rust code. Running the gateway binary is unaffected.
