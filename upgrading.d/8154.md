## One idempotency key covers one backend operation on every route

**Startup:** no notice

A keyed `tools/call` on `/mcp/{name}` used to check only the direct route's
idempotency cache. `/mcp`, stdio and tasks admit keyed calls into a separate
store, the execution lease. So the same key could run one operation twice:
once on the direct route and once through a task or `gateway_invoke`. A retry
after the cache entry expired could also run the call again.

What changes:

- **A key in flight on another route, or used for another request, is
  refused.** For example, a direct call under the key of a running task, or a
  `gateway_invoke` under the key of a direct call still running. The answer is
  409 "Idempotency key belongs to another execution or representation", and
  the backend runs once.
- **A completed direct call retried after its cache entry expires** replays
  the stored answer and does not run the backend again. The replay is signed
  for the retry's own signing nonce.
- **A refused call costs nothing.** Its cache reservation is given back and
  its signing nonce is not spent, so the same nonce can be used on the next
  call.

What to do: nothing, unless a client reuses one idempotency key for different
requests or across routes. Give each operation its own key.
