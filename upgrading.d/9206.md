## A blank certificate name is skipped

**Startup:** no notice, a request presenting a certificate with only blank names is refused (401, JSON-RPC -32000)

A SAN URI or CN made only of spaces or tabs is treated like an empty one,
so the gateway skips it when it picks the name a client certificate
presents. It takes the first SAN URI that is not blank, else the CN if
that is not blank. A certificate whose first SAN URI is blank therefore
now presents its next SAN URI, or its CN, as its identity, for grants,
the firewall key and the agent check alike (the nonce quota is keyed on
the whole certificate and does not change); a grant written for that
certificate must name that value. A certificate left with no name after
skipping is refused, exactly as a certificate with no name already was.
Every other value is kept exactly as written, so `" admin "` stays a
different name from `admin`.
