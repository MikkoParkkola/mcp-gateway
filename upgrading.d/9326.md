## Memory-poisoning `scan_tools`: entries match in any case, and an empty entry is refused

**Startup:** refuses to start, only when a `scan_tools` entry is empty

**Who is affected.** Operators who set `security.firewall.memory_poisoning.scan_tools`.

**Before.** An entry with an uppercase letter (`STORE`) matched no tool, so the memory-poisoning scan never ran for the tools it named, with no warning. An empty entry (`""`) matched every tool, so every call's arguments were scanned as a memory write.

**After.** Entries are compared without regard to case, as the setting was documented: `STORE` scans `store` and `Store_Memory`. A config with an empty entry is refused at load and on reload, whether or not the firewall or the scanner is enabled, with an error naming `security.firewall.memory_poisoning.scan_tools[i]`. Lowercase lists, including the default list, match exactly the tools they matched before.

**What you do.** Remove any empty entry from `scan_tools`. If you relied on an empty entry to scan every tool, list the memory tools' names instead. A config that wrote memory tool names with uppercase letters needs no change, but expect findings on those tools from now on: the scan now runs for them.
