## Audit log: where signing began is recorded, so a stripped signature is caught

**Startup:** no notice, one audit record when an anchor is set from history or found lost or edited

**Who is affected.** Deployments with `security.transparency_log.shared_secret` set.

**Before.** An entry whose fields were edited, whose hash was recomputed and whose signature was removed read `unsigned` in the Activity list, receipts and exports, the same as an entry written before signing was turned on.

**After.** The log keeps `<log>.sigstart` beside it, signed with the same secret: the position of the first signed record and a digest of every byte written before it. Readers show an unsigned entry as `unsigned` only when it lies before that position in bytes that still match; anything else reads `invalid`, and the exports name why (`sig_missing`, `legacy_edited`, `legacy_unlisted`, `sigstart_missing`, `sigstart_mac`, `sigstart_coverage`). The export manifest carries `signing_anchor` per log and an `anchor_faults` count. On the first 4.0.0 start:
- a log a 3.5.1 gateway signed (one file, starting at its first record) is anchored at its first signed record, once, and records `audit_segment_sigstart_migrated`;
- a 3.5.1 log whose first records an external tool removed cannot be anchored: it records `audit_segment_sigstart_unanchored`, its unsigned entries before the first surviving signed one read `unsigned` with an `unanchored` flag, and everything after is fully checked;
- a log with no signed history gets an anchor at its current end, with no record.
A `.sigstart` that is deleted on a log that already holds signed history makes the next start record `audit_segment_sigstart_rebuilt` and treat every unsigned entry as `invalid` from then on. One that is edited or copied from another log is kept as evidence and recorded as `audit_segment_sigstart_invalid` at each start. Each of the four records also bumps a counter: `mcp_audit_sigstart_migrated_total`, `mcp_audit_sigstart_unanchored_total`, `mcp_audit_sigstart_rebuilt_total`, `mcp_audit_sigstart_invalid_total`.

**What you do.** Move, copy and archive `<log>.sigstart` together with the log. If a start records `audit_segment_sigstart_unanchored`, the earliest entries cannot be proven to predate signing: treat them as evidence to read, not to verify. Two limits stay: stripping signatures from a 3.5.1 log before its first 4.0.0 start downgrades those unedited entries to `unsigned` (an edit to one still breaks the chain link the receipt checks), and an unrotated log whose opening record and `.hwm` were both deleted reads as unanchored legacy rather than tampered.
