## The protocol-revision window is per transport, and `record` seals it on shutdown

**Startup:** prints a notice

The RFC-0060 U1 measurement window (`protocol-revision-telemetry/window.json` in the data
directory) is now schema v2. Stdio keeps its counts apart, so a stdio request can no longer stand
in for HTTP traffic. 4.0.0 ships with no measured data; the measurement is MIK-8442.

**A v1 window is refused.**
- What you lose: a data directory that still holds a v1 `window.json`, written by a 4.0.0
  pre-release, gets no durable protocol telemetry. Each stdio start logs a warning that the
  telemetry is "not durable", and so does each HTTP `serve` start with `record`. The gateway keeps
  serving, and the file is left byte-identical, never converted.
- What you gain: an old aggregate can never be read as coverage it never had.
- What you do: nothing, unless you measure. Before a measurement window, move the
  `protocol-revision-telemetry` directory aside.

**New setting `server.protocol_revision_window`: `off` (default) or `record`.**
- With `off`, nothing is recorded for HTTP and shutdown behaves as in 3.5.x.
- With `record`, each HTTP `serve` process opens its own window segment before it serves (waiting
  at most 2 s), updates it every 5 s, and seals it as soon as the shutdown signal arrives. A
  request that reaches counting after that point is refused with HTTP 503 (`U1 window sealed:
  this gateway is shutting down; retry`) instead of being served uncounted. Calls counted before
  the seal carry on within the usual shutdown bounds.

**The v1 library items are removed** from `mcp_gateway::protocol_revision_telemetry`:
`DurableWindow`, `load_durable_window`, `production_retirement_decision`,
`production_retirement_decision_at`, `DURABLE_WINDOW_SCHEMA` and
`RetirementBlocked::WindowMisaligned`. Each of them would fail on, or misdescribe, every window
this version writes. `DurableTelemetrySink`, `durable_window_path`, `DURABLE_TELEMETRY_DIR` and
`DURABLE_WINDOW_FILE` are unchanged. Code that called the removed items has no replacement API:
the decision is an operator procedure, not a library call.
