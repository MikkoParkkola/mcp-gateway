## A backend-scoped admin has no gateway-wide admin powers

**Startup:** no notice, a log warning per admin key whose `backends` names some backends but not `"*"`

What you gain: an admin credential limited to `alpha` can no longer stop,
revive or reload the whole gateway, read every session's and key's spend, or
act as a control-plane Admin. Its admin flag reaches only as far as its
backends, the way its tool calls already do.

What you keep: the static bearer, the dashboard session, admin keys with
`backends: ["*"]`, admin keys with `backends: []` and Admin-role tokens whose
policy scopes them to every backend keep every admin power. Non-admin
callers are unchanged, except that export status now refuses every
non-admin caller whose backend scope names some backends, a key or a
key-server token, whatever its role (see below).

What changes, for an admin API key whose `backends` names some backends but
not `"*"`, and an Admin-role key-server token whose policy scopes it the same
way:

- The web UI's admin routes refuse it, among them `/ui/api/config` and the
  history routes `/ui/api/metrics/series` and `/ui/api/markers` (403), and
  `/ui/api/costs` (401, as for any non-admin). The stream sends it the
  counts-only status view and no `reload` kind.
- `logging/setLevel` is refused on `/mcp` and on a backend's direct route:
  a backend's level is shared by every user of it.
- The admin meta-tools are not listed to it and are refused if called,
  directly or as a task: `gateway_kill_server`, `gateway_revive_server`,
  `gateway_reload_config`, `gateway_reload_capabilities`,
  `gateway_get_stats` and `gateway_webhook_status`.
- `gateway_cost_report` refuses `include_all_sessions`, `include_all_keys`
  and another session's id, and leaves out the gateway-wide total.
- `/health` gives it no backend detail, `/api/costs` answers 403 (also when
  it selects a session with `X-Cost-Session-Id`), and
  operator event types are neither listed nor delivered to it.
- `/ui/api/control-plane/export-status` answers 403. Its counters are
  gateway-wide, so this holds for every caller whose backend scope names
  some backends but not `"*"`, admin or not: a non-admin key with such a
  list, or a key-server token whose policy scopes it so (an Auditor or
  SecurityReviewer identity included), which read it before, is refused too.
- On the control plane it is Auditor, not Admin: it reads within its scope
  and takes no Admin action.
- It keeps admin breadth inside its scope: Activity shows every call on its
  backends, and the admin-only backend capabilities stay callable on its
  backends.
- A queued or continued task ends with an error when a reload lowers its
  caller's standing: an admin key narrowed to some backends, or an
  Admin-role token whose role rule is removed.
- That task error (JSON-RPC code -32003) has new text for every caller, so
  a client that matches on it needs updating. It was "The API key this task
  was created with is no longer valid: a config reload removed, expired,
  re-issued or demoted it." It is now "The credential this task was created
  with is no longer valid as it was: a config reload removed, expired,
  re-issued or demoted it." The code is unchanged.

If such a credential is meant to administer the whole gateway, set
`backends: ["*"]` on the key, or `scopes.backends: ["*"]` in the key-server
policy.
