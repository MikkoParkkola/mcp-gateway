## Removed keys are refused, and `upgrade` deletes them and hashes plaintext API keys

**Startup:** no notice; refuses to start, only for a config that still sets a removed key

**Six keys are refused at load.** `backends.<name>.idle_timeout`, `backends.<name>.circuit_breaker`,
`marketplace`, `server.request_timeout`, `server.ws_port` and `cost_governance.currency` never
changed what the gateway did.
- What you lose: a config that still sets one of them used to load with a warning. It is now
  refused, on start and on reload, with one error that names every such key, says why it went
  and ends "Run `mcp-gateway upgrade`, which deletes them, or delete them by hand."
- What stays the same: `meta_mcp.cache_tools` still loads and warns once. Every other key is
  checked as before.
- What you gain: a key that does nothing can no longer sit in a config looking like a setting.
- What you do: run `mcp-gateway upgrade`, or delete the named keys. What replaces each:

  | Removed key | What it did | Use instead |
  |---|---|---|
  | `backends.<name>.idle_timeout` | nothing: idle hibernation was never built | `stop_when_idle_for` on a `command` backend |
  | `backends.<name>.circuit_breaker` | nothing: never read | `failsafe.circuit_breaker`, which every backend's breaker uses |
  | `server.request_timeout` | nothing: never enforced | the per-backend `timeout` |
  | `server.ws_port` | an echo-only WebSocket listener, removed in 4.0 | HTTP (`POST /mcp`) or stdio |
  | `marketplace` | settings for the removed `plugin` command | `backends:` entries or capability files (`mcp-gateway cap`) |
  | `cost_governance.currency` | a label only; every cost is stored in USD | nothing: costs are USD |

**`mcp-gateway upgrade` deletes the six keys and hashes plaintext API keys.**
- What you lose: nothing. A comment that sat on the same line as a hashed key is dropped, since
  it may quote the key.
- What stays the same: every other byte of the file. A key is deleted, or a plaintext key
  replaced, only when a re-read of the file shows that nothing else changed.
- What you gain: one command turns a 3.x config into one that loads. The same API keys still
  authenticate. The report names lines and entry names, never a key or a digest.
- What you do: run `mcp-gateway upgrade --dry-run` to see the changes, then `mcp-gateway upgrade`.
  A key written in flow style (`server: {ws_port: 1}`), or an API key held elsewhere
  (`env:`, `file:`, `${...}`), is named for you to fix by hand: delete the key, or run
  `mcp-gateway hash-key` and set `key_sha256`.
