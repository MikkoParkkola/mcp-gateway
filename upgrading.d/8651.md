## Capability hot-reload heals a silent file watcher

**Startup:** no notice

The capability file watcher used to stop reloading without a word when its
event source died or its shutdown channel lagged or closed. It now warns on
every such path and keeps running, and a reload that runs past 60 s warns
once, naming the stage it is stuck in, instead of hanging silently. The
reload itself is never cancelled.

Separately, a stale-catalogue check heals a dead event source: every 60 s
the gateway fingerprints the watched trees and reloads when the files drifted
with no file event. The interval is the gateway's own, not a setting
(MIK-8782). A change that keeps the
same length within the filesystem's mtime granularity is missed, and a tree
deeper than 16 levels or larger than 10 000 entries skips the check with a
warn; both are named limits, not bugs.

A symlink cycle under a watched directory (a directory that links to one of
its own ancestors) now ends the stale check at its first repeat on every
platform, with the same "exceeds the walk bounds" warn. Before, on macOS, such
a loop reached the operating system's symlink limit first and was skipped with
no warn, so the check ran on a partial tree without saying so. A single chain
of links longer than that limit, with no cycle, is still skipped silently.
