## Capability hot-reload heals a silent file watcher

**Startup:** no notice

The capability file watcher used to stop reloading without a word when its
event source died or its shutdown channel lagged or closed. It now warns on
every such path and keeps running, and a reload that runs past 60 s warns
once, naming the stage it is stuck in, instead of hanging silently. The
reload itself is never cancelled.

Separately, a stale-catalogue check heals a dead event source: every
`capabilities.stale_check_secs` (default 60) the gateway fingerprints the
watched trees and reloads when the files drifted with no file event. Set the
key to `0` to turn the check off. It is restart-only. A change that keeps the
same length within the filesystem's mtime granularity is missed, and a tree
deeper than 16 levels or larger than 10 000 entries skips the check with a
warn; both are named limits, not bugs.
