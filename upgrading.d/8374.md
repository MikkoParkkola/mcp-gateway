## SIEM export refuses a signed log it cannot authenticate

**Startup:** no notice

What you gain: SIEM export and `audit verify` now agree. A log that holds
signed entries is only exported when the key that signed it is configured,
so a forged entry with a recomputed hash chain cannot reach your SIEM.

What you lose: with SIEM export on and `shared_secret` empty, a log that
holds signed entries (for example one written while a key was set) no longer
exports. Export halts at the first signed entry, logs a warning naming the
missing key, and counts the failure on the export status. An unsigned log
exports as before.

What to do:

- Set `security.transparency_log.shared_secret` to the key the log was signed
  with and restart. Export resumes from where it stopped; the halted polls
  moved nothing, so no entry is lost or sent twice.
- If that key is gone, the signed entries cannot be authenticated. Keep the
  old log set for verification with the release that wrote it and start a
  fresh log (see the MIK-8365 note on changing the key).
