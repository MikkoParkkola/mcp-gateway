## The control-plane snapshot shows a caller only its own grants and events

**Startup:** no notice

**What you gain.** The control-plane snapshot (`GET /ui/api/control-plane`, the Control Plane page) listed every user's identity grants (who may use which server and tool) and every control-plane audit event to any signed-in caller, including an agent's ordinary API key. A caller that does not govern grants now sees only its own.

**What changes.** The role each caller resolves to:

| Caller | Before | After |
|---|---|---|
| An API key without admin rights | `auditor` | `viewer` |
| A signed-in identity no role rule matches | `auditor` | `viewer` |
| An admin key that also carries an identity no rule matches | `auditor` | `viewer` (the identity decides) |
| An admin key, the static bearer, a dashboard session | `admin` | `admin` |
| A signed-in identity a role rule maps | its role | its role |

What each role reads in the snapshot:

- `admin`, `security_reviewer` and `auditor` read every principal's grants and audit events, as before.
- `viewer` and `developer` read only their own: grants whose subject is theirs (a signed-in identity's issuer and subject, or for an API key the key's name), and audit events they performed. You don't see others' changes to your grants.
- Own grants cover the identity the web UI sees: a signed-in OIDC identity or an API key. Certificate, header and agent identities that dispatch also accepts are not used here.
- The audit view is the newest 200 events for every role; a viewer or developer sees its own among them.
- Nothing else changes: every caller still opens the page, and the role name in the snapshot's `actor.role` now reads `viewer` for the callers above. A client that parses `actor.role` strictly sees the new value. The snapshot's `authorizations` gains `read_all_principals`, which says which of the two views the caller gets.

**What you do.** To give a signed-in identity the full view, map it to `auditor` (or `security_reviewer`) with a role rule. An API key cannot carry a role rule; a key that must read every grant is made an admin key. `role: viewer` is accepted in a role rule like any other role.
