## Restart needs the transparency log

**Startup:** no notice, nothing changes at startup

Every accepted restart is recorded in the transparency log before anything stops, and a restart whose record
cannot be written is refused. A gateway with no transparency log, which only a gateway with auth off can be, has
nowhere to record one, so the restart preview (`GET /ui/api/gateway/restart`) answers `available: false` with the
reason `audit_log_required` and its recovery text, and never offers a confirmation. With auth on, configuration
validation already requires the log, so nothing changes there.

Restart itself stays off in this release: the preview answers `restart_not_available` (or
`windows_manual_restart` on Windows) whatever the log setting.
