## Restart needs the transparency log

**Startup:** no notice, nothing changes at startup

4.0.0 has no in-process restart. The restart preview (`GET /ui/api/gateway/restart`) never offers a confirmation,
and a reload or settings save that leaves restart-only settings pending says how to restart the gateway yourself.
When a later 4.0 release adds the in-process restart, each accepted restart will be recorded in the transparency
log before anything stops, and a restart whose record cannot be written will be refused, so its confirmation will
need a configured transparency log. Nothing changes for an existing gateway:

- With auth on, configuration validation already requires the transparency log.
- With auth off, every caller is anonymous and the restart routes are admin-only, so they refuse each request,
  as they did before.

Restart itself stays off in this release: the preview answers `restart_not_available` (or
`windows_manual_restart` on Windows) and offers no confirmation.
