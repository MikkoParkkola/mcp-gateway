## Restart needs the transparency log

**Startup:** no notice, nothing changes at startup

Every accepted restart is recorded in the transparency log before anything stops, and a restart whose record
cannot be written is refused. So the restart preview (`GET /ui/api/gateway/restart`) offers a confirmation only
when a transparency log is configured. Nothing changes for an existing gateway:

- With auth on, configuration validation already requires the transparency log.
- With auth off, every caller is anonymous and the restart routes are admin-only, so they refuse each request,
  as they did before.

Restart itself stays off in this release: the preview answers `restart_not_available` (or
`windows_manual_restart` on Windows) and offers no confirmation.
