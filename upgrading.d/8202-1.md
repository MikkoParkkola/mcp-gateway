## A clock before 1970: undated audit entries, refused token requests

**Startup:** no notice

What you gain: on a host whose clock reads before 1970 (a dead RTC, an unsynced VM), the gateway no longer stamps 1969 or 0 into an audit entry or dates a backend token from 1970, and it never uses an expired token.

What changes:
- The agent tool audit entry (`agent_tool_audit`, its `audit` JSON) is still written, with `"timestamp": null` and `"clock_invalid": true`. On a correct clock the JSON is unchanged.
- The same holds for the attributed transparency log's invocation row and the events audit rows (delivery outcome, dead-letter eviction, subscription lifecycle, watch backoff).
- An inbound webhook is answered `503` with `Retry-After: 60` and is not recorded, so the sender retries once the clock reads. Event deliveries wait, keeping their dates, and occurrences that cannot be dated are dropped and counted.
- An OAuth token request on such a host is refused before anything is sent, with "the host clock reads before 1970".
- Library users: `ToolInvocationAudit.timestamp` is `Option<String>`, and `TokenInfo::from_response(..)` becomes `TokenInfo::from_response_at(.., now)`.
