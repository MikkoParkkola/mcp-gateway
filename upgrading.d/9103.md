## A direct-route call waiting on its question keeps its key

**Startup:** no notice

**What you lose.** On the direct route (`/mcp/{name}`), after a backend answers a keyed `tools/call` with a question the gateway relays to you, a fresh call under the same idempotency key that does not present the continuation's `requestState` no longer runs the tool again. It is answered 409 "Secured execution result is unavailable" for the key's retention (24 h). The meta route (`/mcp`) already answers it this way.

**What you gain.** The tool runs once per key: a same-key retry while its question is open cannot run it a second time.

**What you do.** Answer the question: send the call again with the `requestState` you were given and your `inputResponses`. If you no longer have the continuation, rerun under a new idempotency key. A question the gateway refused instead of relaying to you (for example `-32021`, a capability you did not declare) frees the key as before, so a same-key retry after you fix the cause runs.
