## `/api/costs` decodes its selector and answers "no data" with 404

**Startup:** no notice

**The `?key=` selector is URL-decoded.**
- What you lose: `?key=team+ops` used to select a key literally named `team+ops`. It now selects `team ops`, because `+` is a space in a query string.
- What stays the same: a key name with no special characters is selected as before. A repeated `key` keeps its last value.
- What you gain: a key whose name has a space or a reserved character (`&`, `=`, `%`) can now be selected at all, by its escaped form (`%20`, `%26`, `%3D`, `%25`).
- What you do: send a literal `+` as `%2B` and a literal `%` as `%25`.

**"No data" is 404, not 200.**
- What you lose: a `?key=` or `X-Cost-Session-Id` with no recorded spend used to answer 200 with an `error` body. It now answers 404 with the same body.
- What stays the same: a key or session with spend, and the aggregate view (no selector), answer 200 as before. Bad input still answers 400 and a non-admin caller still gets 403.
- What you gain: the status code says what happened, as on the rest of the REST API.
- What you do: a script that checked the body of a 200 for `error` checks for 404 instead.

**An escaped `session` parameter is refused.**
- What you lose: `?sess%69on=<id>` (an escaped spelling of `session`) used to be ignored and answered with the aggregate view. It now answers 400, like `?session=`.
- What stays the same: pass the session id in the `X-Cost-Session-Id` header.
- What you gain: a session id cannot reach the URI, and so the access logs, by any spelling.
- What you do: nothing.
