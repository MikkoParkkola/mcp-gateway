## Refused stored-task reads name the check that refused them

**Startup:** no notice

A `tasks/get` that the gateway refuses, because a policy published after the
task ran now denies its tool, its key no longer reaches the backend, its
descriptor or schema is blocked, or its stored result no longer has its
provenance, used to record only `response_effect: refused` on its delivery
record. That record now also carries `refused_by`:

- `kind`: the check that refused the read, in the same vocabulary as a
  decision record's `kind`;
- `rule_id`: the configured rule's id, only when a configured rule decided
  (a tool-policy deny entry or default action). Omitted, never null,
  otherwise.

A stored result refused because it has no recorded targets or bindings, or
was produced under an account binding the target no longer runs under, is
refused under the new kind `provenance`.

The refused caller's answer is unchanged: it carries no rule id.
