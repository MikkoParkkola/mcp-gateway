## `mcp-gateway upgrade` exits 1 when the config it leaves will not load

**Startup:** no notice

- What you lose: `upgrade` used to exit 0 even when the config it left would not load. It now
  exits 1 when a removed key or a plaintext API key stays in the file, under `--dry-run` and
  `--quiet` too. With `--quiet` it prints one line saying how many keys stay.
- What stays the same: the version stamp and data migrations run before the exit, so a rerun
  after the hand fix has nothing left to do. A `meta_mcp.cache_tools` that stays still exits 0:
  it loads.
- What you gain: a script or CI job that runs `upgrade` sees that the config needs a hand fix,
  instead of finding out when the gateway does not start.
- What you do: when `upgrade` exits 1, fix the keys it names, then run it again.
