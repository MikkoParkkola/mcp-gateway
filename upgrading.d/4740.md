## The CLI keeps credentials out of gateway.yaml

**Startup:** no notice

**What you lose.** `mcp-gateway add -e NAME=value` is refused (exit 2): values on the command line
are visible in process lists and shell history. A credential value `add` receives no longer lands in
gateway.yaml as text when its name ends in a credential word and it is at least 8 bytes long: it is
saved in the secret store and gateway.yaml holds the store's reference. A registry server's token,
and every env and header value `setup` imports, follow the same rule. `discover --write` no longer
stores a short or ordinary value such as `DEBUG=1`; it writes it as typed. A value that mixes
literal text with a template (`sk-${SUFFIX}`) is refused by `add`.

A backend's command or URL that would write a credential into gateway.yaml as text is refused:
userinfo in the URL other than a whole `${NAME}` placeholder, a query parameter or command flag
named like a credential (`token`, `api_key`, `password`, `Authorization`), a `NAME=value` argument
with such a name, or an `Authorization:` header argument, with a literal value of any length.
`mcp-gateway add` exits 2; the web UI's backend add, update and add preview answer 422 by field
(`secret_in_url`, `secret_in_command`). Ordinary queries (`?transport=sse`), `${VAR}` text and
secret references are saved as before. The gateway does not expand `${VAR}` inside a command or URL.

**What you gain.** A credential given to the CLI, imported from an AI client's config or typed into
a backend's command or URL is no longer readable in gateway.yaml or its backups, and ordinary
settings are no longer redacted from tool results.

**For library users.** One function is new in the public API:
`mcp_gateway::cli_support::store_backend_literals(destination, config, names, keep_as_text)`
moves the credential values of the named backends in `config` to the secret store (the same rule the
CLI and the web UI use) and returns an `Adoption` to settle with the config write's result, plus each
stored field and its reference. Nothing existing changed signature.

**What you do.** In scripts, replace `-e NAME=value` with `-e NAME` (NAME exported in the
environment) or `--env-file FILE` holding a JSON object of names to values (`-` reads stdin, at most
64 KiB). Move a credential out of a backend's command or URL into an env value (`-e NAME` on the CLI,
an env field in the web UI), which goes to the secret store. To keep one value as typed, pass
`--keep-as-text KEY` (or `--keep-as-text header:NAME`) to `add`. `add` prints each stored field and
the reference that names its entry. Values written before 4.0.0 are not moved: replace each with an
`env:` or `keychain:` reference under the same key, or add the backend again.
