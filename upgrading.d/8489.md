## Rate limits and circuit breakers follow the credential

**Startup:** no notice

What you gain: an API key's `rate_limit` and its client circuit breaker are its
own. No other identity can share them by carrying the same name, whether that is
another API key, the static bearer, the dashboard session or an OIDC identity.

What stays the same: a configured key keeps the limit it is configured with,
and every key-server token issued to one OIDC identity still draws on that
identity's one bucket and one breaker. Load validation still refuses API keys
whose names are empty, padded or shared.

For code that embeds the library:

- `check_client_circuit_breaker`, `record_client_success`,
  `record_client_failure` and `client_circuit_state` take the
  `&AuthenticatedClient` instead of its name.
- `check_rate_limit(&str)` is removed. Use
  `check_authenticated_client_rate_limit(&client)`.
